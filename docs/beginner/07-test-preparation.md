# 7. 把学习变成样机测试准备

上一章：[Typhoon 预演](06-typhoon-walkthrough.md) · [学习入口](README.md) · [术语与资料索引](reference.md)

本章目标：学完概念后，能拿出具体笔记、接口问题和测试记录，并参与联调沟通。这里按你当前的知识起点安排任务，实物步骤由实际设备与负责人落实。

## 7.1 先把“准备好了”说具体

样机测试准备可以逐层完成：

| 层次 | 完成后你能拿出什么 |
|---|---|
| 理解系统 | 一张闭环图，指出命令、控制器、驱动、对象和反馈 |
| 理解资料 | 一份术语对照，能找到每个重要参数和引线的来源 |
| 软件练习 | 手算和工具一致的 LIN 样例，一次有解释的预演阅读记录 |
| 接入准备 | 每条真实路径的节点、方向、参考、量程与时序问题 |
| 实体验证 | 负责人确认的接线与步骤，以及实际操作产生的波形和日志 |

前四层可以先推进。遇到具体接口未知，写清是什么未知，同时继续不依赖它的学习和离线工作。

## 7.2 学习任务一：自己画两张闭环图

第一张画当前软件预演：模型内控制器 → 模型逆变器与电机 → 模型反馈 → 模型内控制器。

第二张画拟接入系统：外部命令 → 真实板卡 → 驱动调理与捕获 → 实时对象模型 → 反馈输出与调理 → 真实板卡。

用框线圈出真实硬件，给每个跨框箭头写一个具体量。例如“六路驱动的开关状态”“按采样比例表示的电流反馈”，不要只写“数据”。

完成后能解释：两张图中，谁在执行控制算法？角度从哪里来？哪些线需要真实电气规格？

## 7.3 学习任务二：给 18 条引线做读表笔记

按[接入记录](../tle9877-hil-intake.md#2-引线怎么理解)逐项阅读，先复述用途，再把未知写成可回答的问题。可以在自己的笔记中使用下面格式：

| 标签 | 我理解的用途 | 已有依据 | 下一项需要明确的信息 |
|---|---|---|---|
| GH1 | U 相上桥栅极引出，供调理后捕获驱动 | 引线表的 M4 G 脚 | 引出端是否已分压；相对哪个点测量；接入哪个调理通道 |
| SHP/SHN | 差分电流测量路径 | 引线表 0.5mΩ 与焊接位置 | 与 OP1/OP2 对应；注入在滤波前还是后；允许共模与采样窗口 |
| LIN-IN | LIN 总线接口 | LDF 和引线表 | 主节点设备、SDK、实际调度与停止流程 |

这张表用于你的学习，不必复制一套参数事实到多个地方。新的正式答复应更新[样机配置](../../configs/tle9877_sample.json)及所属接入记录。

## 7.4 学习任务三：建立四列转速记录

以后看日志时，用四列避免把不同环节混为一谈：

| 量 | 从哪里来 | 它回答什么 |
|---|---|---|
| 请求转速 | 人或测试脚本输入 | 原本想要什么 |
| 编码转速 | 根据 raw 与 LDF 换算 | 报文实际能表达什么 |
| 板卡反馈转速 | LIN 状态或其他固件接口 | 板卡报告自己估计或测得多少 |
| 模型转速 | HIL 对象模型 | 仿真对象当前算出多少 |

固件反馈的目标字段 Setspeed 还可以作为独立一列，用来核对限幅和状态机行为。各列都保留原始值、单位、有效性、时间戳和来源。

例如请求 2250rpm，编码为 2240rpm，首先是量化产生的差异。若板卡反馈另一个目标值，再检查固件平台或限制；若模型速度与目标偏离，再结合实际驱动和反馈看控制过程。

## 7.5 学习任务四：读一组证据，写三句话

先读第 6 章的现有预演报告，尝试写：

1. **条件**：“在本次软件参数、内部角度反馈和指定负载下，执行了哪些事件。”
2. **观察**：“在哪个时刻，哪几个信号发生了怎样的变化，指标是多少。”
3. **含义**：“按哪个窗口与判据得到什么结论；接入样机还需要哪些条件。”

“图看起来很好”“AI 判断正常”都没有说明测量和判定依据。Agent 可以帮助整理问题和分析数据，实际闭环的时序由仿真器与控制板承担，报告结论仍要落到具体记录上。

## 7.6 与板卡方、平台方沟通时，问题怎样变具体

把每个问题写成“目前知道什么 → 还差什么 → 需要哪种交付”。以下用于准备沟通材料，不会自动发送给任何人。

| 主题 | 具体问题示例 | 希望取得的材料 |
|---|---|---|
| 版本与流程 | 本次实物的芯片、板号、固件版本是什么？在 9V 条件下怎样唤醒、运行、停止和恢复？ | 版本记录与逐步操作说明 |
| 功率级边界 | 哪些 MOS 和采样电路保留？U/V/W、VM、SL 分别怎样连接？ | 标明保留、断开、替代部分的实际改装图 |
| 栅极捕获 | “18V/2=9V”的除以 2 在哪里实现？各路参考、共模和边沿条件是什么？ | 调理原理、通道映射和输入输出规格 |
| 电流采样 | SHP/SHN 对应哪个芯片输入？增益、偏置、滤波和采样窗口怎样设置？ | 电路映射与当前固件采样配置 |
| 无感控制 | 当前算法需要哪些电流、电压或诊断信息？启动与切换需要什么条件？ | 算法接口与状态说明 |
| 电机模型 | 5mΩ、11μH 是什么定义？Ld/Lq、磁链、惯量和负载怎样取得？ | 带定义、单位和来源的参数表 |
| 通信与停止 | 采用哪张调度表？PWM 与 LIN 谁优先？命令超时和后运行如何结束？ | 已验证样帧、调度与状态转换说明 |

拿到答复后，检查它是否针对这块实物及这份固件，是否明确单位和参考点。通用芯片功能图适合解释原理，实际接口参数需要相应版本证据。

## 7.7 到实体联调时，怎样理解推进顺序

以下是理解各阶段目的的路线，具体电压、命令、接线与操作步骤需由实际设备方案确定。

| 阶段 | 先解决的问题 | 典型证据 |
|---|---|---|
| 确认对象与边界 | 这是什么板、什么固件、哪些电路参与测试？ | 版本、实物对应、改装图、通道表 |
| 在确认条件下建立通信 | 帧头、响应和解码是否对应？ | 原始 ID/PID、数据、校验、设备时间戳 |
| 检查驱动与反馈路径 | 方向、倍率、参考点、有效时刻是否正确？ | 已知状态或数值对应的捕获与测量 |
| 建立一个正常闭环 | 设定后是否有实际驱动、对象响应和一致反馈？ | 同步关联的命令、驱动、反馈和模型波形 |
| 验证停止及恢复 | 结束条件和状态机是否达到预期？ | 驱动状态、电流、速度、状态与恢复过程 |
| 扩展已定义工况 | 在明确扰动下，响应是否符合固定要求？ | 扰动生效、响应窗口、指标与判定依据 |

前面没有对应证据时，先定位缺口。正常闭环和停止过程建立后，再选择一个目标明确的异常用例。

## 7.8 “不转”时，按信号链逐段看

1. **要求是否成立**：原始命令是什么？编码是否有效？当前接口和状态允许运行吗？
2. **板卡怎样回应**：有没有响应帧？反馈目标、故障或状态是什么？实际固件版本是否匹配？
3. **有没有实际驱动**：六路信号是否出现？捕获是否经过正确调理？相序和极性是否对应？
4. **对象是否收到驱动**：模型输入是否变化？母线、开关与电机参数是否按本次条件生效？
5. **反馈怎样返回**：电流对应什么数值和时刻？是否还有相电压或诊断路径需要满足？
6. **启动卡在哪个状态**：是准备、开环升速、估计切换、保护还是后运行？需要固件侧什么观测？

这些是逐项核查的候选位置，最后结论必须由本次证据支持。仅看到“LIN 正常”只能说明通信的一部分已经工作。

## 7.10 最后做一次自检

能不用照抄教程，回答下面八题，就具备继续跟进样机准备的基础了。

1. 芯片、功率 MOS 和电机分别承担什么？
2. 六路 GH/GL 与外部 PWM-IN 有什么关系和区别？
3. 0.5mΩ 分流电阻下，10A 为什么对应 5mV？
4. 为什么注入节点、参考点和采样时刻要一起确认？
5. raw=100、0x64、2240rpm 怎样联系起来？
6. 为什么控制和状态各占 10ms 时隙，同一帧却每 20ms 重复？
7. 当前预演的控制器在哪里？为什么还要验证样机无感启动？
8. 一份报告需要哪些信息，才能从“看见变化”走到“满足要求”？

<details>
<summary>核对要点</summary>

1. 芯片执行程序并提供采样、通信、驱动等功能；功率 MOS 控制能量通路；电机产生机械作用。
2. 外部 PWM-IN 表达命令，六路 GH/GL 控制三相功率开关；各自的电气条件和协议不同。
3. 按 V=I×R，10×0.0005=0.005V。
4. 同一物理量在不同节点可能有不同幅值、偏置和时间；ADC 必须在正确条件下取得对应信息。
5. 十进制 100 等于十六进制 64，再乘 22.4rpm/code 得到 2240rpm。
6. 一次循环包含两个连续时隙，总长 20ms。
7. 在模型内部，采用内部角度与预演参数；实际固件的估计、反馈与时序仍需实体验证。
8. 条件和来源、实际事件与原始数据、单位和同步、计算窗口与公式、预设阈值，以及记录复核和适用范围。

</details>

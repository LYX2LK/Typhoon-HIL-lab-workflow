# Typhoon Agent：案例选择、分析与确认复验

供演示操作者和维护者使用。Agent把原始波形、确定性指标、大模型解释与可确认的下一步连成可复核的对话。首页提供Boost输入跌落、四组示例波形、三相整流桥二极管开路三个案例。

## 启动和选择

```powershell
Set-Location 'D:\Typhoon\lab-workflow'
.\lab.ps1 agent --port 8767
# 可预选案例：
.\lab.ps1 agent --case oscilloscope_tu --port 8767
```

打开启动命令显示的网址（默认 <http://127.0.0.1:8767>），在首条消息前选择案例。卡片联动案例说明、条件、输入提示和开始按钮。可直接输入问题发送，也可点击开始按钮采用默认问题。首条消息提交后案例锁定；“新会话”保留旧会话与报告，再显示案例选择。

沿用 `configs/ai_service_agent.json` 和 `demo.env.local` 中的服务配置，密钥不进入结果目录。默认端口已被占用时明确报错，可指定其他端口，保留原服务现场。保留 `agent-boost`、`verify-boost-agent` 命令兼容入口；旧版Boost会话仍按原协议读取。

## 三个案例怎样工作

| 案例 | 首轮动作 | 后续操作 |
|---|---|---|
| Boost输入跌落 | 编译、运行、采集并复算35→28 V输入跌落 | 基准、延后施扰、重复工况，经确认后执行；[Boost分析细节](boost-agent.md) |
| 示例波形 | 导入tu1至tu4原始CSV和截图，运行已有固定形态规则 | 比较tu1/tu2、tu3/tu4，查看局部/原截图，讨论或总结 |
| 整流桥二极管开路 | 实际运行正常和A相上桥臂开路两个工况 | 正常、故障或重复工况，经确认后执行；[模型和判据](../cases/rectifier_diode_open/README.md) |

示例波形沿用提交660c3c4中的导入、识别和复核实现：5%电平跌落、10%上升过程回落、最短0.2 μs采样支撑。分类仅表示当前规则与窗口的结果。逐文件参考标签为形态推断，在分析后单独比较；测点、倍率及器件原因待确认。CSV网格、点数、截图参数和提供方“us精度、200 MSa/s、131 kpts”说明分别保留，原始时间轴保持。

整流桥模型依据公开研究中的开路诊断问题自行简化建模。模型先读电压、电流和导通方向，分析后再核对实际注入配置。2%判据验证的是简化模型数值一致性；正常/故障状态、设备性能及识别准确率分别说明。

## 对话、图表和确认

模型先实际调用只读证据工具，再生成Markdown正文和受约束的图表/操作参数。模型通过views中的analysis区块决定正文在页面中的位置，支持按要求先画图、再列指标、最后解释。示例波形和整流桥报告逐条校验分类，以及数值引用与复算字段的对应关系；图表由原始数据绘制。自然语言机理解释仍需结合专业知识复阅。

可追问“先画图，再列关键指标，最后解释”，或选择模型的问题卡。选择实验只产生计划：查看配置差异、填写实际操作者、勾选确认后执行。旧问题、跨案例操作、失效确认和变化后的来源记录会被拒绝。运行中不开放新会话或重复提交。

局部查看和配对比较按所选记录读取证据、校验分类及生成图表；单条局部查看无需比较其他记录。其余原始记录仍保存在会话中，后续可直接输入问题查看全部记录。

示例波形默认首轮给分类和主要事件概览。“配对比较”随后按同类波形分组：tu1/tu2 为电平跌落，tu3/tu4 为上升回落；分别绘制局部对照图，并计算最大偏离、阈值倍数、参考幅度、事件数和样本支撑时长的差值与倍率。上升类另列首次穿越间隔。差值为右减左、倍率为右除左，百分比差值使用百分点；分母为零时倍率不定义。标量比较使用各文件自己的分析窗口，原始时间轴不平移、不插值，不作逐点相减，也不将记录间时间差解释为响应延迟。

比较报告解释新增差异，逐对校验差值或倍率引用；成功完成的波形对不再自动作为相同比较选项出现。局部查看、讨论和总结仍可继续，直接输入问题可明确要求再次比较。失败的比较不计入完成状态，重试沿用原选择。

模型服务失败后保留原始数据和请求记录。“重新分析已有证据”重试最近失败的原问题，保留局部查看或比较的选择范围，不会重新执行仿真或导入数据。已有后续分析时，旧错误卡的重试按钮停用。若数据准备本身失败，先根据错误记录修复条件，再开始新会话；已有现场保留。

## 证据、恢复与复核

```powershell
.\lab.ps1 verify-agent --run-dir '实际会话目录' --write --json
.\lab.ps1 agent --session-dir '实际空闲会话目录' --port 8767
```

新会话使用 `kind=agent_session`、`schema_version=2`，保存 `case_id`。示例波形新轮次为 `agent_turn/case_report_v3`，使用版本2比较工具，保存可复算的 `comparison.json`、比较数值引用及完成范围；旧v1/v2轮次按原工具输出与Schema复核。整流桥继续采用 `case_report_v2`；Boost轮次继续复用原协议并绑定案例。原 `boost_agent_session` 版本1保留兼容。busy会话拒绝自动恢复。

`session.json`、前向哈希关联日志、原始记录、每轮输入/证据、实际请求/响应、正文、校验后的控制参数、图表及确认计划共同留证。复核从CSV重算指标和工具结果，并核对API响应、正文与控制参数、确认配置及实际执行的关联，不重新调用模型。

页面“离线报告”导出图像内嵌的HTML；原数据链接使用会话相对目录，交付时保留目录结构。

## 维护入口

通用入口为 `agent.py`、`agent_server.py`、`agent_page.html`；`agent_state.py`负责公共会话记录，`agent_service.py`负责模型传输，`agent_cases.py`负责固定案例目录和分派，`agent_comparison.py`负责独立配对计算与完成范围，`agent_contract.py`与`agent_render.py`负责新案例报告校验与展示。`boost_agent*`中保留Boost专属协议、分析策略和历史兼容；`boost_agent_server.py`是旧导入兼容入口。

当前验证及证据见[验证状态](validation.md)和[按日期索引](validation-history.md)。

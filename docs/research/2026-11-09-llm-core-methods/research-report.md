# 大模型参与 HIL 失效发现与故障诊断：深入调研与选型建议

检索截止：2026-11-09。读者：参与选题讨论的导师、师兄及后续实验实施者。目的：回答大模型能否承担两项任务的核心能力、哪些方法值得优先验证，以及怎样判断其实际增益。本报告是现有方案的调研补充；现有执行版和讨论版保持原文。

## 1. 结论：应扩展核心方法候选，研究重点仍由技术问题决定

**有充分文献依据把语言大模型纳入核心方法比较。原讨论版将 LLM/Agent 主要放在需求整理与试验组织环节，覆盖不充分。** 最值得优先检验的两个位置是：利用需求语义和历史响应选择下一测试点；融合信号分析结果、工况与机理知识，区分具有相似表现的故障。前者已有 CPS 规格证伪研究，后者已有时序诊断、工业诊断及物理系统原因归属研究。[LLM-Falsifier](https://arxiv.org/html/2609.20752v1)、[S2S-FDD](https://arxiv.org/html/2603.08048v1)、[TraceBench](https://arxiv.org/html/2608.27182v1)。

但这些研究尚不能推出“大模型已经优于专用方法，适合直接替代电机 HIL 的检测与诊断”。任务、输入权限、评价方式和验证对象存在显著差异。**建议保留“有限预算下发现更多失效、从测试数据中获得更好的分析结果”这两个目标，把 LLM 方法提升为主要研究候选，用实验决定最终组合。** 暂不因一轮文献调研就将全部研究主题锁定为“大模型引导”。

应区分三类模型和五种作用位置：

| 概念/位置 | 核心作用 | 对本项目的意义 |
|---|---|---|
| 时序基础模型 | 从大规模时序学习可迁移表示 | 原方案的预训练时序路线；与语言大模型不是同一类别 |
| 语言/视觉语言大模型 | 理解文本、图像、语义关系，产生决策或程序 | 可以直接参与测试搜索、诊断和方法设计 |
| LLM 驱动 Agent | 在观测、工具与决策之间多轮交互 | 是否有效取决于可用信息、行动和反馈，而非 Agent 名称 |
| 规格到可执行测试 | 将需求映射为合法测试步骤 | AutoHIL 支持这一位置 |
| 下一测试点选择 | 根据语义与历史结果搜索规格违反 | LLM-Falsifier、GLLMPro 支持这一位置 |
| 信号/故障判别 | 直接读序列/图像，或综合特征与物理知识 | LLMAD、LLM-TSAD、VLM4TS、S2S-FDD 等 |
| 下一观测/复验选择 | 选择最能区分候选原因的信息或行动 | CoffeeBench 提供受限模拟证据；LeGIT、ACTMED 提供更高层方法参考 |
| 分析方法生成 | 生成特征、检测规则或分析代码，经数据反馈优化 | Argos 等表明 LLM 不必在线逐点推理，也能参与核心能力形成 |

上述具体论文的来源、阅读深度和实验边界见第 2—4 节。表中的项目取舍是本次调研判断，不是文献已经验证的电机结论。

原对话方向基本合理，需要改写三处：将“能提升”改为“已有实质研究、值得检验增益”；将 TraceBench 的静态归属与主动实验分开；将 LLMAD 的检测效果与端到端故障发现、分类、定位分开。

## 3. 深入检索补充了哪些有价值的路线

### 3.1 综合物理与信号信息的诊断，比单纯读长序列更值得优先验证

[S2S-FDD](https://arxiv.org/html/2603.08048v1)把正常参照、异常前后变化、多变量差异和过程知识组织成 LLM 可用信息，允许继续查询传感器表。已读实验使用 500 个正常样本、13 个案例及 5 类故障，DeepSeek-R1 经五次投票得到 10/13 正确。案例规模较小，主要比较不同 LLM；故障区间由前置环节提供，且包含已知故障知识。“继续查表”也不是新物理复验。

其可借鉴部分是**把多通道信号变成具有物理含义的诊断输入，并让模型选择补充信息**。迁移到电机时，应提供相电流及 dq 电流特征、速度跟踪误差、执行状态、扰动时序、与条件化正常参照的差异；所有字段以实际可测信号为准。

[BatteryAgent](https://arxiv.org/html/2512.24686v1)采用物理特征、GBDT/SHAP 与 LLM，说明混合方法可以让 LLM 参与最终判别。但其消融包含“warning”类别并将其视为合理中间状态；细粒度原因分析主要是单车多个充电片段的案例，而原标签为正常/异常。不能把报告一致性视为多类根因准确率。我们的试验应预先规定“不确定”的处理方式，分别核验二分类与故障机制定位。

反面证据也直接相关：[When LLMs Sit Above Diagnostic Tools](https://arxiv.org/html/2610.05031v1)在多个工业数据集比较直接融合策略，没有发现稳定超过最强单组件的收益。例如其 TEP 对照中，混合方法优于 LLM 单独使用，却低于专用模型。它是预印本，不能代表所有融合方法，但明确提示：**仅证明“加工具后优于裸 LLM”不足以支持采用混合方案。**

### 3.2 多模态输入能够扩展分析能力，仍须分离筛选器和大模型的贡献

[VLM4TS](https://arxiv.org/html/2506.06836v1)先用视觉编码器生成候选异常区间，再让视觉语言模型结合全局图像修订；其输入避免对每个短窗口重复调用大模型。公开 v1 的主表使用 F1-max，不能直接作为固定阈值部署效果。它提出的“局部精细定位＋全局语境判断”适合本项目验证，但需对照候选检测器单独使用、图像输入与数值特征输入，识别改善究竟来自哪里。

电机波形输入必须按物理问题分层：电流瞬态保留必要带宽与局部细节，速度恢复保留较长过程，工况变化单独标注。现有讨论版已指出 100 kSa/s 下 5000 点仅为 50 ms。不能先固定模型点数，再让所有物理过程迁就它。降采样前应抗混叠；时频特征可在原始采样上计算，随后交给 LLM；绘图保留时间单位、量纲及事件对齐。

“冻结时序编码器＋LLM”也不是把任意嵌入向量直接转成文字。需要经过训练的对齐层，或将编码结果转为有定义的类别、相似样例、统计量和工具接口。无需训练的首轮更适合后一种方式。

### 3.3 大模型可以生成分析算法，而不必每次在线处理波形

[Argos](https://arxiv.org/html/2501.14170v1)让 LLM 根据数据与反馈生成、修正可执行异常规则，在线执行规则；[微软公开代码](https://github.com/microsoft/argos)已提供数据格式和运行入口。这是原对话遗漏的核心方法位置：大模型参与构造检测能力，部署时可以运行普通程序。云监控规则不能直接代表高频电机分析效果，但这一范式适合检验自动发现动态特征、跨信号关系或工况判据。

[AnomalyLLM，IJCAI 2024](https://www.ijcai.org/proceedings/2024/0239.pdf)则利用语言模型引导知识蒸馏，形成时序异常检测器，主要价值来自表示迁移；它不等同于语言推理 Agent。[FD-LLM](https://arxiv.org/html/2412.01218v1)把时间/频域信息和机器背景用于语言模型微调，提供机械故障识别方向的例子，但其轴承数据条件与控制器 HIL 故障仍有距离。

上述路线解释了为什么“在线核心模块没有通用 LLM 调用”不必然意味着研究没有利用大模型。首轮可保留 Argos 型小规模方法生成试验；蒸馏和多模态训练等待数据条件。

### 3.4 主动诊断需要真正的新信息，不能把再次推理当作复验

[CoffeeBench](https://arxiv.org/html/2610.19291v1)比 TraceBench 更接近主动诊断：在模拟咖啡机中选择动作与下一观测，区分九种故障及正常状态。但它提供传感器快照而非完整时序，并由环境告知每次猜测是否正确；后者允许逐项排除，在实际待诊断 HIL 中通常没有对应信息。其动作—观测框架有价值，报告的诊断轮数不能原样外推。

更高抽象层级还有两条参考：

- [LeGIT](https://arxiv.org/html/2503.01139v1)：利用语义知识帮助选择因果发现的干预对象，再与数值方法结合。已读版本使用 DAG 和硬干预；改变闭环电机给定值通常不等于对内部变量做硬干预。
- [ACTMED](https://arxiv.org/html/2510.18988v1)：将 LLM 与贝叶斯实验设计结合，选择预计最能减少诊断不确定性的检查。它属于医学诊断方法参考；迁移时应优先用物理模型或已验证代理模型预测响应，用实际模拟/测量更新诊断，避免把 LLM 自己生成的结果作为外部证据。

因此，本项目可研究的增量是：**在相似波形对应多个候选原因时，利用语义与机理提出区分性试验，并通过真实反馈用更少次数确定原因。** 这仍是需要实验验证的项目假设。

## 4. 建议的优先级与首轮边界

| 优先级 | 路线 | 应回答的技术问题 | 首轮边界 |
|---|---|---|---|
| 最高 | LLM 语义反馈证伪 | 需求和历史响应能否帮助更快发现失效，特别是事件交互与边界？ | 一个提案接口，直接与混合两种用法；不同时接入很多 Agent 框架 |
| 最高 | 信号特征/物理知识＋LLM 诊断 | 工况与机理是否提高相似表象的区分、少样本及跨工况表现？ | 一个通用模型，固定信息集及工具；保留最强数值分类/定位方法 |
| 小规模探索 | LLM/VLM 直接异常识别 | 哪些异常可由语义与整体形态判断补充数值检测？ | LLM-TSAD 式输入或 VLM4TS 式修订先选一种，LLMAD 作参考 |
| 小规模探索 | LLM 自动生成分析规则 | 能否发现人工指标遗漏的动态/跨信号特征？ | 只在训练/开发数据反馈，测试集冻结规则；与人工特征及受限自动搜索比较 |
| 第二阶段 | LLM 选择区分性复验 | 能否减少原因确定所需的新增实验？ | 前两条建立可辨识故障集后，有限动作集试验 |
| 条件成熟后 | ATTLLM/FD-LLM 式对齐微调、蒸馏 | 在足够配对数据下是否值得额外训练？ | 由首轮瓶颈触发，不预先把训练大模型设成必做项 |

“最高”表示优先验证，不表示已确定优于现有方法。为延续原方案压缩首轮的约束，直接检测和规则生成中可先选一个小试点，不把表中所有方法并行实施。

## 5. 怎样做能回答问题的实验

### 5.1 任务一：语义引导失效搜索

验证场景保留 PMSM 调速恢复、负载扰动与事件次序。先固定输入范围、需求、运行时长和规格计算器，再比较以下方法。

| 组别 | 测试点生成 | 作用 |
|---|---|---|
| A0 | 随机/Sobol、直接搜索；加入固定工程启发式 | 分离基础搜索能力与已有领域知识的收益 |
| A1 | LLM 使用规约、变量含义和历史参数/裕度 | 检验语义搜索 |
| A2 | A1 加时间对齐的响应特征、关键违反/接近违反时刻 | 检验反馈信息增益 |
| A3 | LLM 提出区域/事件模式，数值优化器局部搜索 | 检验语义探索与数值细化的组合 |

A1—A3 使用同一模型版本与推理设置。增加移除有意义变量名/工况语义的消融，以及数值优化器获得相同可计算响应特征的对照。LLM 额外获得的知识、其他方法可获得的先验均明确记录，避免把信息不对等误当算法优势。

主结果给出两套预算曲线：相同有效物理执行次数；相同总时间/费用。模型调用、失败格式修复、非法候选、重复候选、初始化和每次执行均计费计时。非法候选不必执行，但不能从方法开销中消失。规格归一化及多需求聚合在开发集确定。

报告预算内证伪成功率、首次发现成本、唯一失效模式数，以及未发现时的最佳裕度。首次发现成本包含未成功试验的右删失，不能只平均成功运行。失效模式按预先定义的物理/行为类别去重；较严重违规不自动等于更多模式。

### 5.2 任务二：先看信息提取与故障区分，再看完整流程

选取“速度下降/恢复变慢但原因不同”的案例族：正常负载变化、反馈偏置/异常、执行通道异常。先核实实际接口能否实现各注入点及是否有足够独立观测。控制器为了补偿反馈异常而引发电流变化，不能简单用“哪个通道偏差最大”判断原因。

| 组别 | 方法 | 要分离的贡献 |
|---|---|---|
| B0 | 物理/动态特征分类器、残差签名及已有时序模型中的最强者 | 专用方法基线 |
| B1 | 同一特征、同一工况信息交给 LLM，不给其他模型结论 | LLM 对信息的判别利用能力 |
| B2 | B1 加过程/故障机制知识与正常参照 | 语义和机理信息增益；与规则/案例检索基线比较 |
| B3 | B2 按需调用特征、频谱、相似案例和额外通道工具 | 自适应信息选择；对照固定获取相同信息的方式 |

原方案的 TimeRCD、MiniRocket、MantisV2 是各环节候选，不必与每个 LLM 变体做全笛卡尔积比较。先选定强基线，再做有针对性的消融。单独验证真实故障窗口中的分类与定位，最终统一从完整波形起步：

**端到端发现且正确识别率 = 在规定延迟内被发现、匹配到真实事件并正确识别的故障事件数 ÷ 全部真实故障事件数。**

未检出、检出后错分类和超时均进入分母；事件匹配与合并规则预先固定。同时报告每单位正常运行时间误报、检测/诊断延迟、已知类混淆、未知类拒识和具体注入位置的定位。未知故障应单列“检出且拒识”，不把正确拒识算已知类识别失败，也不把拒识算已确定根因。

按完整运行、控制参数/设备配置和故障机制划分数据；高度重叠窗口不跨训练测试。知识库可以包含训练阶段已知机制，但不得含测试记录的故障标签、注入位置或未来观测。区分未见工况、未见故障幅值、未见机制，不能统称零样本。主指标采用开发集固定阈值；点调整 F1、测试集最佳阈值最多作为附加对照。

### 5.3 第二阶段：主动复验

先建立有限候选原因与可执行动作集，如改变负载阶跃幅值、改变目标速度、增加特定观测或重复试验。每个动作必须在当前模拟/实体平台上有明确含义；真正的物理干预与读取已有数据分开计费。

比较固定顺序、随机、基于候选模型响应分歧/预期信息增益、LLM 提案、LLM＋数值信息增益五种选择策略。相同动作集、初始信息和候选模型；对模型不完备、无故障、未知故障以及不能区分的情况保留拒绝确定原因的出口。

环境只返回可测响应和运行状态，不返回“你猜错了/猜对了”。隐藏真值仅用于离线评分。评价固定预算内正确定位率、包含失败与未决案例的复验成本，以及每次新增观测对原因区分的贡献。停止条件预先确定，不能用隐藏真值提示模型何时停止。

## 7. 对现有技术选型的有限调整建议

1. 两任务目标与电机验证场景保持。把总述中的 LLM 定位改为“可参与测试搜索、信号理解、故障推理与复验选择，其作用通过与专用方法的比较确定”。
2. 任务一在组合覆盖/数值搜索旁加入 LLM 语义反馈证伪及混合搜索，AutoHIL 继续服务需求到执行的部分。
3. 任务二保留时频/动态特征、物理残差与时序模型；新增知识与工具辅助的 LLM 诊断。直接读时序、自动规则生成设置小规模探索，不扩成多个同步主线。
4. 诊断反馈在第二阶段加入 LLM 复验选择，与现有分歧选点/信息增益方法比较。根因依据来自新增观测，评价核心仍是正确率与实验效率。

可在讨论时用一句话概括：**研究大模型能否利用需求、工况与机理语义，帮助我们更快找到控制系统的失效，并从波形中区分传统指标难以区分的故障；保留数值搜索与信号分析作为强基线，通过同条件实验决定如何组合。**

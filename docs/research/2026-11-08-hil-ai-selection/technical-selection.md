# HIL 智能测试生成与数据分析：技术选型方案（修订版）

本版取代 [11 月 6 日方案](../2026-11-06-hil-ai-selection/technical-selection.md) 的选型建议。交付为技术方案与实验设计，算法效果尚待本项目实验验证。修订依据和处理情况见 [评估意见落实](revision-notes.md)。

## 1. 选型结论

**任务一：在有限预算内测得更全面，发现人工设计容易遗漏的失效。任务二：从测试数据中提取更多有用信息，更准确地发现异常、识别故障、定位问题并总结跨工况规律。**

建议建设“需求与约束驱动的测试生成”和“测试数据智能分析与故障诊断”两个相互反馈的模块。可复现、可追溯与数值正确是共同质量要求；方法的价值由分析能力的提升、实际效果和成本决定。

| 技术问题 | 建议先做的比较 | 推荐方案 |
|---|---|---|
| 需求转为正确的可执行测试 | 人工模板、直接 LLM、检索＋LLM＋结构化规约 | 采用结构化规约架构；具体生成策略按语义正确率与修订时间选择 |
| 多因素与事件序列覆盖 | 人工/随机、PICT、少因素全枚举；另设状态转换测试 | PICT 为多因素组合候选；序列覆盖独立设计 |
| 难触发边界发现 | 随机、Sobol、网格/边界扫描、直接搜索，随后加入 BO | 先用轻量回调；BO 和 PSY-TaLiRo 按收益与需求复杂度接入 |
| 瞬态、频域与动态特性提取 | 时域与时频特征、条件化正常模型、低阶辨识/物理残差 | 结合特征提取与动态建模，量化超调、振荡、响应差异并估计系统状态 |
| 复杂及未知异常发现 | 条件化统计/IForest、TimeRCD | 先比较统计基线与异常专用模型；MOMENT、TS2Vec 按首轮不足后续加入 |
| 故障类型识别 | 物理特征＋线性模型/树、MiniRocket、MantisV2 冻结特征 | 优先比较物理特征分类器、MiniRocket 与 MantisV2 冻结特征分类器 |
| 少标签与跨工况识别 | 固定标签预算下比较手工特征、MantisV2、TS2Vec | 先验证冻结表示；目标域未标注数据较多时加入 TS2Vec |
| 部件/信号链定位 | 标准化偏差、条件化正常参照＋残差签名 | 物理残差先进入可评估原型；AERCA 为满足条件后进入的第二轮候选 |
| 分析指导下一轮测试 | 固定复验表、随机选择、候选原因最大分歧选点 | 在同一复验预算下比较定位成功率与减少的候选数 |

方法与来源详见 [文献与工具记录](evidence-register.md)，试验详见 [比较协议](experiment-protocol.md)。

## 2. 要解决的技术问题与目标场景

### 2.1 测试用例生成的目标与范围

输入包括需求、控制状态、接口、允许的操作范围和故障机制；输出为测试意图、可执行配置、覆盖缺口与可复现反例。重点处理三类遗漏：工况交互、连续参数边界、事件顺序与恢复过程。前期把“罕见”定义为难以触发的边界或组合；现实发生概率需要额外的运行分布支持。

### 2.2 测试数据分析的目标与输出

| 分析任务 | 分析输出 | 评价目标 |
|---|---|---|
| 性能与行为特征 | 稳态合格之外的短时反转、振荡频率、衰减、响应迟滞、电流不平衡 | 特征估计误差、重复性、对参数/工况变化的分辨能力 |
| 异常发现 | 固定阈值遗漏的缓慢漂移、间歇异常、跨通道关系破坏 | 误报预算下的事件召回、检测延迟、起止区间质量 |
| 故障识别 | 将相似表象区分为传感器问题、执行通道问题、控制/负载变化等 | 故障宏平均 F1、混淆矩阵、未知类拒识表现 |
| 故障定位 | 识别可疑信号链或部件，并给出候选排序 | 部件级 Top-1/Top-k、误定位率、定位时间 |
| 跨工况规律 | 哪些速度、负载、阶段下更容易振荡或误诊；已知趋势能否外推 | 留出工况误差、最差工况性能、规律在新运行中成立的比例 |
| 诊断反馈 | 给出能区分当前候选原因的下一项测试 | 同预算定位成功率、所需复验次数、人工判断时间 |

最终评价同时保留独立算法能力与完整流程效果：前者使用真实事件窗口比较分类和定位能力，后者从完整波形自动检测、截窗、分类和定位。完整流程以“规定时限内发现且正确识别的已知故障事件数／全部真实已知故障事件数”为联合指标，漏检保留在分母中；未知故障另报发现且正确拒识率，并同时报告误报、误定位和诊断延迟。具体定义见 [比较协议 §6](experiment-protocol.md#6-b1b5-分任务比较)。

例如，现有 [GUI 预演记录](../../tle9877-gui-practice.md) 描述零速命令后速度短暂约至 −305 rpm，而练习判据检查事件后 100–200 ms。这个记录说明“已定义窗口通过”和“完整动态过程值得分析”可以同时成立。首轮应自动提取反转峰值、持续时间和恢复特性，并比较负载依赖；是否构成规格失效要由相应需求定义。

### 2.3 三级应用场景

| 层级 | 角色与测试对象 | 完成条件 |
|---|---|---|
| L1：教学流程 | Boost；整流桥作为辅助定位练习 | 配置迭代、有效激励、搜索目标和失败回归可运行；不承担电机方法效果主结论 |
| L2：电机 Virtual HIL | PMSM 启动、调速、负载、零速响应；扩展传感器与执行通道故障；感应电机用于跨对象检查 | 至少两种有区分度的电机需求；正常动态及多类异常/故障；按工况留出比较 |
| L3：真实控制板 HIL | LIN→控制板与固件→六路驱动→HIL 电机模型→采样反馈→控制板 | 首个正常闭环和停止行为通过现场验收后，再评价真实接口、保护响应、故障诊断与域迁移 |

L2 的模型控制器、内部角度和假设参数与 L3 无感固件分别建基准。L3 是真实控制板＋实时仿真被控对象的闭环；其结果也应按实际建模与采集范围解释。实体迁移单独形成结果表。

2026-11-08 的只读检查中，PMSM、Boost、感应电机阶跃均静态校验通过，运行证据均返回 `not_verified / evidence code is stale`；实体 smoke 计划为 `execution_enabled=false`。该次检查未运行仿真或操作硬件。首轮试验需复验软件基准，并按目标分析任务补齐模型与采集能力。详见 [项目检查](project-checks.json) 与 [能力及实施映射](capability-and-implementation.md)。

## 3. 任务一：智能测试生成与边界探索

### 3.1 需求驱动的测试用例生成与组合覆盖

采用 `需求/接口资料→LLM 测试规约→确定性校验→模板配置→执行反馈`。LLM 负责候选意图与资料映射；约束生成器负责组合，搜索器负责连续参数，执行器负责施加与采集。

AutoHIL 研究需求到 ECU HIL 测试的生成，其台架操作知识和需求补全方法值得进一步核对。现有阅读材料仅为会议摘要，完整方法与实验条件待补读；其 AUTOSAR 源码/配置条件能否适用于 TLE9877 也需另行确认。[AutoHIL 会议页](https://conf.researchr.org/details/issta-2026/issta-2026-research-papers/64/AutoHIL-LLM-Based-ECU-Functional-Test-Generation-through-Domain-Knowledge-Augmentati)

PICT 用于速度分区、负载分区、阶段、故障机制、注入时机等离散因素。按合法约束计算 2-wise，必要时对高风险因素组增加局部 3-wise。电机多因素表是主要试验对象；只有两个变量的 Boost 保留网格扫描。[PICT 官方文档](https://github.com/microsoft/pict/blob/main/doc/pict.md)

状态转换与短事件序列另列清单，如“调速→负载变化”“负载变化→调速”“故障→恢复”。同一参数集合的不同次序可能产生不同轨迹，普通成对覆盖不能替代序列测试。当前 PMSM 每次最多三事件且要求各事件后有完整稳态窗口；快速连续事件需先扩展适配器，详见能力表。

覆盖报告同时列出目标需求集合、当前可执行子集与实现缺口。每个冻结版本内，设计覆盖和有效执行覆盖使用同一合法组合分母；新增实现后升版分母，保留旧版结果，避免缩小范围造成覆盖率虚增。

### 3.2 连续参数边界探索与反例搜索

Boost 仅验证流程和已知失败回归。主比较选择电机的两个不同需求族：

1. **调速恢复边界**：给定幅度、初始速度和负载变化下的恢复时间/误差带。
2. **负载扰动或事件次序边界**：负载幅值、施加时刻、与调速事件间隔下的速度跌落/恢复；若涉及电流/保护限制，先获得独立规格。

先在独立预试集上检查是否既有通过又有失败、是否存在有意义的局部边界。全通过或几乎处处失败时更换有实际需求的场景、范围或观测任务；规格阈值保持来源一致。正式试验前冻结，已知失败点不能作为未计成本的初始化优势。

保留纯随机、Sobol、低维网格/边界扫描和直接搜索。LHS 可用于替换 Sobol 做采样敏感性比较。BO 适用于单次执行较昂贵且目标裕度提供有效引导的任务；PSY-TaLiRo 适用于多种时序规格与黑盒回调的组织需求。低维原型可先直接调用现有执行入口，工具框架与优化算法分别决策。[PSY-TaLiRo](https://github.com/cpslab-asu/psy-taliro)、[BoTorch TuRBO 示例](https://botorch.org/docs/v0.15.1/tutorials/turbo_1)

搜索目标为固定需求的数值裕度，正值满足、负值违反。不同物理量分别优化，若组合需冻结归一化。配置不合法、执行失败、激励未生效、数据不足均返回不可评价状态；不能通过赋一个极差分数让优化器把台架错误当作控制器失效。

### 3.3 测试生成效果评价

评价有效需求/组合/序列覆盖、同预算反例发现率、首次反例调用数、不同失效模式数量和总墙钟成本。重复参数点、同一波形模式、已知失败回归与新增模式分别计数。找不到失败的运行保留为截尾结果。先按“需求＋阶段＋响应形态”归类，再通过复验检查是否为不同原因；不直接把聚类数当缺陷数。

## 4. 任务二：测试数据的智能分析与故障诊断

### 4.1 系统行为特征提取与动态特性分析

从事件响应和频域结构提取工程信息：稳态偏差、超调/欠调、反转幅值与持续时间、恢复时间、IAE、振荡频率及衰减、电流 RMS/不平衡、频带能量。对变速过程比较 STFT/小波与按转速或电角频率组织的特征，避免固定频带把正常转速变化当故障。可从 SciPy 信号处理和条件化统计开始；多尺度方法是否有增益用 B1 验证。[SciPy 信号处理文档](https://docs.scipy.org/doc/scipy/reference/signal.html)

首轮先比较既有工程指标与扩展时频/动态特征。需要解释响应动态变化或建立预测残差时，再选一种低阶 ARX/NARX 或状态空间模型；若这正是首轮目标，则将该模型列为必要比较。先拟合正常工况，检查留出运行的多步预测和残差结构；只报告能被当前激励辨识的动态参数。闭环下控制输入与扰动相关，普通输入输出拟合不自动提供真实开环带宽或物理参数。SysIdentPy 可作为 NARX 实现候选。[SysIdentPy](https://sysidentpy.org/)

物理机理与数据分析的融合优先采用以下残差和特征，并通过消融试验检验各项贡献：

- 电机机械关系可构造 `r_m = J·dω/dt − (T_e − T_load − B·ω)`，前提是转矩、惯量、摩擦与负载定义匹配。导数滤波和参数误差必须纳入正常残差标定。
- 电气预测残差需要相电压/等效施加电压、电流、电角度及参数；当前 PMSM 导出不齐全，列为新增采集任务。
- 相电流关系可帮助发现测量不一致；三相电流和接近零并不能排除桥臂故障，尤其不能由理想模型强制成立的关系推断诊断能力。

比较“信号特征”“物理残差”“二者融合”，确认收益来自哪一项。PINN、完整数字孪生或联合优化留给低阶残差确实不足且参数/数据条件支持的任务。

### 4.2 时序异常检测

首轮比较条件化统计/IForest 与 TimeRCD；PCA 可在通道关系是主要分析目标时作为基线替换项。MOMENT、TS2Vec 保留为后续候选，仅在首轮错误分析指出表示能力不足且数据、预算满足时加入。

| 候选 | 可能改善的能力 | 数据和实施条件 | 主要比较 |
|---|---|---|---|
| 条件化统计、PCA、IForest | 发现同工况下的偏离，抑制正常启动/调速误报 | 按模式、速度、负载组织的正常数据 | 全局阈值 vs 条件化基线 |
| TimeRCD | 利用上下文与多变量关系发现局部、复杂异常 | 可用权重；窗口物理时长合适；正常/异常独立留出 | 同校准误报预算的事件召回、持续故障漏报、区间误差 |
| MOMENT 冻结特征＋简单检测器 | 检验通用预训练表示能否提高异常可分性 | 固定 checkpoint、表示层和正常训练数据 | 表示检测 vs 重建误差，二者单独列项 |
| TS2Vec 表示＋距离/检测器 | 从本领域未标注序列学习行为模式 | 仅使用训练组的未标注数据；检查裁剪/增强语义 | 随未标注数据量变化的增益和训练成本 |

TimeRCD 采用相对上下文差异，官方接口支持单/多变量输入；公开基准结果支持将其列入试验，但尚未证明能识别本项目异常。默认 5000 点在 10 kSa/s 下为 0.5 s；当前 [PMSM 软件预演配置](../../../configs/pmsm_software_preview.json) 与 [GUI 预演](../../tle9877-gui-practice.md) 均采用 100 kSa/s，同样点数仅覆盖 0.05 s。按 §5 先确定物理窗口与所需带宽，再决定输入点数和预处理。整段持续异常、正常模式切换和短促事件均应单列检查。[TimeRCD 正文](https://arxiv.org/html/2509.21190v2)、[教程](https://github.com/thu-sail-lab/Time-RCD/blob/main/Tutorial.md)

原始幅值、时序形状和物理残差保留可区分的输入分支，检查归一化是否隐藏偏置/增益故障。模型分数输出到事件区间，再进入识别与定位任务；检测结果不直接充当故障类别标签。

### 4.3 故障类型识别

首批诊断目标建议为：正常动态、测量偏置/增益异常、控制反馈异常、执行通道缺失，以及可与这些故障混淆的合法负载变化。具体类别由可实现机制和可观测信号决定。模型中修改反馈路径、修改导出 CSV、真实传感器失效分别标注，不能共享未经验证的物理故障标签。

| 方法 | 比较目的 | 数据要求与局限 | 试验安排 |
|---|---|---|---|
| 物理/时频特征＋逻辑回归、SVM 或树模型 | 建立可解释、低成本的故障边界 | 少量但覆盖工况的已标注运行；特征可能遗漏复杂形状 | 必留强基线，先固定一种线性头和一种非线性头 |
| MiniRocket＋线性分类器 | 提供低成本时序形状分类基线 | 有标签，窗口/通道定义固定；不是物理机理模型 | 首轮进入；多变量实现需固定随机性和实现版本 |
| **MantisV2 冻结编码器＋线性分类器** | 分类专用基础表示，有望减少特征设计和标签需求 | 下游标签仍必需；原始多变量策略按通道编码后拼接，不等于显式耦合建模 | 首轮前沿候选，与 MiniRocket 和物理特征同标签预算比较 |
| TS2Vec 自监督表示＋相同分类头 | 检验本领域数据适配是否比通用表示更有效 | 训练组未标注序列及训练成本；裁剪/掩码不能破坏关键故障语义 | 少标签任务的第二轮候选 |
| MOMENT 冻结表示 | 检验通用预训练表示在故障分类中的适用性 | 检查权重、通道聚合与预处理 | 首轮存在明确表示不足且资源允许时，作为第二轮分类对照 |

MiniRocket 的作者实现提供多变量扩展，可作为时序形状分类基线。Mantis 系列已有 ICML 2026 论文和公开 MantisV2 权重，适合纳入分类专用预训练表示的比较。[MiniRocket](https://github.com/angus924/minirocket)、[Mantis 论文](https://proceedings.mlr.press/v306/feofanov26a.html)、[MantisV2 方法正文](https://arxiv.org/html/2602.17868v1)

MantisV2 的“zero-shot feature extraction”指编码器冻结，最终分类头仍需本任务标签。论文默认将序列变为固定长度，可能影响短瞬态；本项目先固定物理窗口，再评价尺寸变换。TS2Vec 按目标训练数据学习表示；TS2Vec-FM 则研究预训练后复用冻结编码器，两者的数据条件和训练流程不同。后者的权重与复现条件待核对，列为后续候选。[TS2Vec 正文](https://arxiv.org/pdf/2106.10466)、[TS2Vec-FM 预印本](https://arxiv.org/html/2610.28602v1)

### 4.4 故障定位与原因分析

先建立“故障机制—预计影响信号—观测残差”的签名表。例如负载扰动、速度测量偏置和执行通道异常都可能产生速度误差，但电流、转矩、给定与反馈关系不同。必须设计相似表象的配对任务，检验分析器能否区分。

第一轮比较：最大标准化偏差排名、条件化正常参照＋残差签名、特征分类器的部件标签。已知正常工况参照可减少把工况差异误当原因的风险，但参照匹配本身也需要留出评价。

残差方法仍难区分传播源、且观测与标签条件齐备时，第二轮再引入 AERCA：利用正常多变量序列学习滞后关系及外生变量分布，排序异常来源。其论文采用特定外生干预与独立性假设；电机闭环中的共同驱动、瞬时耦合、未测控制量和结构改变故障可能不符合这些条件。先在已知源头、传播效应可区分的注入试验上比较，再决定是否保留。评价到“可疑信号”和“物理部件”两个层级，显式维护映射。[AERCA 正文](https://proceedings.iclr.cc/paper_files/paper/2025/file/6fde96479648d71e4fd9724374bf76eb-Paper-Conference.pdf)

相关性、注意力、SHAP 或通道异常排名可以帮助筛查；只有在部件标签、观测条件和干预结果支持时才报告物理原因。对不可辨识的原因组输出集合，并生成需要补采的信号或复验。

### 4.5 跨工况分析与诊断驱动复验

先按运行模式、转速、负载、供电与故障强度构建特征响应图，回答在哪些区域出现动态退化、混淆或漏检。使用条件化基线、速度归一化/阶次特征、物理残差和冻结表示逐项比较；只有确认域差异导致性能下降，才引入域适应。未使用目标域数据的泛化，与使用目标域未标注数据的适应分别报告。

诊断驱动复验采用“候选原因→各原因对下一工况的不同预测→按分歧和成本选择复验”。首轮基于有限候选表与可执行仿真，比较固定复验表、随机选择和分歧选点，评价缩小原因集合所需的复验次数。选点过程仅使用当前可获得的观测与候选预测，真实原因标签由评价器保留。

LLM 在这里负责查询任务背景、调用分析器、组织假设与测试规约，并帮助解释结果。分析算法输出和经复验确认的区分结果构成核心增益；报告文字质量单独评价。

## 5. 分析所需的数据与采样条件

采用两条尺度不同的支路：保留高频原始数据提取电流/电压瞬态和频谱；用经过抗混叠处理的较低频数据分析速度、包络与控制阶段。慢速 LIN 和状态日志保留事件语义，可先做事件级融合；只有时间关联及误差满足任务要求时再做逐点融合。

每项分析先登记目标事件持续时间、所需带宽和前后上下文，再确定物理窗口、采样率与模型长度。以 `N ≈ T_window × f_input` 核对输入点数；原始采样率与派生输入采样率分别记录。首轮按以下目标制定窗口，而非统一截为 5000 点：

| 分析目标 | 物理窗口依据 | 输入处理与核对 |
|---|---|---|
| 短时电流异常、相间关系与频谱 | 最短目标事件及所需频率分辨率，同时保留正常上下文 | 优先使用高频支路；核对幅值、持续时间和频带保真，采样不足时补采 |
| 速度跌落、反转、振荡及恢复 | 包含事件前基线与完整恢复过程 | 可抗混叠后降采样；核对峰值、恢复时间、滤波延迟及事件对齐 |
| 启动、模式切换与持续异常 | 覆盖目标控制阶段及跨窗口连续性 | 使用长记录或连续滑窗；固定步长、重叠和事件合并规则，检查持续异常漏报 |

开发集上比较少量有物理依据的窗口后冻结参数；定长插值、归一化和降采样均需检查是否削弱短瞬态或幅值故障。当前自动 PMSM 预设采集 0.8 s，GUI 单次采集 0.4 s；目标过程超出记录时先调整采集时长、触发及样点预算。完整流程中的窗口由检测结果或预定滑窗产生，真实故障区间仅供评价和独立算法试验使用。

当前自动 PMSM 采集有速度、三相电流、转矩、参考和负载，适合动态特征起步。电气残差、单分流重建误差、栅极/PWM 故障和无感启动需补齐相应模型与测量点。10 kHz 数据无法证明完整捕获微秒级毛刺；需要单独设计带宽、采样率与触发。模型可接收多通道不等于采集已经包含可辨识故障的信息。

数据集按完整运行、生成配置族和工况分组，分别保存正常行为、异常区间、故障类别、注入源及部件映射。故障指令时刻、实际激活时刻和症状起点分别标注。波形切窗增加训练样本，不增加独立运行数；相同确定性仿真重复也不增加独立工况数。

正式比较包含：同分布留出、未见工况留出、未知故障类留出，以及后续固件/板卡/实体域留出。仅有几十次运行时用于检查可行性和明显错误，采用结论需要足够独立测试单元及不确定区间。详见 [B 组协议](experiment-protocol.md)。

## 6. 候选技术的采用条件与决策规则

| 候选 | 进入条件 | 采用依据 | 暂缓/退出与回退 |
|---|---|---|---|
| PICT | 多因素、合法约束、可执行映射齐备 | 独立复算达到声明覆盖，较人工/随机减少有效执行成本 | 因素少时全枚举；机制未实现时先补能力 |
| PSY-TaLiRo | 多时序规格或多个搜索器需要统一编排 | 定量语义核对通过，集成维护收益超过适配成本 | 简单回调即可满足时暂缓框架 |
| BO | 单次调用较贵、裕度可评价、至少两类有区分度需求 | 调用/墙钟或独立失效发现有稳定改善，不能只靠已知失败点 | 无益则保留 Sobol/直接搜索；范围无区分度则更换任务 |
| TimeRCD | 权重可用、物理窗口适配、独立正常校准及测试集 | 相同校准误报目标下提高事件召回/定位，关键工况不明显退化 | 长异常/正常切换失效则采用条件化统计或仅在适用子任务启用 |
| MiniRocket | 已标注故障及工况留出 | 达到故障识别要求，训练/推理成本低 | 数据缺类先暂缓类别结论；效果差则回到特征基线 |
| MantisV2 | checkpoint 可获取、尺寸转换验证、有分类标签 | 相同标签预算改善宏 F1/最差工况，或达到同等效果显著节约标签 | 无优势则采用 MiniRocket/物理特征；不默认追加全量微调 |
| MOMENT | 第二轮；首轮有明确表示不足，固定特征方案、输入/聚合明确 | 异常或分类中至少一个任务有可复验增益 | 无增益移出常规流程，保留比较结果 |
| TS2Vec | 足够多样的训练域未标注数据、训练预算 | 少标签或未见工况增益超过额外训练成本 | 样本不足暂缓；无增益用冻结表示 |
| 物理残差/辨识 | 信号和模型可观测，参数及正常误差可核对 | 特征误差、配对故障区分或跨工况定位改善 | 失配严重时保留信号特征，补测量后重评 |
| AERCA | 同步正常序列、明确源头标签、假设检查 | 部件级定位和混淆原因区分优于残差/偏差基线 | 不可辨识则报告原因集合；假设不匹配退出该任务 |

分别报告分析效果与资源成本，并单列关键故障漏报和最差工况表现。运行成本包括预处理、训练、下载/加载、特征提取、推理和人工修订；正式比较同一机器、固定版本并给调参同等机会。

## 7. 实施顺序与阶段交付

按任务依赖与预期能力增益安排实施顺序，完成基准预试和成本测量后确定阶段工期。A、B 共同使用需求和数据清单；B1 特征分析、B2 异常及 B3 诊断准备可与 A 组生成原型并行推进。

任务二的首轮比较按下表执行，各任务在其数据与故障机制就绪后启动；候选目录中的其余方法不同时进入首轮。

| 分析任务 | 首轮主要比较 | 后续进入条件与候选 |
|---|---|---|
| 行为特征分析 | 固定工程指标 vs 扩展时频/动态特征 | 动态建模或预测残差有明确需求时加入一种低阶辨识模型；必要时首轮保留 |
| 异常检测 | 条件化统计/IForest vs TimeRCD | 表示能力不足时试 MOMENT；训练域未标注数据充分时试 TS2Vec |
| 故障识别 | 物理特征分类器 vs MiniRocket vs MantisV2 | 少标签/跨工况表现不足时试 TS2Vec 或 MOMENT |
| 故障定位 | 标准化偏差 vs 条件化正常参照＋物理残差签名 | 残差难区分传播源且假设、数据条件满足时试 AERCA |
| 诊断反馈 | 固定复验 vs 随机选择 vs 分歧选点 | 有限候选池不能满足诊断目标时再考虑更复杂的主动实验设计 |

1. **冻结任务与数据需求**：确认两类电机需求、正常动态、首批故障及观测点，补齐因素—执行能力表。已有指标是基线，新增分析目标单列。
2. **完成电机特征与基线试验**：复验当前版本，生成分组数据；交付动态特征、条件化异常基线、故障机制与标签字典。
3. **比较重点候选**：A 侧运行组合与搜索对照；B 侧按首轮表比较异常发现、故障识别及定位收益，并报告完整波形起点的端到端效果。
4. **按错误样本增加第二轮方法**：按表示不足选择 MOMENT 或 TS2Vec，需要传播源定位且假设成立时试 AERCA；每次只回答一个明确的分析不足。
5. **L3 迁移与诊断反馈**：真实正常闭环验收后，用独立实体数据比较；进一步检查复验选择是否提高定位效率。

首批交付包括电机场景的动态特征与异常检测结果、故障识别与混淆分析，以及同预算下的有效反例发现结果。通过效果对照表说明各方法相对基线的收益和适用范围，并提供错误样本、成本及可复现配置。

模块、输入输出和逐项验收见 [能力及实施映射](capability-and-implementation.md)。质量保障沿用现有 `lab.ps1`、原始记录、版本和复核；第三方算法放在独立环境，经文件/JSON 交换，按实际需要增加少量接口。

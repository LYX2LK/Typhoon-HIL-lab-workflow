# 工况能力、接口与实施任务

用于把 [技术选型](technical-selection.md) 转为开发与实验任务。目标先由测试问题确定，现有能力决定接入顺序与新增工作。下文新模块名为建议路径，不表示已经实现。

## 1. 当前能力核对

2026-11-08 对 `boost_input_disturbance`、`pmsm_software_preview`、`im_speed_step` 执行只读 `validate-case --json`。三者静态通过，运行证据均为 `not_verified`，原因为 `evidence code is stale`。原始响应见 [project-checks.json](project-checks.json)。本轮不调用设备 API、不运行模型。

PMSM 当前控制时间量化为 50 µs，最多三个转速/负载事件；自动采集 20–200 kSa/s，且单次总样点上限 100,000，不能同时取最大时长与最大采样率。具体约束来自 [适配器](../../../src/typhoon_lab/pmsm_preview.py) 及校验返回。范围表示软件当前允许的配置，不是实体板卡电气额定值。

## 2. 因素—执行能力矩阵

状态：S＝静态声明支持、当前运行待复验；E＝需要扩展；P＝实体计划待接入。因素分区是目标设计，具体值按模型/规格冻结。

| 因素与候选分区 | 参数/事件与状态 | 生效观测 | 对应分析/判据 | 限制和最小新增工作 |
|---|---|---|---|---|
| 转速：低/中/高、上/下阶跃 | PMSM `reference_speed_rpm`，S | `LabReference`/导出参考与机械速度 | 跟踪、超调、恢复、振荡 | 初始参考范围与事件参考范围不同；数值分区需按有效运行区间确认 |
| 负载：轻/重、上/下变化 | PMSM `load_torque_nm`，S | `LabLoad`、电磁转矩、速度 | 跌落、恢复、转矩/电流响应 | 负载命令在实体侧不自动等于实际负载 |
| 阶段：启动/稳态/零速给定 | 初值与事件模板，S | 参考、速度与状态条件 | 分阶段正常行为与响应特征 | 零速给定不等于真实停机/驱动禁止；实体停止语义需确认 |
| 顺序：调速后负载/负载后调速 | 事件列表，S；快速相邻事件 E | 两目标实测变化及相对时刻 | 顺序敏感性、短序列覆盖 | 当前最多三事件，各事件后需完整稳态窗；快速切换不能绕过校验器 |
| 供电：低/额定/高 | PMSM 初始 `dc_bus_v`，S；运行中供电扰动 E | 初值回读；动态需新增母线采集 | 跟踪/电流与供电关系 | 新增动态电源事件及激活探针；Boost 范围不可移植到板卡 |
| 电机参数族：惯量/电阻等 | PMSM 编译前参数，S | 参数快照、轨迹响应 | 鲁棒性、跨参数泛化 | `Lq>Ld` 等约束保持；改变参数是模型试验，不自动等同实体故障 |
| 测量链：偏置/增益/间歇丢失 | 导出副本可构造；闭环反馈注入 E | 独立真值、反馈值、注入探针 | 异常检测、传感器类识别 | CSV 编辑只能评价信号级异常；需模型反馈路径注入才能评价闭环影响 |
| 执行链：单通道驱动缺失 | PMSM 故障模型/适配器 E | 驱动指令、实际作用点、相电流 | 部件定位、相似故障区分 | 新建可控开关故障副本及独立探针；核验实际电流路径 |
| 通信：正常/超时/恢复 | 当前 LIN Mock；真实链 P | 总线时间戳、接收状态、控制响应 | 超时/恢复需求及端到端延迟 | Mock 仅检查协议流程；真实驱动/固件/同步待接入 |
| 保护：限流/禁止/恢复 | L2 控制逻辑扩展 E；L3 P | 状态、驱动、反馈与保护输出 | 触发阈值、响应时延、恢复行为 | 需要控制器规格、可观察保护状态及对应固件 |

首轮 A2 先用前四项及可确认的初始条件构造合法因素表。故障、通信、保护保留在目标清单并分别安排实现；不能因当前缺接口就删除研究问题，也不能把设计组合计为执行覆盖。

## 3. 分析任务—观测点映射

| 分析需求 | 已有/需补数据 | 交付层级 |
|---|---|---|
| 反转、速度振荡、负载响应 | PMSM 已有参考、速度、转矩、负载及三相电流 | 可在当前软件模型复验后开展 B1 |
| 电流时频和三相不平衡 | 已有三相电流；核对采样与模型频率 | 可做模型层 B1/B2；真实传感器特性另验 |
| 电气残差/dq 特征 | 补电角度、相电压或等效施加电压、参数与驱动 | E；无法仅由当前七路导出完整建立 |
| 传感器故障与负载变化区分 | 真值与反馈两条信号、注入探针、同表象任务对 | E；是 B3/B4 的数据建设重点 |
| 开关/驱动通道定位 | 六路驱动、有效作用状态、相电流/电压 | E/P；已有整流桥案例只作辅助验证 |
| LIN 到保护动作时延 | 总线、控制状态、栅极与采样的时间关联 | P；无同步依据时分别分析各时间域 |
| 单分流与无感启动诊断 | 实际测量窗口、缩放、重建/观测器状态与固件版本 | P；单独设计，不能由内部角度软件预演替代 |

## 4. 最小接口草案

所有新结构均为规划，不直接更改当前 CLI 协议。

| 对象 | 最小字段 | 使用者 |
|---|---|---|
| `TestSpec` | 需求引用、模式/前置条件、因素标签、带单位参数、事件序列、预期行为、判据引用、能力版本 | LLM/组合生成器→配置编译器 |
| `CapabilitySnapshot` | 模型/后端、参数与设置阶段、事件目标/数量/量化、采集信号/单位、硬约束、模型有效范围依据 | 编译器与计划器 |
| `ExecutionOutcome` | 候选 ID、run_dir、配置/模型摘要、执行状态、激活状态、数据状态、性能状态、计数/耗时 | 执行器桥接→搜索器 |
| `ObjectiveValue` | 需求 ID、裕度及单位、`evaluable`、不可评价原因、目标/判据版本 | 搜索器 |
| `AnalysisInput` | 原始记录引用、来源、信号/时钟、工况、可用信息清单、拟合/校准/测试分组 | 特征/检测/诊断模块 |
| `AnalysisResult` | 任务类型、方法/权重/预处理版本、特征、分数、事件、类别、可疑部件排名、未知/不可辨识状态、成本 | 评价器与展示 |
| `RetestProposal` | 当前候选原因、可区分预测、需要的测量、合法刺激、预期区分结果、成本 | 分析反馈→测试规约 |

`ExecutionOutcome` 的分类映射在桥接层完成：`invalid_config / execution_error / stimulus_not_activated / insufficient_data / performance_pass / performance_fail`。前四类 `ObjectiveValue.value=null`，仍消耗相应预算。仅当激活与数据有效才读取性能裕度。现有 `record_status` 等状态保留，不能覆盖为新枚举。

学习分析器读取的特征白名单与评价器读取的真值/故障标签分离。记录之间由 ID/路径关联；原始采样不改写，派生分析保存到独立结果目录。

## 6. 依赖与资源进入检查

不在 Typhoon 配套环境里直接升级 NumPy/PyTorch。每个算法独立锁定代码、依赖、checkpoint 和预处理版本，先验证少量代表记录的形状、数值、峰值资源和端到端耗时。

- PICT、MiniRocket、传统模型先用 CPU。MiniRocket 作者仓库标为 GPL-3.0，拟采用具体实现时登记许可证；不能沿用原方案中其他工具的 MIT 判断。
- Mantis 代码与 MantisV2 模型卡均标 Apache-2.0；读取到的 `mantis-tsfm` 1.1.0 元数据支持 Python ≥3.10、<4.0。本轮未安装或下载权重，不声明本机可运行。
- TS2Vec 作者环境建议较旧（Python 3.8/PyTorch 1.8.1 等）；先隔离复现或测试兼容迁移，成本计入选型。
- TimeRCD/MOMENT/AERCA 沿用候选资格，重新固定所用版本和权重许可；不得把官方教程能运行等同本项目已经通过。

许可证/接口来源见 [证据表](evidence-register.md)。资源不足时优先缩小候选和分阶段比较，依据明确的性能瓶颈决定扩容。

# 面向电机 HIL 的智能测试生成与数据分析：技术选型方案

编制日期：2026-11-09。本文面向具有控制与测试专业基础、参与方案讨论和实验实施的研究人员，说明两项任务的研究问题、优先技术路线、方法取舍和验证安排，为选择首批实验及后续投入提供依据。选型依据为截至该日期的文献调研；候选方法在本项目中的效果由后续实验确定。

## 1. 研究目标与选型结论

**围绕两项任务开展研究：在有限测试预算内扩大有效测试覆盖，发现人工设计容易遗漏的系统失效；从测试数据中提取更多有用信息，更准确地刻画动态行为、发现异常、识别故障、定位原因并总结跨工况规律。** 以电机控制系统为验证对象，比较语言大模型、专用时序模型、数值搜索和物理分析方法的效果，形成适用条件明确的方法组合。

硬件在环（Hardware-in-the-Loop，HIL）测试通过实时仿真被控对象，使控制器能够在可重复工况下接受测试。本研究先在 Typhoon 的电机软件闭环中建立基准，再迁移到真实控制板与实时电机模型组成的闭环。研究重点由目标问题决定，已有模型、接口和工具用于提供实验基础，并按分析需要补充。

| 核心问题 | 优先技术路线 | 希望获得的能力增量 |
|---|---|---|
| 哪些工况、参数与事件次序更容易触发失效？ | 用组合覆盖组织离散工况；比较数值搜索、LLM 语义反馈搜索与二者混合 | 同预算覆盖更多有效交互，更快发现性能边界和不同失效模式 |
| 稳态指标之外，波形还反映了什么系统行为？ | 时域、时频与动态特征，结合按工况建立的正常参照和物理残差 | 提取短时反转、振荡、恢复退化及跨通道关系变化 |
| 相似波形是否来自不同故障？ | 专用检测/分类方法，与融合信号、工况和机理知识的 LLM 诊断比较 | 改善相似表象区分、少标签识别、未见工况表现和原因定位 |
| 动态行为与诊断效果如何随工况变化？ | 分析特征响应与误诊分布，在未见工况检验规律 | 找出性能退化与诊断混淆的工况范围，指导后续测试 |
| 现有观测不足时，下一次应测什么？ | 根据候选原因的预测响应差异或预期信息增益选择复验，与 LLM 提案比较 | 用更少新增实验缩小原因范围并正确定位 |

首轮优先研究 **LLM 参与的失效搜索** 和 **融合信号特征与机理知识的故障诊断**。动态特征、统计方法和物理分析提供基础信息与比较参照；专用时序模型用于检验时序形状和预训练表示的附加价值。具体比较范围根据研究假设、数据条件和接入成本确定，通过初步实验逐步调整。主动复验在形成候选原因及可区分动作后开展。

本方案中的 LLM 指语言大模型，VLM 指视觉语言模型；MantisV2 等时序基础模型通过时序预训练获取表示，两类模型的能力与输入方式分别评价。LLM 可以直接选择测试点、判断故障、提出分析调用和复验动作。是否采用某种组合，取决于它相对强基线增加了多少有效信息、改善了多少结果，以及增加多少成本。

**后续部署以本地小参数语言模型为目标。** 在线推理、领域训练和离线方法生成分别研究：模型既可在测试间选择动作和分析证据，也可生成分析程序，或通过微调、时序对齐与蒸馏形成可部署能力。远程 API 与本地推理服务是不同的运行方式，均可通过程序接口连接工具；采用何种方法与部署位置分别确定。本地模型尽早纳入任务验证，适配与资源评价见 §5.5。

上述路线来自[LLM 专题调研](../2026-11-09-llm-core-methods/research-report.md)：LLM-Falsifier/GLLMPro 支持反馈搜索候选，S2S-FDD/TraceBench 支持信号与知识结合及工具分析，Argos 支持规则生成，ATTLLM/FD-LLM 等提供训练适配参考。各文献的阅读深度和适用限定见专题调研及第 8 节。

## 2. 验证对象、典型问题与预期输出

### 2.1 验证场景

以永磁同步电机（PMSM）的启动、调速、负载扰动和零速响应为主场景，进一步引入测量/反馈异常与执行通道异常。以下两个例子分别说明交互失效搜索与相似表象诊断，可作为初步验证场景：

- **交互失效发现**：调速与加负载分别通过，但特定幅值、时间间隔或先后次序使速度恢复过慢、振荡加剧或触发已定义的限制。
- **相似表象诊断**：速度下降或恢复变慢，可能来自正常负载变化、速度反馈偏置或执行通道异常；需要利用电流、控制状态、事件关系和机理预期区分原因。

后续按需求类型、运行阶段和故障机制扩展验证范围，同时考察动态行为刻画、未知异常与跨工况规律。方法的适用范围由扩展实验确定。

| 验证层级 | 研究用途 | 结果适用范围 |
|---|---|---|
| 电机软件闭环 | 建立可控工况、注入机制、完整运行数据与方法比较基准 | 对应软件控制器、模型参数和可观测信号 |
| 真实控制板 HIL | 以 TLE9877 控制板为目标，验证接口、固件保护、反馈条件及方法迁移 | 对应具体板卡、固件和实时电机模型；须先完成正常闭环联调 |
| 辅助教学模型 | Boost 等用于执行接口、配置生成与已知失败回归 | 用于流程检查；电机方法结论由电机场景给出 |

软件预演采用的理想角度、控制参数等与实体控制器分别登记。按目标应用分别确定分析方法可用的观测和评价器持有的真值。模型内部转矩、真实速度等可用于构造真值或计算参考误差；目标 HIL 环境实际可读取的仿真器状态，也可作为已声明的分析输入。若迁移目标无法获得这些信号，应另设受限观测下的比较。

### 2.2 两项任务的输入与输出

**任务一输入**为需求、控制阶段、可施加输入、参数范围、事件约束和历史执行结果；**输出**为可执行测试、覆盖情况、规格违反条件及相应响应。这里的“失效”是违反已定义的功能或性能需求，故障注入是研究该问题的一种实验手段，二者分别记录。

**任务二输入**为完整多通道波形、工况与事件记录，以及允许使用的模型/机理知识；**输出**包括动态特征、异常区间、故障类别、可疑位置或原因集合、跨工况规律与下一步复验建议。正常但复杂的启动、调速和负载响应必须进入数据集，用于检验误报与误诊。

两项任务通过以下过程衔接：

```mermaid
flowchart LR
    A[需求、工况与故障机制] --> B[组合覆盖与测试搜索]
    B --> C[电机闭环执行与采集]
    C --> D[动态特征、异常检测与故障诊断]
    D --> E[候选原因与区分性复验]
    E --> C
    D --> B
```

任务一侧重在较大范围发现问题；诊断复验侧重区分当前问题的原因。两者复用执行接口，分别设置目标与指标。

## 3. 任务一：智能测试生成与失效边界搜索

需求转换解决测试意图如何落到可执行操作的问题，组合覆盖减少离散工况交互的遗漏，自适应搜索则利用执行反馈寻找更容易违反需求的测试。已有可执行配置时，可直接开展搜索比较；因素组合较多时，再用组合覆盖组织初始测试或补充探索范围。

### 3.1 将需求转为可执行测试

采用“需求与接口资料→结构化测试规约→约束检查→可执行配置”的流程。规约包含测试意图、初始状态、事件、输入范围、观察信号和判定条件。LLM 结合检索到的接口、操作原语和工程知识提出规约，由固定校验程序检查字段、单位、合法范围及事件可执行性。需求到台架操作的映射参考 AutoHIL。[1]

比较人工模板、直接 LLM 生成、检索与规约约束辅助的 LLM 生成。评价语义正确率、可执行率、有效激励率和人工修订时间。缺少接口或需求值时形成待补字段；合法配置能否实际激活目标工况，由执行结果检查。

### 3.2 组合覆盖与事件次序

离散因素较多时，优先考虑 PICT 生成速度分区、负载分区、运行阶段、故障机制和注入时机等因素的合法成对组合；少因素任务可用全枚举，高风险交互确有需要时增加局部三因素覆盖。组合覆盖针对已定义的因素空间，连续参数边界和失效发现效果由搜索实验评价。[PICT 官方文档](https://github.com/microsoft/pict/blob/main/doc/pict.md)

另设“调速→负载变化”“负载变化→调速”“异常→恢复”等状态转换与短事件序列。参数组合覆盖和事件次序覆盖分别计算。覆盖分母为冻结的合法组合/序列集合，同时报告设计覆盖与实际有效执行覆盖。

### 3.3 LLM 语义反馈搜索与数值搜索

数值搜索利用需求的满足程度探索测试空间，LLM 语义反馈搜索进一步结合需求含义、变量的物理关系和历史响应选择下一测试。本节检验这些信息是否提高搜索效率，以及 LLM 提案与数值优化能否互补。

首批搜索需求优先从调速后的速度误差与恢复时间，以及负载扰动、事件交互下的速度跌落和振荡中选择。涉及电流或保护的判据在取得对应需求后加入。每项需求计算**需求满足裕度**：正值满足，负值违反。例如，恢复时间裕度为 `ρ_rec = T_limit − T_recover`，表示允许恢复时间与实际恢复时间之差。阈值记录其需求来源；探索性阈值对应研究判据。不同量纲分别优化，联合目标的归一化在正式比较前固定。

LLM 获取变量的物理含义、需求、历史输入、需求满足裕度和时间对齐的响应特征，直接提出下一组参数或事件模式。混合方式由 LLM 提出高风险区域、数值优化器进行局部细化。方法参考 LLM-Falsifier 与 GLLMPro；前者已在公开 CPS 基准研究该问题，项目需要重新建立同预算电机对照。[2][3]

| 组别 | 测试选择方式 | 比较目的 |
|---|---|---|
| A0 数值与工程基线 | 随机、Sobol 采样及 Dual Annealing 等数值优化候选；固定工程启发式作为另一参照 | 建立数值探索与已有领域知识的参照 |
| A1 LLM 搜索 | 需求语义、变量含义、历史参数与裕度→下一测试点 | 检验语义对搜索效率的作用 |
| A2 响应反馈搜索 | A1 增加恢复、振荡等特征及最接近违反需求的时刻 | 检验响应信息能否改善测试选择 |
| A3 混合搜索 | LLM 提出区域/事件模式，直接搜索器细化参数 | 检验语义探索与数值优化的互补性 |

首批从 A0 选取适合当前空间的基线，与 A1 开展比较；同轮固定 LLM 版本和推理设置。需要检验响应信息的作用时加入 A2，需要检验语义提案与数值优化的互补性时加入 A3。各组复用测试提案与执行入口，具体实验组合由待回答的问题确定。正式形成方法优势结论前，补齐相关强基线；所选 A0 方法分别报告结果。移除变量语义的消融、工程启发式对照和信息量匹配试验，用于核验相应的贡献解释。

单次执行较昂贵且裕度有效时，再加入贝叶斯优化；多时序规格和多个搜索器需要统一组织时再引入 PSY-TaLiRo。初始原型采用轻量执行回调，保留更换优化器的能力。[PSY-TaLiRo](https://github.com/cpslab-asu/psy-taliro)

### 3.4 测试搜索的评价

主指标为预算内失效发现率、首次发现成本、不同失效模式数及最佳需求满足裕度，辅助报告需求/组合/序列覆盖。按预先定义的“需求、控制阶段、响应形态”归类，结合复验判断不同原因；响应模式与原因机制分别记录，重复失败与新增模式分别计数。

同时比较相同闭环执行次数与相同总时间/费用两种预算。初始化、重复候选、非法候选的修正、LLM 调用和失败运行均计入相应成本；不可执行或数据不足的运行标记为不可评价，与系统规格违反分开。未找到失效的运行保留在成功率和首次发现的截尾统计中。

## 4. 任务二：测试数据分析、故障诊断与复验

数据分析首先提取完整动态过程中的行为与关系，再根据问题开展异常检测、故障识别和原因定位。动态特征及跨工况规律既是独立分析结果，也为诊断和后续测试选择提供依据。

### 4.1 提取动态行为和物理关系

先比较固定工程指标与扩展特征，量化完整动态过程中的差异。特征包括反转峰值及持续时间、超调/欠调、恢复时间、误差积分、振荡频率与衰减、电流均方根、不平衡和频带能量。变速过程结合转速或电角频率组织频域特征，必要时采用短时傅里叶变换或小波分析。

按运行阶段、速度和负载建立正常参照，将待分析响应与相近工况的正常表现比较，计算相对偏差。具备参数与观测条件时加入物理残差，以实际响应偏离模型关系的程度辅助分析，例如机械平衡残差：

`r_m = J·dω/dt − (T_e − T_load − B·ω)`

其中 J 为转动惯量，B 为黏性摩擦系数，ω 为角速度，T_e 和 T_load 分别为电磁转矩和负载转矩。参数误差、导数滤波和未测扰动进入正常残差标定。电气残差需要相应电压、电流、角度和参数；低阶 ARX/NARX 或状态空间辨识在需要预测残差时加入。

通过“信号特征、物理残差、二者融合”的对照，判断哪些信息有助于行为刻画及故障区分。SHAP、相关性和异常通道排名用于筛查；部件定位根据有真值的注入实验和区分性观测评价。

### 4.2 异常检测与专用故障识别

工程特征方法便于对应物理含义，时序形状方法用于检验人工特征之外的波形信息，预训练表示用于考察标签效率与跨工况能力。以下候选按这些不同问题组织，首批比较根据当前假设和数据条件选择。

| 分析环节 | 优先考虑的候选 | 选择理由与具体问题 |
|---|---|---|
| 异常检测 | 按工况建立的统计检测、IForest、TimeRCD | 比较局部及多通道异常的发现能力，重点检查正常切换、持续异常和短促异常 [4] |
| 故障分类 | 物理/动态特征分类器、MiniRocket、MantisV2 冻结表示＋线性分类头 | 分别代表工程特征、时序形状和预训练表示，比较同标签预算下的识别与跨工况能力 [5][6] |
| 原因/位置排序 | 相对同工况正常参照的标准化偏差、各残差的响应模式 | 判断相似表现能否映射到不同信号链或部件 |

初步实验可从统计检测、物理/动态特征分类器等合理基线起步，与相关时序候选或 LLM 路线开展有限比较。基线完善与候选方法探索交替推进，正式采用结论以相关强基线为参照。MantisV2 的冻结编码器仍需本任务分类标签。MOMENT、TS2Vec 可用于后续表示能力比较；AERCA 在传播源定位有明确需求、观测条件和闭环假设适用时评估。扩展选择依据见第 6 节。

### 4.3 融合信号、工况与机理的 LLM 诊断

本节重点检验机理知识与按需分析能否改善相似表象的区分，以及这些收益是否值得额外成本。**优先将有物理含义的波形信息与工况知识共同提供给 LLM，由它判断故障类别、比较候选原因并选择需要补充的分析。** 输入包括事件前后特征、正常参照差异、可测控制状态、残差、通道关系，以及允许使用的故障机制知识。方法参考 S2S-FDD 的信号语义组织和 TraceBench 的工具辅助原因归属。[7][8]

例如，同样出现速度下降，诊断器需结合电流是否出现不对称、负载事件是否先发生、测量值与独立观测是否一致，以及控制器的补偿响应进行区分。数据准备时核对各候选原因的作用路径、可用观测和预期区分证据，再通过实验检查可辨识性。观测支持多个原因时保留候选集合，必要时进入 §4.6 的诊断复验。

| 组别 | 输入与决策方法 | 要分离的贡献 |
|---|---|---|
| B0 专用方法 | §4.2 中与当前问题相关的分类/定位方法，正式比较补齐强基线 | 判断是否已有低成本有效方法 |
| B1 LLM 特征诊断 | 与特征分类基线相同的数值特征、工况信息，由 LLM 作判断 | LLM 对相同信息的利用能力 |
| B2 知识增强诊断 | B1 加正常参照、控制关系与故障机制知识 | 额外知识的作用；同时增加规则或案例检索对照 |
| B3 工具辅助诊断 | B2 按需调用特征、频谱、相似案例与已有通道查询 | 自适应信息获取的作用；对照固定提供同等信息 |

初步实验可比较 B0/B1；若核心假设是机理知识的价值，也可先比较 B0/B2，并在解释知识贡献时补充 B1 和规则或案例检索对照。研究按需分析的作用时加入 B3，与固定提供同等信息的方式比较。时序形状和预训练表示方法的整体性能单独报告；相同信息利用能力的判断以输入匹配的对照为依据。

比较既包括“相同信息下谁判断得更好”，也包括“加入何种知识后是否值得额外成本”。融合专用模型预测时，额外与简单规则融合/选择器比较。工业诊断研究已提示，混合方案优于裸 LLM 并不保证超过专用模型，因此 B0 是采用决策的主要参照。[9]

首轮通过语义明确的特征、检索结果和工具返回值连接时序算法与 LLM。若后续使用编码器隐向量，需要专门的对齐方法；模型自报置信度在独立数据校准后才能作为阈值或停止依据。

### 4.4 直接时序理解与分析方法生成

以下两个方向用于检验输入表示和分析方法生成的价值。可根据具体研究假设或初步实验中的遗漏选择一个小规模试点：

- **直接时序与波形图理解**：借鉴 LLM-TSAD 的统计分解与位置提示，或 VLM4TS 的候选区间＋全局波形图，检验不同输入表示对复杂异常判断的价值，重点考察候选检测器难以描述的异常；保留筛选器单独使用的结果。[10][11]
- **特征与规则生成**：借鉴 Argos，让 LLM 在训练/开发数据反馈下生成、修订特征或检测规则，检验其能否提取人工特征遗漏的动态关系或减少特征设计工作。与人工特征、规则库及受限自动搜索比较，正式测试前冻结程序，在线执行成本与生成成本分别报告。[12]

时序—语言对齐、领域微调和蒸馏提供进一步的训练路线。对齐用于连接时序表示与故障语义，需相应配对数据；领域与工具使用微调可利用测试提案、分析调用和诊断样本；蒸馏用于检验能力能否迁移到较小模型或专用检测器。它们按目标与数据条件选择，具体路径见 §5.5。ATTLLM 等提供可借鉴方法，不同工业过程的数据条件需重新适配。[14]

### 4.5 跨工况规律与方法适用范围

按速度、负载、控制阶段和故障强度分析特征响应，提取恢复时间、振荡衰减、残差等随工况变化的关系，识别动态性能退化的区域。进一步分析检测与诊断的误差分布，找出更易漏检或混淆的工况，并据此补充任务一的测试范围。

跨工况规律以响应曲线、工况分区或可检验的关系表述，注明适用范围与不确定性，并用独立运行和未见工况检查。**未见工况泛化**指方法在训练未覆盖的工况下保持性能的能力；使用目标域未标注数据进行适应的结果另行报告。

### 4.6 诊断驱动的复验选择

当现有观测支持多个原因时，建立有限复验动作集，如改变速度/负载、调整事件间隔、增加指定观测或重复运行。优先选择能使不同候选原因产生可区分响应的动作，或能预期减少原因不确定性的动作。候选策略包括固定顺序、随机、基于预测响应差异或预期信息增益的选择、LLM 提案及混合选择，按当前问题选取对照。LLM 负责提出或排序动作，模拟/测量返回实际响应以更新判断。

读取已有数据与新增物理试验分别计费。所有方法共享可执行动作、初始信息和候选模型，环境只返回可测数据与运行状态；隐藏故障真值由评价器持有。CoffeeBench 提供动作—观测诊断的研究参考，其“告知猜测正误”等基准条件需要与实际 HIL 区分。[13]

评价固定预算内正确定位率、包含失败/未决情况的复验成本与诊断延迟。不可辨识的原因保留为集合，未知机制保留拒识出口。主动复验作为两项任务的后续连接实验，不影响独立测试搜索和数据分析结果的成立。

## 5. 数据、输入尺度与效果评价

初步探索使用开发数据检验可行性，记录独立运行、数据用途、方法设置和基本成本。正式比较前确定测试范围、工作点、预算和重复次数。具体采样参数、划分清单与实验配置随相应实验记录保存，本章说明影响选型结论的数据与评价原则。

### 5.1 按物理过程设计采集与模型输入

先确定目标事件持续时间、所需带宽及前后上下文，再确定采样率、窗口与模型长度。当前 PMSM 软件预演配置为 100 kSa/s、0.8 s；在这一采样率下，5000 点仅覆盖 50 ms。该配置是采集起点，正式数据集按目标过程调整。

| 分析目标 | 时间与带宽依据 | 输入处理 |
|---|---|---|
| 电流瞬态、相间关系与频谱 | 最短目标事件、需要保留的频带及频率分辨率 | 保留高频原始采样；可在原始数据上计算特征后供 LLM 使用 |
| 速度跌落、反转、振荡与恢复 | 事件前基线至完整恢复 | 抗混叠后按需降采样；检查峰值、恢复时间及滤波延迟 |
| 启动、模式切换与持续异常 | 完整控制阶段和跨窗口连续性 | 长记录或连续滑窗；固定步长与事件合并规则 |

记录原始采样率与派生输入采样率，用 `输入点数 ≈ 窗口秒数 × 输入采样率` 核对。定长插值、幅值归一化和波形绘图都检查是否损失短瞬态或偏置/增益信息。状态日志先做事件级关联，时间精度满足要求后再进行逐点融合。

### 5.2 数据集与真值

正常数据覆盖启动、调速、负载变化与稳态；故障数据覆盖可实现的反馈偏置/增益、执行通道异常及不同强度。各机制登记注入位置、指令时刻、实际生效时刻和症状起点。物理闭环中的反馈修改、导出数据修改和实体故障分别标注。

按完整运行、配置族和工况分组，再进行切窗，防止相邻或重叠窗口跨训练/测试。正常参照、知识库、阈值、提示示例、自动生成程序均只由训练/开发部分确定；测试故障标签、注入位置和未来数据保留给评价器。

正式评价按结论范围设置同分布、未见速度/负载/事件组合、未知故障机制，以及后续实体域测试；数据随研究推进逐步补充。已用于探索和方法选择的数据保持开发用途，独立测试可从未使用的运行中划分或另行采集。少标签按独立标注运行数比较；切出更多窗口不视为新增独立样本。所有方法在各自允许的信息范围内共享数据划分与可用观测。

### 5.3 独立能力与完整流程分别评价

| 评价层次 | 输入条件 | 主要指标 |
|---|---|---|
| 行为特征 | 有参考值或受控变化的运行 | 特征误差、重复性、对动态变化的分辨能力 |
| 跨工况规律 | 独立运行与留出的工况 | 关系的重复性、预测误差或趋势一致性、适用范围 |
| 异常检测 | 完整正常/异常记录 | 正常运行单位时间误报、事件召回、检测延迟、区间质量 |
| 独立分类/定位 | 给定真实事件区间 | 宏平均 F1、混淆矩阵、部件级 Top-1/Top-k、误定位 |
| 完整诊断流程 | 完整波形，自动检测、截窗与诊断 | 规定时限内检出并正确识别率、误报、拒识、误定位与总延迟 |
| 主动复验 | 相同初始信息与动作预算 | 正确定位率、复验次数/成本、未决比例 |

**已知故障的端到端检出并正确识别率 = 规定时限内被检出并正确识别的已知故障事件数 ÷ 全部真实已知故障事件数。** 漏检、错分类和超时保留在分母中。未知故障单列“检出且正确拒识率”，同时统计已知故障被错误拒识的比例；正确拒识与根因确定分别评价。

事件匹配、允许延迟、滑窗合并和阈值在正式测试前冻结。主结果使用开发集确定的工作点，报告实际误报；测试集最佳阈值和点调整 F1 仅作附加参考。正常瞬态、短异常、持续异常和最差工况分别列结果。

### 5.4 预算与重复试验

训练标签、可用知识、工具调用、调参机会和计算资源分别记录。LLM 搜索/诊断在同轮比较中固定模型版本、推理设置与提示版本，在关键结论上增加第二个模型检验方法的可迁移性。本地目标模型与远程参照分别报告，模型选择关注结构化输出、工具使用、输入长度及完整任务成本；视觉路线另检查图像能力。

预试测量运行方差、执行成本与故障发生比例，再预注册正式重复次数、预算档位和实际有意义的提升门槛。对相同需求和测试组作配对比较，按独立运行或配置族计算不确定区间，同时报告平均表现、关键故障漏诊和最差工况。仿真确定性重复用于测量模型或搜索随机性，配置多样性通过独立工况提供。

### 5.5 本地小参数模型的部署与适配

本地部署是目标运行条件，首批方法验证即纳入一个与现有资源匹配的小参数模型。采用本地推理服务或直接程序调用，复用测试提案、分析工具和结果反馈协议。先测量原有权重配合任务提示、知识检索和工具的能力，再依据错误分析选择训练与压缩路线。远程较强模型可作为能力参照或经核验的训练数据生成来源，本地模型单独完成相同任务以确认可部署效果。

| 路线 | 实施方式与所需数据 | 需要验证的收益 |
|---|---|---|
| 原有权重＋知识与工具 | 将需求、接口、工况和机理组织为输入；通过程序计算波形特征和返回工具结果 | 小模型能否合法提案、选择有效分析并依据反馈更新判断 |
| 领域与工具使用微调 | 用有执行反馈的测试提案、工具调用、故障证据与诊断结果构造监督样本；比较原有权重与监督微调/LoRA 版本 | 任务正确率、工具使用、少标签或跨工况能力是否提高 |
| 时序—语言对齐 | 将时序编码器与语言模型通过训练的映射连接，使用波形与故障属性等配对数据 | 波形表示是否补充语义特征遗漏的信息；与特征输入比较 |
| 知识蒸馏 | 选择目标为小语言模型或专用时序检测器；使用核验后的教师输出、表示或任务反馈训练 | 能否以更低资源保持所需能力；教师与学生分别评价 |
| 离线规则/程序生成 | 在开发数据上生成、执行和修订特征或规则，冻结后部署普通分析程序 | 新特征是否有效，在线成本是否降低；生成成本单列 |

训练样本按独立运行与配置族划分，生成数据及教师输出使用执行结果、已知机制或分析程序核对。测试标签与测试反馈保持独立。直接读取数值序列或波形图的路线，也在本地模型具备对应输入能力时比较；图像路线需要视觉模型。

本地部署记录参数规模、权重版本、精度/量化方式、输入长度、显存或内存峰值、加载与单轮推理延迟、完整任务耗时。量化前后复测提案合法性、工具调用和任务效果；训练另报资源与数据准备成本。根据实际输入、并发和任务频率确定部署配置，具体模型与硬件规格通过试运行选择。

## 6. 方法试验与采用依据

小规模试验用于检验明确的技术假设，选择依据包括预期信息增量、标签与人工成本、跨工况能力及接入代价。已有方法暴露的不足、文献支持的假设或可验证的工程收益，都可以成为试验理由。正式采用则需要相关强基线和独立数据支持，并说明收益适用的任务与工况范围。

| 方法 | 小规模试验依据与准备条件 | 正式采用依据 | 后续处理 |
|---|---|---|---|
| LLM/混合失效搜索 | 检验语义与响应反馈的作用；具备需求、合法动作和需求满足裕度 | 相同执行预算或总成本下提高失效发现；扩大采用范围时检验跨需求收益 | 无稳定增益则保留数值搜索，分析语义信息与搜索空间的影响 |
| TimeRCD | 检验上下文差异对异常检测的价值；具备可用权重、输入窗口方案与正常校准数据 | 在可接受误报下改善事件召回/区间定位，关键工况退化可控 | 保留按工况建立的统计检测参照；需要比较其他表示时考虑 MOMENT/TS2Vec |
| MiniRocket/MantisV2 | 检验时序形状或预训练表示的价值；具备分组标签与输入转换方案 | 识别、少标签或跨工况收益值得训练/推理成本 | 保留物理特征分类器参照，根据结果决定是否适配训练 |
| LLM 知识与工具诊断 | 检验机理知识或按需分析的作用；具备语义特征与相应知识、工具 | 超过强专用方法或以相当效果明显减少标签/分析成本 | 解释质量与诊断性能分别评价，融合收益单独核验 |
| 物理残差/低阶辨识 | 检验物理关系对行为分析的价值；观测、参数与正常误差可核对 | 改善相似故障区分或动态规律提取 | 模型失配较大时补充观测或采用同工况正常数据参照 |
| LLM 直接时序/VLM、规则生成 | 有具体的输入表示或特征生成假设，以及可用于验证的数据 | 在独立测试上改善检测/特征能力，收益超过额外调用和开发成本 | 先选一个试点，结果决定是否扩大 |
| 主动复验 | 候选原因对可执行动作有预期可区分的响应 | 相同预算提高正确定位或减少必要实验 | 根据效果选择固定、预测响应差异或 LLM 等策略 |
| 本地小模型适配、对齐与蒸馏 | 具备目标任务样本，明确需改善的任务能力或资源目标；按 §5.5 选择路线 | 本地任务效果与资源收益值得数据准备和训练成本 | 比较原有权重、适配版本及压缩版本，确定部署组合 |
| AERCA 等传播源方法 | 传播源定位需求、观测条件与方法假设成立 | 改善目标定位问题 | 按具体问题增补 |

报告同时给出性能、标签需求、预处理/训练/推理成本及维护工作量，选取能满足目标且代价合适的组合。充分比较后发现某方法缺乏稳定收益、明确其失败边界或确定更低成本的替代方法，同样构成选型成果。

## 7. 实施路径与阶段产出

实施以能够回答当前研究问题的可运行实验为起点，优先复用已有执行、采集与分析能力。每项核心任务先选取合理基线和有明确依据的候选方法开展初步比较，再根据结果完善对照、扩展场景或调整技术路线。A0—A3、B0—B3 提供比较设计的参考，实际实验组合由拟回答的问题确定。

下表给出从初步验证到选型与迁移的推进路径。基线完善、候选方法试验和数据补充可以迭代开展，任务一与任务二可在具备各自输入条件后分别推进。

| 环节 | 主要工作 | 阶段产出与后续决策 |
|---|---|---|
| 1. 选定问题并准备首批实验 | 选择可执行的需求或分析问题，核对信号、判据、故障机制和合法动作；复用并核验软件闭环 | 可复核的运行样本、输入输出及预期区分证据，据此选择初始基线和候选方法 |
| 2. 开展核心方法初步比较 | 搜索优先比较 A0/A1；诊断按假设比较 B0/B1 或 B0/B2；同步检查动态特征与运行成本 | 初步效果、失败样本和成本记录，决定继续验证、调整方法或补充数据 |
| 3. 完善对照并形成选型结论 | 补齐相关强基线、独立测试和必要消融；依据预试确定预算及重复次数；评价适用范围与完整流程 | 有证据支持的增益或无增益结论、跨工况规律及推荐组合 |
| 4. 扩展能力与验证范围 | 按研究假设选择新需求、故障机制、复验动作或表示方法试点 | 扩展场景结果、复验效率或单项能力改进，据结果更新选型 |
| 5. 实体控制板迁移 | 正常闭环及采集条件验收后，按目标 HIL 环境可用观测重新校准与比较 | 软件域和实体域独立结果、迁移成本与适用范围 |

实体条件尚未齐备时，软件闭环中的方法比较与主动复验可先开展；实体结果单列。

工程上复用 Typhoon 执行、采集和结果记录入口，按实验需要补充测试提案与合法性检查、响应特征与需求满足裕度、诊断/分析工具、复验动作与反馈四类能力。初步实验可采用轻量函数或文件交换，重复使用后再整理公共接口。底层实时控制由控制器和仿真器承担，模型在测试间选择与分析。第三方算法使用独立环境，经文件或结构化接口交换数据。

每次实验记录当前问题、复用能力、所需信号与故障机制、评价方法和实际结果。研究环境用于检索和离线分析，Typhoon 执行采用其配套环境。最终交付包含基准数据、可运行方法、动态行为与跨工况分析、性能与成本对照、失败案例和推荐组合，以及本地模型版本、适配方式、资源实测与运行说明，为后续测试任务及部署决策提供依据。

# 面向电机 HIL 的智能测试生成与数据分析：技术选型方案

编制日期：2026-11-09。本文面向研究方案讨论与实验实施，独立说明研究问题、技术路线、方法取舍和评价安排。选型依据为截至该日期的文献调研；候选方法在本项目中的效果由后续实验确定。

## 1. 研究目标与选型结论

**围绕两项任务开展研究：在有限测试预算内发现更多有价值的系统失效；从测试数据中提取更多信息，更准确地刻画动态行为、发现异常、识别故障与定位原因。** 以电机控制系统为验证对象，比较语言大模型、专用时序模型、数值搜索和物理分析方法的效果，形成适用条件明确的方法组合。

硬件在环（Hardware-in-the-Loop，HIL）测试通过实时仿真被控对象，使控制器能够在可重复工况下接受测试。本研究先在 Typhoon 的电机软件闭环中建立基准，再迁移到真实控制板与实时电机模型组成的闭环。研究重点由目标问题决定，已有模型、接口和工具用于提供实验基础，并按分析需要补充。

| 核心问题 | 优先技术路线 | 希望获得的能力增量 |
|---|---|---|
| 哪些工况、参数与事件次序更容易触发失效？ | 组合覆盖建立测试起点；比较数值搜索、LLM 语义反馈搜索与二者混合 | 同预算覆盖更多有效交互，更快发现性能边界和不同失效模式 |
| 稳态指标之外，波形还反映了什么系统行为？ | 时域、时频与动态特征，结合条件化正常参照和物理残差 | 提取短时反转、振荡、恢复退化及跨通道关系变化 |
| 相似波形是否来自不同故障？ | 专用检测/分类方法，与融合信号、工况和机理知识的 LLM 诊断比较 | 改善相似表象区分、少标签识别、未见工况表现和原因定位 |
| 现有观测不足时，下一次应测什么？ | 候选原因的响应分歧或预期信息增益，与 LLM 复验选择比较 | 用更少新增实验缩小原因范围并正确定位 |

首轮投入集中在 **LLM 参与的失效搜索** 和 **信号、机理结合的故障诊断**。动态特征、统计与物理方法提供必要信息和强基线，TimeRCD、MiniRocket、MantisV2 分别代表异常检测、时序形状分类和预训练表示候选。主动复验在前两项形成可评估结果后开展。

本方案中的 LLM 指语言大模型，VLM 指视觉语言模型；MantisV2 等时序基础模型通过时序预训练获取表示，两类模型的能力与输入方式分别评价。LLM 可以直接选择测试点、判断故障、提出分析调用和复验动作。是否采用某种组合，取决于它相对强基线增加了多少有效信息、改善了多少结果，以及增加多少成本。

## 2. 验证对象、典型问题与预期输出

### 2.1 验证场景

以永磁同步电机（PMSM）的启动、调速、负载扰动和零速响应为主场景，进一步引入测量/反馈异常与执行通道异常。两类典型问题贯穿研究：

- **交互失效发现**：调速与加负载分别通过，但特定幅值、时间间隔或先后次序使速度恢复过慢、振荡加剧或触发已定义的限制。
- **相似表象诊断**：速度下降或恢复变慢，可能来自正常负载变化、速度反馈偏置或执行通道异常；需要利用电流、控制状态、事件关系和机理预期区分原因。

| 验证层级 | 研究用途 | 结果适用范围 |
|---|---|---|
| 电机软件闭环 | 建立可控工况、注入机制、完整运行数据与方法比较基准 | 对应软件控制器、模型参数和可观测信号 |
| 真实控制板 HIL | 以 TLE9877 控制板为目标，验证接口、固件保护、反馈条件及方法迁移 | 对应具体板卡、固件和实时电机模型；须先完成正常闭环联调 |
| 辅助教学模型 | Boost 等用于执行接口、配置生成与已知失败回归 | 用于流程检查；电机方法结论由电机场景给出 |

软件预演采用的理想角度、控制参数等与实体控制器分别登记。模型内部转矩、真实速度等可用于构造真值或计算参考误差；若实体端无法获得，应另设不使用这些信号的迁移比较。

### 2.2 两项任务的输入与输出

**任务一输入**为需求、控制阶段、可施加输入、参数范围、事件约束和历史执行结果；**输出**为可执行测试、覆盖情况、规格违反条件及相应响应。这里的“失效”是违反已定义的功能或性能需求，故障注入是研究该问题的一种实验手段，二者分别记录。

**任务二输入**为完整多通道波形、工况与事件记录，以及允许使用的模型/机理知识；**输出**包括动态特征、异常区间、故障类别、可疑位置或原因集合、跨工况规律与下一步复验建议。正常但复杂的启动、调速和负载响应必须进入数据集，用于检验误报与误诊。

两项任务通过以下过程衔接：

```mermaid
flowchart LR
    A[需求、工况与故障机制] --> B[组合覆盖与测试搜索]
    B --> C[电机闭环执行与采集]
    C --> D[动态特征、异常检测与故障诊断]
    D --> E[候选原因与区分性复验]
    E --> C
    D --> B
```

任务一侧重在较大范围发现问题；诊断复验侧重区分当前问题的原因。两者复用执行接口，分别设置目标与指标。

## 3. 任务一：智能测试生成与失效边界搜索

### 3.1 将需求转为可执行测试

采用“需求与接口资料→结构化测试规约→约束检查→可执行配置”的流程。规约包含测试意图、初始状态、事件、输入范围、观察信号和判定条件。LLM 结合检索到的接口、操作原语和工程知识提出规约，由固定校验程序检查字段、单位、合法范围及事件可执行性。需求到台架操作的映射参考 AutoHIL。[1]

比较人工模板、直接 LLM 生成、检索与规约约束辅助的 LLM 生成。评价语义正确率、可执行率、有效激励率和人工修订时间。缺少接口或需求值时形成待补字段；合法配置能否实际激活目标工况，由执行结果检查。

### 3.2 组合覆盖与事件次序

使用 PICT 生成速度分区、负载分区、运行阶段、故障机制和注入时机等离散因素的合法成对组合；少因素任务用全枚举对照，高风险交互确有需要时增加局部三因素覆盖。工具和算法只负责已定义的因素空间。[PICT 官方文档](https://github.com/microsoft/pict/blob/main/doc/pict.md)

另设“调速→负载变化”“负载变化→调速”“异常→恢复”等状态转换与短事件序列。参数组合覆盖和事件次序覆盖分别计算。覆盖分母为冻结的合法组合/序列集合，同时报告设计覆盖与实际有效执行覆盖。

### 3.3 LLM 语义反馈搜索与数值搜索

首批搜索两类需求：调速后的速度误差与恢复时间；负载扰动及事件交互下的速度跌落、振荡与恢复。涉及电流或保护的判据在取得对应需求后加入。每项需求计算数值裕度：正值满足，负值违反；不同量纲分别优化，联合目标的归一化在正式比较前固定。

LLM 获取变量的物理含义、需求、历史输入、数值裕度和时间对齐的响应特征，直接提出下一组参数或事件模式。进一步比较由 LLM 提出高风险区域、数值优化器进行局部细化的混合方式。方法参考 LLM-Falsifier 与 GLLMPro；前者已在公开 CPS 基准研究该问题，项目需要重新建立同预算电机对照。[2][3]

| 组别 | 测试选择方式 | 比较目的 |
|---|---|---|
| A0 数值与工程基线 | 随机、Sobol、Dual Annealing 等直接搜索；加入固定工程启发式 | 建立数值探索与已有领域知识的参照 |
| A1 LLM 搜索 | 需求语义、变量含义、历史参数与裕度→下一测试点 | 检验语义对搜索效率的作用 |
| A2 响应反馈搜索 | A1 增加恢复、振荡等特征及最接近违反需求的时刻 | 检验响应信息能否改善测试选择 |
| A3 混合搜索 | LLM 提出区域/事件模式，直接搜索器细化参数 | 检验语义探索与数值优化的互补性 |

首轮用一个提案接口实现 A1—A3，固定同一 LLM 版本和推理设置。先建立 A0/A1，再依次增加反馈与混合，明确每步增益。移除变量语义的消融、工程启发式对照和信息量匹配试验，用于区分语义知识、数值反馈与算法结构的贡献。

单次执行较昂贵且裕度有效时，再加入贝叶斯优化；多时序规格和多个搜索器需要统一组织时再引入 PSY-TaLiRo。初始原型采用轻量执行回调，保留更换优化器的能力。[PSY-TaLiRo](https://github.com/cpslab-asu/psy-taliro)

### 3.4 测试搜索的评价

主指标为预算内失效发现率、首次发现成本、不同失效模式数及最佳需求裕度，辅助报告需求/组合/序列覆盖。按预先定义的“需求、控制阶段、响应形态”归类，结合复验判断不同原因；重复失败与新增模式分别计数。

同时比较相同物理执行次数与相同总时间/费用两种预算。初始化、重复候选、非法候选的修正、LLM 调用和失败运行均计入相应成本；不可执行或数据不足的运行标记为不可评价，与系统规格违反分开。未找到失效的运行保留在成功率和首次发现的截尾统计中。

## 4. 任务二：测试数据分析、故障诊断与复验

### 4.1 提取动态行为和物理关系

先比较固定工程指标与扩展特征，量化完整动态过程中的差异。特征包括反转峰值及持续时间、超调/欠调、恢复时间、误差积分、振荡频率与衰减、电流均方根、不平衡和频带能量。变速过程结合转速或电角频率组织频域特征，必要时采用短时傅里叶变换或小波分析。

以运行阶段、速度和负载相近的正常数据建立条件化参照，计算相对偏差。具备参数与观测条件时加入物理残差，例如机械平衡残差：

`r_m = J·dω/dt − (T_e − T_load − B·ω)`

其中 J 为转动惯量，B 为黏性摩擦系数，ω 为角速度，T_e 和 T_load 分别为电磁转矩和负载转矩。参数误差、导数滤波和未测扰动进入正常残差标定。电气残差需要相应电压、电流、角度和参数；低阶 ARX/NARX 或状态空间辨识在需要预测残差时加入。

通过“信号特征、物理残差、二者融合”的对照，判断哪些信息有助于行为刻画及故障区分。SHAP、相关性和异常通道排名用于筛查；部件定位根据有真值的注入实验和区分性观测评价。

### 4.2 异常检测与专用故障识别

| 分析环节 | 首轮候选 | 选择理由与具体问题 |
|---|---|---|
| 异常检测 | 条件化统计/IForest 与 TimeRCD | 比较局部及多通道异常的发现能力，重点检查正常切换、持续异常和短促异常 [4] |
| 故障分类 | 物理/动态特征分类器、MiniRocket、MantisV2 冻结表示＋线性分类头 | 分别代表工程特征、时序形状和预训练表示，比较同标签预算下的识别与跨工况能力 [5][6] |
| 原因/位置排序 | 标准化偏差与条件化正常参照＋残差签名 | 判断相似表现能否映射到不同信号链或部件 |

先分别选出异常检测和故障分类的强基线，再与 LLM 路线比较，避免每个检测器、分类器和提示策略全部交叉组合。MantisV2 的冻结编码器仍需本任务分类标签。MOMENT、TS2Vec 在首轮显示表示不足后再评估；AERCA 在传播源定位有明确需求、观测条件和闭环假设适用时评估。

### 4.3 融合信号、工况与机理的 LLM 诊断

**首选将有物理含义的波形信息与工况知识共同提供给 LLM，由它直接判断故障类别、比较候选原因并选择需要补充的分析。** 输入包括事件前后特征、正常参照差异、可测控制状态、残差、通道关系，以及允许使用的故障机制知识。方法参考 S2S-FDD 的信号语义组织和 TraceBench 的工具辅助原因归属。[7][8]

例如，同样出现速度下降，诊断器需结合电流是否出现不对称、负载事件是否先发生、测量值与独立观测是否一致，以及控制器的补偿响应进行区分。对应信号是否可测、候选原因是否可辨识，在数据准备阶段明确。

| 组别 | 输入与决策方法 | 要分离的贡献 |
|---|---|---|
| B0 专用方法 | §4.2 选出的分类/定位强基线 | 判断是否已有低成本有效方法 |
| B1 LLM 特征诊断 | 与基线相同的数值特征、工况信息，由 LLM 作判断 | LLM 对相同信息的利用能力 |
| B2 知识增强诊断 | B1 加正常参照、控制关系与故障机制知识 | 额外知识的作用；同时增加规则或案例检索对照 |
| B3 工具辅助诊断 | B2 按需调用特征、频谱、相似案例与已有通道查询 | 自适应信息获取的作用；对照固定提供同等信息 |

比较既包括“相同信息下谁判断得更好”，也包括“加入何种知识后是否值得额外成本”。融合专用模型预测时，额外与简单规则融合/选择器比较。工业诊断研究已提示，混合方案优于裸 LLM 并不保证超过专用模型，因此 B0 是采用决策的主要参照。[9]

首轮通过语义明确的特征、检索结果和工具返回值连接时序算法与 LLM。若后续使用编码器隐向量，需要专门的对齐方法；模型自报置信度在独立数据校准后才能作为阈值或停止依据。

### 4.4 直接时序理解与分析方法生成

保留两个有明确价值的小规模扩展方向，由首轮错误分析选择其中一个先试：

- **异常难以被候选检测器描述时**，借鉴 LLM-TSAD 的统计分解与位置提示，或 VLM4TS 的候选区间＋全局波形图，比较输入表示能否帮助判断复杂异常；必须保留筛选器单独使用的结果。[10][11]
- **固定特征遗漏了可重复的动态关系时**，借鉴 Argos，让 LLM 在训练/开发数据反馈下生成、修订特征或检测规则，与人工特征、规则库及受限自动搜索比较。测试前冻结程序，在线执行成本与生成成本分别报告。[12]

时序—语言对齐、LoRA 微调和蒸馏属于后续训练路线，进入条件是已有足够波形—故障语义配对数据，且首轮结果指向明确表示瓶颈。ATTLLM 等提供可借鉴方法，但不同工业过程的数据条件需重新适配。[14]

### 4.5 跨工况规律与诊断驱动复验

按速度、负载、控制阶段和故障强度形成特征响应与误诊分布，识别哪些工况更易振荡、漏检或混淆。使用未见工况检查规律，区分完全未使用目标域数据的泛化与使用目标域未标注数据的适应。

当现有观测支持多个原因时，建立有限复验动作集，如改变速度/负载、调整事件间隔、增加指定观测或重复运行。根据各候选原因对动作的预期响应，比较固定顺序、随机、数值分歧/预期信息增益、LLM 提案及混合选择。LLM 负责提出或排序能够区分原因的动作，模拟/测量返回实际响应以更新判断。

读取已有数据与新增物理试验分别计费。所有方法共享可执行动作、初始信息和候选模型，环境只返回可测数据与运行状态；隐藏故障真值由评价器持有。CoffeeBench 提供动作—观测诊断的研究参考，其“告知猜测正误”等基准条件需要与实际 HIL 区分。[13]

评价固定预算内正确定位率、包含失败/未决情况的复验成本与诊断延迟。不可辨识的原因保留为集合，未知机制保留拒识出口。主动复验作为两项任务的后续连接实验，不影响独立测试搜索和数据分析结果的成立。

## 5. 数据、输入尺度与效果评价

### 5.1 按物理过程设计采集与模型输入

先确定目标事件持续时间、所需带宽及前后上下文，再确定采样率、窗口与模型长度。当前 PMSM 软件预演配置为 100 kSa/s、0.8 s；在这一采样率下，5000 点仅覆盖 50 ms。该配置是采集起点，正式数据集按目标过程调整。

| 分析目标 | 时间与带宽依据 | 输入处理 |
|---|---|---|
| 电流瞬态、相间关系与频谱 | 最短目标事件、需要保留的频带及频率分辨率 | 保留高频原始采样；可在原始数据上计算特征后供 LLM 使用 |
| 速度跌落、反转、振荡与恢复 | 事件前基线至完整恢复 | 抗混叠后按需降采样；检查峰值、恢复时间及滤波延迟 |
| 启动、模式切换与持续异常 | 完整控制阶段和跨窗口连续性 | 长记录或连续滑窗；固定步长与事件合并规则 |

记录原始采样率与派生输入采样率，用 `输入点数 ≈ 窗口秒数 × 输入采样率` 核对。定长插值、幅值归一化和波形绘图都检查是否损失短瞬态或偏置/增益信息。状态日志先做事件级关联，时间精度满足要求后再进行逐点融合。

### 5.2 数据集与真值

正常数据覆盖启动、调速、负载变化与稳态；故障数据覆盖可实现的反馈偏置/增益、执行通道异常及不同强度。各机制登记注入位置、指令时刻、实际生效时刻和症状起点。物理闭环中的反馈修改、导出数据修改和实体故障分别标注。

按完整运行、配置族和工况分组，再进行切窗，防止相邻或重叠窗口跨训练/测试。正常参照、知识库、阈值、提示示例、自动生成程序均只由训练/开发部分确定；测试故障标签、注入位置和未来数据保留给评价器。

设置同分布、未见速度/负载/事件组合、未知故障机制，以及后续实体域四类测试。少标签按独立标注运行数比较；切出更多窗口不视为新增独立样本。所有方法在各自允许的信息范围内共享数据划分与可用观测。

### 5.3 独立能力与完整流程分别评价

| 评价层次 | 输入条件 | 主要指标 |
|---|---|---|
| 行为特征 | 有参考值或受控变化的运行 | 特征误差、重复性、对动态变化的分辨能力 |
| 异常检测 | 完整正常/异常记录 | 正常运行单位时间误报、事件召回、检测延迟、区间质量 |
| 独立分类/定位 | 给定真实事件区间 | 宏平均 F1、混淆矩阵、部件级 Top-1/Top-k、误定位 |
| 完整诊断流程 | 完整波形，自动检测、截窗与诊断 | 规定时限内发现且正确识别率、误报、拒识、误定位与总延迟 |
| 主动复验 | 相同初始信息与动作预算 | 正确定位率、复验次数/成本、未决比例 |

**已知故障的端到端发现且正确识别率 = 规定时限内被检出并正确识别的已知故障事件数 ÷ 全部真实已知故障事件数。** 漏检、错分类和超时保留在分母中。未知故障单列“检出且正确拒识率”，同时统计已知故障被错误拒识的比例；正确拒识与根因确定分别评价。

事件匹配、允许延迟、滑窗合并和阈值在测试前冻结。主结果使用开发集确定的工作点，报告实际误报；测试集最佳阈值和点调整 F1 仅作附加参考。正常瞬态、短异常、持续异常和最差工况分别列结果。

### 5.4 预算与重复试验

训练标签、可用知识、工具调用、调参机会和计算资源分别记录。LLM 搜索/诊断先固定一个模型版本、推理设置与提示版本，在关键结论上增加第二个模型检验方法的可迁移性。模型选择关注结构化输出、工具使用、输入长度及成本；视觉路线另检查图像能力。

预试测量运行方差、执行成本与故障发生比例，再预注册正式重复次数、预算档位和实际有意义的提升门槛。对相同需求和测试组作配对比较，按独立运行或配置族计算不确定区间，同时报告平均表现、关键故障漏诊和最差工况。仿真确定性重复用于测量模型或搜索随机性，配置多样性通过独立工况提供。

## 6. 方法采用条件与后续候选

| 方法 | 进入条件 | 采用依据 | 后续处理 |
|---|---|---|---|
| LLM/混合失效搜索 | 需求、合法动作和数值裕度齐备 | 相同执行预算或总成本下提高失效发现，增益跨需求成立 | 无稳定增益则保留数值搜索；检查语义信息不足或搜索空间设置 |
| TimeRCD | 可用权重、物理窗口与正常校准数据 | 在可接受误报下改善事件召回/定位，关键工况退化可控 | 条件化统计作为回退；表示不足再考虑 MOMENT/TS2Vec |
| MiniRocket/MantisV2 | 分组标签与输入转换方案齐备 | 识别、少标签或跨工况收益值得训练/推理成本 | 物理特征分类器保持参照；有明确瓶颈后再考虑适配训练 |
| LLM 知识与工具诊断 | 机理知识、语义特征及可调用分析齐备 | 超过强专用方法或以相当效果明显减少标签/分析成本 | 仅解释更丰富时保留辅助用途；融合收益单独核验 |
| 物理残差/低阶辨识 | 观测、参数与正常误差可核对 | 改善相似故障区分或动态规律提取 | 模型失配较大时补充观测或采用条件化数据参照 |
| LLM 直接时序/VLM、规则生成 | 已识别具体分析不足 | 在冻结测试上改善检测/特征能力，收益超过额外调用和开发成本 | 先选一个试点，结果决定是否扩大 |
| 主动复验 | 候选原因和动作具有可区分响应 | 相同预算提高正确定位或减少必要实验 | 无收益时保留固定或数值分歧策略 |
| 对齐微调/蒸馏、AERCA 等 | 对应数据与方法假设成立，已有明确不足 | 解决已定位的表示或传播源问题 | 按单一问题增补，不预先并行铺开 |

方法先进性通过实际提取的信息和效果体现。报告同时给出性能、标签需求、预处理/训练/推理成本及维护工作量，选取能满足目标且代价合适的组合。

## 7. 实施顺序与阶段交付

| 阶段 | 主要工作 | 交付及进入下一阶段的条件 |
|---|---|---|
| 1. 建立电机任务与数据基准 | 确认两类测试需求、相似表象故障、可测信号、注入点和动作；复验软件闭环 | 需求/故障字典、合法范围、采集方案、分组数据与固定指标；场景具有真实区分度 |
| 2. 建立强基线与分析输入 | 完成组合覆盖、数值搜索、动态特征、条件化检测与专用分类/定位比较 | 可运行基线、错误样本、成本测量与数据划分；据预试冻结正式预算 |
| 3. 比较两条核心 LLM 路线 | 执行 A1—A3 和 B1—B3 的递进对照，评价完整诊断流程 | 搜索与诊断的增益、消融、适用工况和失败边界；据结果确定保留方法 |
| 4. 验证诊断复验与针对性扩展 | 比较复验动作选择；针对明确不足选择直接时序/VLM 或规则生成试点 | 复验效率结果及单项能力改进，形成选型结论 |
| 5. 实体控制板迁移 | 正常闭环及采集条件验收后，按实体可用观测重新校准与比较 | 软件域和实体域独立结果、迁移成本与适用范围 |

任务一与任务二可在共享基准建立后分别推进。实体条件尚未齐备时，软件闭环中的方法比较与主动复验可先完成；实体结果单列。

工程上复用 Typhoon 执行、采集和结果记录入口，新增四类轻量接口：测试提案与合法性检查、响应特征与需求裕度、诊断/分析工具、复验动作与反馈。底层实时控制由控制器和仿真器承担，模型在测试间选择与分析。第三方算法使用独立环境，经文件或结构化接口交换数据。

实施准备表至少登记：目标能力、现有实现、需补采信号/故障机制、校验方法与可运行状态。研究环境用于检索和离线分析；Typhoon 执行采用其配套环境。最终交付包含基准数据、可运行方法、性能与成本对照、失败案例和推荐组合，使选型结果可用于后续测试任务。

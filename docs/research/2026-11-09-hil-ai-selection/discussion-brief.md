# 面向电机 HIL 的智能测试生成与数据分析

方法依据和评价设计见[完整技术选型方案](technical-selection.md)。 LLM 方法的来源与适用边界见[专题调研](../2026-11-09-llm-core-methods/research-report.md)。

## 1. 研究目标与典型问题

研究目标：**在有限测试预算内扩大有效测试覆盖，发现人工设计容易遗漏的系统失效；从测试数据中提取更多有用信息，刻画动态行为、发现异常、识别故障、定位原因并总结跨工况规律。** 重点比较语言大模型（LLM）如何与数值搜索、时序分析和物理方法结合，形成有实验依据的技术选型。

以永磁同步电机（PMSM）为验证对象，先在 Typhoon 电机软件闭环中比较方法，再迁移到 TLE9877 真实控制板与实时电机模型组成的硬件在环（HIL）闭环。软件域与实体域分别评价。

| 任务 | 典型困难 | 希望获得的增量 |
|---|---|---|
| 测试生成与失效发现 | 调速、加负载分别通过，但特定幅值、间隔或先后次序可能导致恢复过慢、振荡或违反限制 | 同样预算覆盖更多有效交互，更快找到失效边界与不同失效模式 |
| 数据分析与故障诊断 | 稳态指标通过仍可能存在反转、振荡和恢复退化；相似速度下降可能来自正常负载变化、反馈偏置或执行异常 | 提取动态和跨通道信息，区分相似表现的不同原因，并识别行为与诊断效果随工况变化的规律 |

这些例子可用于初步验证，后续按需求类型、运行阶段和故障机制扩展。两项任务通过“测试→波形分析→候选原因→区分性复验”连接；动态行为与跨工况规律也作为独立分析结果，用于补充测试范围。

## 2. 技术路线与实现

### 2.1 测试生成与失效搜索

任务一面对大量可能的工况，需要在有限预算内更充分地探索系统行为，发现人工测试容易遗漏的失效。为此，先根据需求、模型接口和允许操作确定可执行的参数与事件；已有配置可以直接复用，需要时也可利用 LLM 将需求转为测试步骤。

在此基础上，比较不同方法如何选择值得执行的测试。比较方法包括人工设计（固定工程启发式）、采样（随机、Sobol）和数值优化（如 Dual Annealing）；LLM 则结合需求含义、历史结果和响应特征提出下一测试条件，并根据执行反馈调整。混合方式由 LLM 提出高风险区域或事件模式，再交给数值优化器细化参数。

离散工况组合较多时，可用组合测试工具（如 PICT）组织合法组合，减少遗漏；事件次序和连续参数边界分别设计与搜索。测试生成、覆盖组织与反馈搜索根据当前问题组合使用。

**重点检验：LLM 利用需求语义、物理关系与历史响应，能否发现其他方法容易遗漏的失效，或以更少测试找到失效边界。** 具体按“目标与约束→模型提案→工具执行→结果反馈→下一测试”的循环实施：

1. **给出测试问题。** 向模型提供需求、允许参数、可执行事件、已有测试和响应。例如，在合法调速与负载范围内寻找恢复超时的组合。
2. **提出下一测试。** 模型选择事件次序、参数和间隔，说明选择依据。需求尚未转成配置时，也可结合接口资料生成测试步骤。
3. **执行并计算结果。** 测试工具检查配置，调用 Typhoon 运行和采集，再计算误差、恢复时间、振荡等信息。允许恢复时间减去实际时间得到满足裕度，负值表示超限。
4. **根据反馈继续搜索。** 模型可以细化接近边界的参数、改变事件顺序或转向另一类组合；也可提出区域，交给数值优化器细化，直至达到预算。

首批可用实验脚本传递结构化提案和结果，复用已有执行入口。模型参与测试间的选择，实时控制与信号采集由控制器和仿真器承担。

反馈搜索参考 LLM-Falsifier、GLLMPro，需求到可执行步骤参考 AutoHIL。方法依据和适用限定见完整方案与专题调研。

### 2.2 动态分析与故障诊断

任务二关注固定指标可能遗漏的动态行为，以及相似异常为何对应不同原因。例如，速度恢复变慢时，需要结合电流、控制状态与事件关系判断其原因；跨多次测试，还需要分析这种变化是否与特定工况有关。

**重点检验：LLM 结合多通道观测、机理知识和工具调用，能否利用固定分析方法未充分利用的信息，改善相似表象诊断，并提出可验证的新特征或规律。** 其分析过程为“数据与工况→候选解释→分析调用→证据更新”：

1. **输入现有观测。** 提供事件前后的波形信息、工况、控制状态和允许使用的机理知识。长波形可先组织为有物理含义的特征、正常参照差异及可查询通道；直接输入序列或波形图作为另一种表示路线比较。
2. **形成候选解释。** 模型判断哪些变化值得关注，提出可能原因及区分它们所需的证据。例如，速度恢复变慢时，检查负载事件、电流响应与反馈一致性。
3. **调用分析工具。** 模型选择所需通道、时间区间与计算，程序返回频谱、跨通道关系或物理关系偏差等结果，再由模型更新判断。工具结果保留对应数据和计算记录。
4. **形成诊断或待验证发现。** 输出异常、候选原因和证据；观测不足时保留原因集合，并提出补充分析或复验。跨多次运行出现的关系，继续用独立数据检查。

这里包含两类研究能力。**诊断**关注已有证据下判断是否更准确；**分析发现**关注能否提出人工指标遗漏的特征、跨通道关系或工况规律。例如，模型提出某种振荡与事件间隔有关，可生成相应特征计算程序，在开发数据中修订，再冻结程序、用独立运行检验。

为了判断这些能力的价值，按分析环节选择下列方法开展比较。它们既可独立产生结果，也可提供特征、残差或模型预测，与 LLM 形成组合；分别检查独立效果与组合增益。

| 分析环节 | 候选方法 | 作用与比较重点 |
|---|---|---|
| 行为分析 | 时域/时频特征、按工况建立的正常参照、物理残差 | 提取反转、振荡、恢复及信号关系变化，分析其随工况变化的规律 |
| 异常检测 | 按工况建立的统计检测、IForest、TimeRCD | 比较异常检出能力，重点检查短促与持续异常、正常切换误报 |
| 故障识别 | 物理特征分类器、MiniRocket、MantisV2 冻结表示＋分类器 | 比较工程特征、时序形状与预训练表示的识别及跨工况能力；分类器使用本任务标签训练 |
| 原因分析 | 正常参照偏差与残差响应模式、LLM 知识与工具辅助诊断 | 比较相似表象的原因区分；检验结合工况、机理和按需分析是否改善判断 |

具体比较范围根据当前问题和数据条件选择。相同信息下的判断能力、增加机理知识的作用与按需调用工具的作用分别核验。

信号与机理组织参考 S2S-FDD，工具辅助原因分析参考 TraceBench，特征与检测规则生成参考 Argos。直接序列或图像理解、时序与语言表示对齐、领域微调和蒸馏也是调研中的候选路线，按问题和数据条件选择。LLM 可以在线分析，也可在离线阶段生成可部署的分析程序或参与训练专用模型。

### 2.3 本地模型部署与适配

本地模型的选型与适配服务于前述两项任务。初期用现有可用模型开展少量任务验证，检查测试提案、工具使用与证据判断，测量推理延迟、显存或内存占用及完整任务成本。核心方法比较与本地可行性测试可交替推进；后续部署能力以本地实测确认，远程较强模型如参与比较，单列结果。

先用任务提示、知识检索和工具组织输入，验证原有权重能达到的效果。依据任务需求、能力误差和资源测量，再选择相应适配试点：

- **领域能力适配**：用可核对的测试提案、工具调用和诊断样本开展监督微调（可采用 LoRA）；需要直接利用时序表示时，另评估时序与语言模型的对齐及其配对数据需求。
- **部署成本优化**：按资源目标比较量化或知识蒸馏，并复测任务效果。离线生成并验证的规则可作为分析程序运行，其生成成本与在线成本分别评价。

每次试点围绕一个明确问题选择技术，依据效果和资源收益决定是否扩大。具体训练与部署设计见完整方案 §5.5。

## 3. 评价与选型依据

- **测试搜索**：同执行次数及同总成本分别比较失效发现率、首次发现成本和不同失效模式数，计入初始化、无效提案与模型调用。
- **数据分析**：检查行为特征与跨工况规律的重复性和适用范围；诊断既比较给定故障窗口的分类/定位，也从完整波形开始评价。端到端检出并正确识别率为“规定时限内检出并正确识别的已知故障事件数／全部真实已知故障事件数”，漏检、错分类和超时均保留在分母；另报误报、未知故障拒识、定位和延迟。
- **方法采用**：以独立数据和相关强基线检验信息或性能增益，或相当效果下标签、人工与实验成本的降低，并检查关键故障和最差工况。

## 4. 实施路径与预期成果

复用已有执行与采集能力，先选定问题、核对输入和判据，尽早开展合理基线与核心候选的比较；根据结果完善对照、补充数据或调整方法。实验组合由当前研究问题确定，任务一与任务二具备各自输入条件后可分别推进。初期用轻量函数或文件交换，重复使用后再整理公共接口。本地模型先开展少量任务验证，按效果与资源实测选择后续适配和部署工作。

形成候选原因和可区分动作后，再比较主动复验策略：依据不同原因的预测响应差异，或由 LLM 选择复验，与固定、随机等方法比较。实体正常闭环和采集条件齐备后，按目标 HIL 环境可用观测验证迁移效果。

预期形成失效搜索与数据分析的推荐方法、动态行为和跨工况规律，以及适用范围和成本边界。充分比较后得到的无稳定增益结论同样属于选型成果。近期重点是确定可执行的首批问题及预期增益，取得能指导下一步选择的实验结果。

主要方法依据：[LLM-Falsifier](https://arxiv.org/html/2609.20752v1) 支持语义反馈搜索；[S2S-FDD](https://arxiv.org/html/2603.08048v1) 支持信号与知识结合的诊断；[Argos](https://arxiv.org/html/2501.14170v1) 支持生成分析规则。这些研究提供候选方法，电机 HIL 收益由上述实验验证。

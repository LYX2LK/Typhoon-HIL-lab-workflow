# 面向电机 HIL 的智能测试生成与数据分析

**研究两件事：在有限测试预算内发现更多系统失效；从测试波形中提取更多信息，更准确地识别异常、区分故障并定位原因。** 重点比较大模型如何与数值搜索、时序分析和物理方法结合，形成有实验依据的技术选型。

以永磁同步电机（PMSM）为验证对象，先在 Typhoon 电机软件闭环中比较方法，再迁移到 TLE9877 真实控制板与实时电机模型组成的硬件在环（HIL）闭环。软件域与实体域分别评价。

## 1. 要解决的具体问题

| 任务 | 典型困难 | 希望获得的增量 |
|---|---|---|
| 测试生成与失效发现 | 调速、加负载分别通过，但特定幅值、间隔或先后次序可能导致恢复过慢、振荡或违反限制 | 同样预算覆盖更多有效交互，更快找到失效边界与不同失效模式 |
| 数据分析与故障诊断 | 稳态指标通过仍可能存在反转、振荡和恢复退化；相似速度下降可能来自正常负载变化、反馈偏置或执行异常 | 提取动态和跨通道信息，发现隐蔽异常，并区分相似表现的不同原因 |

两项任务通过“测试→波形分析→候选原因→区分性复验”连接。测试搜索负责扩大问题发现范围，诊断复验负责缩小当前问题的原因范围。

## 2. 优先采用什么方法

**任务一：组合覆盖建立起点，重点比较 LLM 语义反馈搜索与数值搜索。**

将需求、接口和允许操作整理为结构化测试规约，用 PICT 覆盖离散因素组合，另设事件次序测试。连续参数以随机/Sobol、直接搜索和工程启发式为基线；让 LLM 利用需求含义、历史参数、数值裕度和响应特征提出下一测试点，再比较“LLM 选高风险区域＋数值优化器局部细化”。

例如，让方法寻找“哪种调速幅值与负载施加时机，更容易使恢复时间超过要求”。大模型直接参与测试选择，核心问题是语义与响应信息能否减少发现失效所需的实验。

**任务二：以动态特征和物理关系为基础，重点比较专用模型与 LLM 知识、工具辅助诊断。**

| 分析环节 | 优先方法与作用 |
|---|---|
| 行为分析 | 时域/时频特征、条件化正常参照和物理残差，提取反转、振荡、恢复及信号关系变化 |
| 异常检测 | 条件化统计/IForest 与 TimeRCD，比较复杂异常召回及正常瞬态误报 |
| 故障识别 | 物理特征分类器、MiniRocket、MantisV2，建立工程特征、形状与预训练表示的强基线 |
| 原因分析 | LLM 综合同一组信号特征、工况、控制关系和故障知识，按需调用频谱、残差与相似案例分析 |

先选出各环节强基线，再增加 LLM 的知识与工具，分离每项增益。直接读时序/波形图与自动生成检测规则，按首轮暴露的问题选择一个小试点；多模态对齐和微调在数据与瓶颈明确后加入。

## 3. 如何证明方法有价值

首批采用两组实验：**调速与负载/事件交互的失效搜索**，以及**正常负载变化、反馈异常和执行异常的相似表象诊断**。电流瞬态与速度恢复分别按物理时间尺度设计输入；数据按完整运行和工况划分，并留出未见工况与未知故障。

- **测试搜索**：同执行次数及同总成本分别比较失效发现率、首次发现成本和不同失效模式数，计入初始化、无效提案与模型调用。
- **数据分析**：既比较给定故障窗口的分类/定位，也从完整波形开始评价。核心指标为“规定时限内发现且正确识别的已知故障数／全部真实已知故障数”，漏检计入分母；另报误报、未知故障拒识、定位和延迟。
- **方法采用**：看是否超过强基线，或以相当效果减少标签与实验成本，并检查关键故障和最差工况。

## 4. 后续如何推进

先建立需求、故障机制和电机数据基准；随后完成数值/时序/物理基线，比较两条核心 LLM 路线；再研究主动复验：当多个原因都能解释波形时，选择哪次负载变化、调速或新增观测最有助于区分，并与固定、随机及数值分歧选点比较。实体正常闭环具备条件后，验证迁移效果。

预期形成三类结果：**更高效的失效搜索方法、更有区分力的数据分析与诊断方法，以及各方法的适用工况和成本边界。** 近期讨论重点是确定最有代表性的失效需求、最难区分的故障，以及能够获得的观测和复验动作。

主要方法依据：[LLM-Falsifier](https://arxiv.org/html/2609.20752v1) 支持语义反馈搜索；[S2S-FDD](https://arxiv.org/html/2603.08048v1) 支持信号与知识结合的诊断；[Argos](https://arxiv.org/html/2501.14170v1) 支持生成分析规则。这些研究提供候选方法，电机 HIL 收益由上述实验验证。

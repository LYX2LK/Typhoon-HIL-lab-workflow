# 两个技术任务的验证卡

> 本页为 2026-11-06 历史任务卡。当前采用 [2026-11-08 修订任务卡](../2026-11-08-hil-ai-selection/research-question-card.md) 及其比较协议。

用途：把 [技术选型方案](technical-selection.md) 转为可冻结的比较任务。类型均为应用验证，以下预期需要实验支持。

## 任务卡 A：提高测试设计效率、工况覆盖和边界发现能力

| 项目 | 内容 |
|---|---|
| 问题 | 相同需求、合法输入空间和预算下，结构化生成＋覆盖生成＋反例搜索能否比人工模板/随机扫描产生更多有效测试证据？ |
| 工作预期 | 检索与规约降低人工修订；约束组合补齐交互；搜索在部分需求上更快找到边界反例 |
| 当前证据 | FaultGene、组合测试与 BO 相关方法；项目现有配置校验和事件记录。对应证据表 R01–R08、P01–P02 |
| 缺失证据 | 本项目的语义正确率、执行激活率、覆盖差额、搜索收益及墙钟成本；当前版本基准复验 |
| 支持采用的结果 | 硬约束全部满足，声明覆盖可复算；多需求/多种子比较显示稳定收益且成本可接受 |
| 改变选择的结果 | 人工模板/简单扫描效果相当，生成修订成本过高，BO 增加总耗时或增益只来自重复已知失败 |
| 最小下一步 | 固定一个 Boost 单事件任务，复验基准并测耗时；冻结两维范围，再进行 3 方法×3 种子×30 次预算的小试 |
| 当前决定 | 进入原型比较；算法采用待结果决定 |

## 任务卡 B：提高异常发现能力与分析结论可复核性

| 项目 | 内容 |
|---|---|
| 问题 | 同一数据划分和误报预算下，TimeRCD 或 MOMENT 特征能否提高本项目异常事件召回，并支持准确的证据报告？ |
| 工作预期 | 特定异常可受益于上下文或预训练表示；固定指标与证据校验降低数值、引用错误 |
| 当前证据 | TSB-AD、ICLR 2026 的局限研究、MOMENT/TimeRCD 实现；项目数据接收与报告复核。对应 R10–R13、P02 |
| 缺失证据 | 独立正常/异常运行、确认的异常窗口、工况与设备分组；本机模型成本和迁移性能 |
| 支持采用的结果 | 固定误报预算下召回/延迟有稳定增益；关键回归通过；报告可核对字段全部一致 |
| 改变选择的结果 | 简单基线更好，长故障/模式变化漏报，未来上下文造成延迟不可接受，或者报告出现无依据机理解释 |
| 最小下一步 | 整理来源与时钟，按完整运行划分拟合/校准/测试；运行统计、物理特征、MOMENT 特征、TimeRCD 四组比较 |
| 当前决定 | 优先离线异常检测与证据解释；有同步干预数据后再评价根因定位 |

比较协议、阈值和采用规则先固定，试运行可以暴露基准设计问题；正式测试集保持独立。结果支持到哪个层次，就在该层次交付：接口可运行、异常检测有效、性能判定正确和根因定位有效分别验证。

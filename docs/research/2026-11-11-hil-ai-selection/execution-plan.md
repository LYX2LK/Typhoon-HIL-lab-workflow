# 搜索与诊断研发执行安排

本文面向研发与工程协作人员，将技术选型方案落实为可交付工作。两条研究线分别按依赖推进，样机接入与共用支撑同期开展。

## 首批目标

1. 搜索：一个模型自主提出连续参数和事件安排，程序执行后返回真实评分与响应，再由模型决策；保留全部调用与执行记录。
2. 诊断：建立现有运行索引和按工况使用的参照，核对控制模型实际反馈路径，实现首个可重复、可观测的故障及正常对照。
3. 样机：复用现有 I/O 合同，逐条收敛接口、模型、固件及停止恢复条件。

模型接入仅复用既有服务连接配置与凭据，研究流程独立实现。LLM 的测试选择、响应预测和反馈更新依据实际任务设计；原演示 Agent 的固定工作流、动作目录和展示模板不作为本研究方法。

## 验收口径

知识增强实验先复用减速加载与同症速度跌落两组任务。测试和控制人员核对规约、单位和适用版本，模型人员核对实际事件与可用测点，研究侧形成带出处的条款表、机理关系与可执行边界检查。独立复核人员封存留出问题、可接受条款和预期动作。三类输入为仅给任务说明、自动取回条款、直接给定正确条款；各组共用校验器。交付逐题检索与首次动作、工具拦截或修订、最终评分和人工工时，按错误所在环节决定扩展检索、补测点或调整模型。[完整比较设计](technical-selection.md#42-数据划分与公平比较)

- 搜索沿用同一恢复评分；找到需求违反样本后，进一步取得邻近满足/违反点和复验才讨论局部边界。
- 首批少量连续运行验证流程与反馈使用，保留与简单基线的开发性对照；正式方法收益依赖后续独立重复。
- 正常参照按模型、参数、工况与运行阶段组织；确定性复跑用于复现核对。数据划分以完整运行或配置族为单位。
- 故障注入在模型内实际反馈/执行路径生效，保留原始波形；正常数据可先联调工具。
- 检测、诊断分别评价，并另报完整流程的漏检、误诊、时延和成本。
- 从首次模型调用记录输入/输出用量、时间、返回模型、结束原因与错误。缺失用量或价格字段保持未取得。
- Virtual HIL 编译、加载和运行使用现有互斥；离线开发、分析与资料确认可同期进行。

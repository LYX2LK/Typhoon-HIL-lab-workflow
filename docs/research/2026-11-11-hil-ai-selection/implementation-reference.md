## A. 评分、数据与实验口径

### A.1 当前基础与观测范围

对照当前 [PMSM 适配器](../../../src/typhoon_lab/pmsm_preview.py)和[预演配置](../../../configs/pmsm_software_preview.json)，可复用模型准备、速度/负载事件、七通道采集及结果记录。当前配置采样率为 100 kSa/s、时长 0.8 s；适配器允许每次最多三个速度/负载事件，具体范围和时间网格由其能力声明约束。这些是现有软件实现条件，正式研究场景可经验证后扩展。

新增工作包括：测试提案与历史反馈接口、搜索目标计算器、正常参照与特征工具、电机控制闭环中的故障注入及必要观测、知识检索、LLM 诊断和模型调用接口。当前七通道中尚无 dq 电流、限幅/保护状态和独立速度反馈通道；按诊断问题补充。实体接口仍需依据 [HIL 接口工作表](../../../configs/tle9877_hil_contract.json)完成确认。

已有 [PMSM 幅值与时序实验（本地记录）](../../../results/agent-tasks/20261111-100724-pmsm-boundary-2e9e/analysis/analysis-report.md)完成 23 次完整运行，所测点均未违反 100 ms 恢复要求，最小恢复时间余量为 62.55 ms。该结果为预试提供基础；正式搜索问题与评分口径见本附录 A.2。该记录位于被 Git 忽略的 `results/`，共享仓库读者需另获证据材料；对外据此评审前，整理含配置、指标、运行标识及生成方法的可共享摘要，并保留原始记录的追溯入口。

### A.2 恢复评分与搜索停止

首批恢复评分沿用现有[分析实现](../../../scripts/analyze_pmsm_interaction.py)：从末实际事件起，寻找最后一次越出 ±50 rpm 误差带后重新入带、并保持至统一记录终点的时刻，要求至少 20 ms 尾部证据；始终在带内时恢复时间为零。恢复时间余量沿用记号 `ρ_rec = T_limit − T_recover`，单位为 s；首批 `T_limit = 0.10 s`，余量非负为满足、负值为违反。搜索最小化该评分，报告本轮有效测试中的最小余量及对应工况。

正式比较固定事件起点的确定方式、误差带、恢复定义、记录终点、最小尾部证据和截尾处理。评分配置可用 `score_profile_id` 标识，关联现有分析方法版本与代码摘要。固定保持时长的定义可作为另一评分版本比较；各对照方法使用同一版本。历史评分保留，采用新定义时从原始数据生成新的派生分析。

记录结束时尚无法确定完整恢复时间，称为截尾；保留已观察时长及可支持的恢复时间下界、余量上界。仅在观测支持超过期限时判违反，其余为不可评价。优化器使用预先固定的截尾处理规则，不可评价时保留无分数状态，按剩余预算决定补充观测或结束。其他需求分别定义速度跌落、振荡或电流限制的评分，并说明单位、差值方向及零值判定；多指标联合搜索的归一化与组合方式在开发阶段固定。恢复时间余量按上述工程定义计算；采用信号时序逻辑（STL）表达要求时，接入相应监测器，按公式的定量语义计算 STL 鲁棒度。

| 搜索目的 | 停止条件 | 输出 |
|---|---|---|
| 首个反例 | 有效需求违反，或执行/提案/时间预算到达 | 反例或本轮未发现、本轮最小余量及成本 |
| 失效模式发现 | 固定总预算到达 | 按需求、阶段和响应形态去重的模式及代表样本 |
| 局部边界刻画 | 已有相邻满足/违反点，达到指定分辨率或复验预算 | 参数切片的边界区间、重复性及未覆盖区域 |

### A.3 波形、特征与物理关系

原始波形先进入固定分析程序，形成有单位、时间范围和物理含义的特征。首批 LLM 读取这些信息与知识条目，按需调用分析工具。直接数值序列或波形图作为后续表示路线比较。

| 数据层 | 当前字段或拟补字段 | 单位/来源 | 用途与获取条件 |
|---|---|---|---|
| 时间 | `t_relative_s`、`t_simulation_s` | s，采集记录 | 定位波形窗口及实际事件；外部日志需时钟或触发依据 |
| 速度 | `MechanicalSpeed_rad_s`、`Reference_rad_s` | rad/s，模型速度及给定探针 | 误差、反转、跌落与恢复；显示 rpm 时乘以 30/π |
| 电流 | `Ia_A`、`Ib_A`、`Ic_A` | A，三相采集 | RMS、不平衡、频带能量和瞬态关系 |
| 转矩与负载 | `ElectromagneticTorque_Nm`、`Load_Nm` | N·m，模型探针 | 机械关系与扰动响应；迁移时声明是否可读 |
| 事件和配置 | 指令与实际生效时刻、模型/控制参数、运行阶段 | 执行记录及事件探针 | 同工况参照、先后关系与版本核对 |
| 拟补观测 | dq 电流、控制限幅/保护状态、独立速度/反馈路径 | 按模型、固件和接口确认 | 进一步区分反馈、执行和正常负载效应 |

当前七个物理通道依据 A.1 的适配器。模型内部真值、仿真器可读状态和目标板卡可读信号分别登记；主比较使用预先声明的观测集，受限观测迁移另做实验。

| 提供给 LLM 的信息 | 生成方法 | 保留的引用 |
|---|---|---|
| 动态特征 | 峰值、误差积分、恢复时间、振荡频率/衰减、电流特征 | 运行 ID、通道、窗口、单位、计算版本 |
| 相对同工况正常参照的偏差 | 按速度、负载、运行阶段匹配正常运行，计算偏差和正常波动范围 | 正常参照版本、工况匹配质量 |
| 物理残差 | 在所需参数和观测具备时计算关系偏差 | 关系式、参数来源、正常误差标定 |
| 事件与状态 | 将已确认时钟关联的操作和状态变化加入上下文 | 时间依据、实际生效时刻 |
| 知识与工具目录 | 检索相关机制、测点和已核验案例，列出合法查询 | 知识 ID、适用条件及可用工具 |

采集尺度由物理过程确定：电流瞬态保留所需带宽，速度恢复覆盖事件前至完整恢复，持续异常覆盖足够长的控制阶段。在 100 kSa/s 下，5000 点仅为 50 ms。降采样前做抗混叠，原始采样用于高频特征，绘图保留单位和事件位置。

机械平衡残差可采用 `r_m = J·dω/dt − (T_e − T_load − B·ω)`，其中 J 为转动惯量、B 为黏性摩擦系数、ω 为角速度，T_e 与 T_load 为电磁转矩和负载转矩。参数误差、导数滤波及未测扰动通过正常数据标定。需要电气残差或 ARX/NARX 预测残差时，核对相应信号与建模条件。

### A.4 贡献验证的具体口径

分别比较显式知识与变量含义的作用：保持模型、反馈形式、内层搜索和预算一致，先比较提供/不提供额外工程机理条目，再比较保留/隐藏变量名称与物理含义。两组输入使用一致的变量编码和数值域；隐藏组移除提示中的物理名称与说明，程序通过预先固定的映射还原实际变量及单位，执行校验与评分保持一致。需求、知识和历史描述中的标识同步处理，并登记保留的单位、目标等语义线索。结果用于判断显式知识或变量含义对当前方法的贡献，解释范围限于该输入条件；模型预训练知识与一般推理仍共同影响表现。

混合搜索的外层替代共用事件模式集合、内层优化器、评分器和总预算，使用相同历史与工程知识。在同一模型下，比较无历史反馈、参数与距限值的余量反馈及增加动态响应三种输入。测试假设与解释用来理解决策，收益依据实际选点和执行结果评价。

诊断的初始摘要可在开发阶段设计为只呈现共同症状，再核验固定基线能否仅凭这些摘要轻易区分机制；补充查询的价值由独立样例中的候选区分变化检查。全部策略共用初始信息和工具权限，工具可访问的观测与评价器持有的隐藏真值分别定义。

非 LLM 自适应策略可将预期观测归入经工程核验的结果类别，按能区分的候选对比例与调用成本选择查询，返回后用证据规则更新候选。不可读观测和已无新增信息的查询从动作集中移除；各候选预测相同时保留未决。贝叶斯或信息增益策略另需先验、预测分布及噪声标定，建模投入单列。

开展新需求适配时，人工与 LLM 辅助使用相同资料和正确性要求，记录规约/策略修改、知识整理、提示维护、审核、返工与总时间。登记工程人员熟悉程度及任务顺序，控制学习和复用影响；同对象新需求与跨控制器迁移分别报告。

### A.5 指标与成本明细

| 对象 | 主要指标 | 必须保留的情况 |
|---|---|---|
| 工况生成 | 可执行率、有效激励率、人工修订时间、组合/序列覆盖 | 非法、重复、执行后未激活目标的提案 |
| 新需求适配 | 规约正确性、可执行性、适配后效果、增量及总人工时间 | 知识整理、提示维护、审核、返工和失败适配 |
| 失效搜索 | 固定预算内发现率、首次发现成本、唯一模式数、本轮最小余量 | 未发现运行、初始化、失败执行和模型开销 |
| 边界刻画 | 边界区间/分辨率、邻近复验一致性、覆盖范围 | 无满足点或无违反点、不可评价点 |
| 行为与规律 | 特征误差、重复性、独立工况趋势/预测质量 | 失配区域、正常复杂响应及规律失效条件 |
| 异常检测 | 正常运行单位时间误报、事件召回、检测延迟和区间质量 | 正常瞬态、短异常、持续异常和漏检 |
| 独立分类/定位 | 给定真实区间的宏 F1、混淆矩阵、位置 Top-1/Top-k | 未知、未决、错分类和误定位 |
| 完整诊断 | 规定时限内检出并正确识别率、误报、总延迟 | 漏检、错分类和超时 |
| 证据选择与判断更新 | 预算内原因区分率、有效分析次数、证据更新正确性、人工排查时间 | 查询失败、无效/重复分析、不当确定和未决；新增实验单列 |
| 主动复验（后续扩展） | 固定预算正确定位率、新增实验成本与未决比例 | 不能区分、未知机制、无故障和失败实验 |

**已知故障端到端检出并正确识别率 = 规定时限内检出且正确识别的已知故障事件数 ÷ 全部真实已知故障事件数。** 漏检、错分类和超时留在分母；未知机制单列“检出且正确拒识”，并统计已知类的错误拒识。事件匹配、合并、阈值及延迟在测试前固定。

搜索同时给出相同测试执行次数、相同总时间/费用两套预算结果，并另报有效执行数。首次发现成本保留未成功运行的截尾情况；重复失败与新模式分别计数。局部边界复验成本单列，并计入完整边界获取成本。

覆盖指标分别统计至少完成一次有效测试的合法工况组合、事件次序和预先划分的参数区域数量，以及它们占各自总数的比例。重复测试同一组合、次序或区域不增加相应覆盖数；正式比较前固定分母、划分规则和有效测试条件。余量按同一指标、单位和评分定义比较；多个指标分别报告，联合评分按预先固定的归一化与组合方式计算。

正式重复次数、预算档位和实际有意义的收益门槛由预试方差、执行成本及应用要求确定。按独立运行或配置族给出不确定区间，报告关键故障与最差工况；模型和搜索随机性通过固定配置多次运行衡量。

首批优先完成两项核心任务的策略替代对照，以及知识、语义与反馈的作用比较，按研究问题选择组合。新需求适配、特征与规律发现和跨模型家族复核各自登记范围、数据与投入，避免把所有模型、信息条件和任务阶段同时组成全量试验矩阵。预测建模、机制—工具表、知识整理及工程审核计入对应方法的准备成本，共用投入与增量投入分别报告。

## B. 资料、接口与调用示例

### B.1 按当前问题整理工程知识

工程人员负责确认对象、需求和物理含义，研究侧负责将资料整理为规约、知识条目和可调用工具。按首批问题收集资料，每条知识登记来源、对象/固件版本、适用条件和确认人。

| 资料 | 形成的输入 | 主要提供/确认角色 |
|---|---|---|
| 需求、正常工作范围、保护逻辑与性能要求 | 测试目标、阈值和允许动作 | 合作方测试与控制负责人 |
| 模型接口、信号表、单位、采样和执行限制 | 信号字典、动作原语和配置校验规则 | 模型/平台负责人 |
| 控制框图、相关原理图、反馈与执行路径 | 控制关系及“机制—症状—区分证据”条目 | 固件/硬件工程师 |
| 电机与控制参数、正常样本 | 正常参照、物理关系及参数误差范围 | 建模与控制人员 |
| 已知故障、维修记录、专家经验 | 故障知识、混淆案例和复验动作 | 测试/维修工程师，研究侧核验整理 |
| 板卡、固件、驱动反馈接口和时钟信息 | 实体观测集、版本及时间关联条件 | 现场实验负责人 |

机制条目可按对象与运行阶段、机制、作用路径、预期响应、易混淆情况、区分观测、复验建议、来源与版本组织。例如“反馈偏置”的判断需要知道偏置施加在哪条链路、控制器如何补偿、哪些独立观测可区分真实转速变化。资料先覆盖当前诊断问题，缺少关键知识时缩小问题或补充资料。

| 执行与评分返回 | `run_id`/`run_dir`、CLI 原始状态、实际事件、原始数据引用；评分值、`requirement_verdict`、截尾与有效性说明 | 评分对象独立关联执行记录；执行错误或缺失指标对应空值及原因，需求违反保留真实评分 |
| 异常事件与分析结果 | `event_id`、运行、通道、窗口、数值/单位、工具参数与版本、数据有效性、来源引用 | 工具错误、缺失观测与有效测量分别表达 |
| 诊断及决策更新 | 候选原因、预期区分证据、查询/工具记录 ID、支持与冲突证据、候选变化、缺失信息、下一动作 | 每项观测判断均可追溯到已有有效结果；真值由评价器保存 |

CLI 的 `status`、`experiment_status`、`record_status` 按原语义保留。研究评分可另用 `requirement_verdict` 表达，示例取值为 `passed`、`failed` 或 `not_evaluated`，对应需求满足、违反和不可评价。执行错误与采集问题保留各自来源状态，不能作为需求违反的数值反馈。事件未生效、工具查询错误或数据不足时，返回错误/缺失原因，诊断保留对应未决项。

有重复请求时，可通过 `proposal_id` 关联；采用缓存或去重时，各方法使用一致的处理方式。相同配置的重复性复验使用新的执行标识并注明目的，每次真实运行计入执行预算。缓存命中、无效提案、真实执行和重试分别计数。诊断工具结果保留参数、有效性及证据引用，查询失败产生的文本不得被登记为测量事实。

### B.4 搜索提案示例与可调设置

下面演示信息交接，**提案与反馈数值均为说明性示例，未运行该实验**。固定模板设置初始速度 1800 rpm、负载 0.01 N·m 和 0.8 s 采集；恢复评分采用 A.2 的记录终点定义、0.10 s 期限与 ±50 rpm 误差带。转换为预演配置时，将 `acceptance.window_policy` 设为 `event_group`，评价事件前基线和末事件后稳定段；恢复评分从末实际事件起计算。下例两事件相隔 50 ms，采用默认 `all_segments` 及 100 ms 稳定等待会因中间评价窗口不足而被拒绝。

```json
{
  "requirement_id": "RECOVERY_DEMO",
  "test_hypothesis": "调速尚未完成时叠加负载可能延长恢复",
  "history_ids": [],
  "events": [
    {"at_s": 0.20, "target": "reference_speed_rpm", "value": 2400},
    {"at_s": 0.25, "target": "load_torque_nm", "value": 0.03}
  ],
  "expected_effect": "检查调速尚未完成时叠加负载是否延长恢复"
}
```

执行器转换配置、核对两事件生效后，分析器若测得恢复时间 0.12 s，则反馈恢复时间余量为 −0.02 s，并附恢复区间、速度最低点、三相电流特征和原始数据引用。首个反例模式在这里结束搜索；边界研究继续复验该点，并在相同模式下调整事件间隔，寻找相邻的满足与违反条件。若选择混合搜索，LLM 可提出间隔子域，优化器对该子域内实际参数评分。

| 起步设置示例 | 用途 | 调整方式 |
|---|---|---|
| 最近十次历史 | 借鉴 LLM-Falsifier 组织反馈 | 按任务长度、信息保留与成本调整 |
| 总执行 50 次、混合搜索每轮至多 10 次 | 演示外层与内层预算分配 | 正式档位依据预试固定，各策略共用总预算 |
| 最多四轮工具查询 | 诊断流程开发的起点 | 根据有效证据、调用成本和任务难度确定正式预算 |

混合搜索可由外层给出事件模式、连续参数上下界及依据，内层返回本轮实际测试中评分最低的工况、实际执行参数与全部调用记录。时间网格映射后再校验和评分，程序掌握总执行预算，优化器迭代与真实执行分别计数。无改善时将完整反馈交回外层，再选择是否更换模式或区域。

### B.5 诊断工具与结果示例

工具调用可用运行 ID、通道、时间窗口和计算参数定位数据，返回数值、单位、有效性和引用。诊断先记录候选原因、作用位置、适用条件、响应预测及可能的冲突观测，再选择工具；返回后记录实际结果与预测的比较、候选变化及依据。预测在读取对应补充结果前保存，字段组织按现有工具调整。假设检验的方法依据与比较设计见[完整方案 §3.2](technical-selection.md#32-诊断循环与相似症状示例)。

结果字段参考：`event_id`、`fault_class`、`candidate_causes`、`supporting_evidence`、`conflicting_evidence`、`missing_information`、`next_action`。证据关联运行、通道、区间和工具结果。工具返回 `insufficient_data` 或错误时保留缺失原因；证据足够、无新增信息或预算到达均可结束查询。模型自报置信度在独立校准后再作为阈值。

知识检索先按对象、阶段和允许机制筛选，再用 BM25 等关键词方法排序；资料增多或同义表达造成漏检时，再比较向量检索。返回保留适用条件和来源，输入长度依据实际负载安排。

任务二首批的工具只读取和分析已采集数据。新增复验动作的校验、执行及成本在后续主动复验中单列。

### C.2 模型初筛与版本追踪

第一阶段用经工程审核的小批任务样例初筛，先测原有权重配合提示、知识与工具的效果。首批围绕测试搜索与故障诊断，覆盖合法提案、事件交互、历史反馈、相似原因、证据冲突、缺失观测及工具错误处理；开展新需求适配或特征与规律发现时再补充相应样例。

| 初筛能力 | 样例与检查方式 | 保留的评价记录 |
|---|---|---|
| 结构与约束遵循 | 生成测试配置、工具请求及诊断字段，由程序校验 | 格式/业务合法率、错误类型、修订及重试成本 |
| 工程语义与知识使用 | 检查单位、作用路径、适用条件和资料引用 | 事实错误、知识误用和工程审核结果 |
| 反馈决策 | 给定历史响应，检查是否据新结果调整模式、区域或后续选择 | 所用历史、测试假设、预期响应与选择变化 |
| 诊断证据综合 | 比较多个解释，补充证据后检查候选更新 | 正确原因/候选集合、冲突处理和不当确定结论 |
| 工具选择与错误处理 | 存在多种有效查询，部分工具返回缺失或错误 | 有效调用、获得的区分证据、失败处理与耗时 |

搜索样例允许多个合理下一工况，诊断也允许多个有效工具或尚不可区分的候选集合。初筛依据规约、物理关系和证据检查能力；固定历史回放用于筛查输入理解，真实搜索收益在第二阶段评价。模型自报信心和解释流畅度分别记录。

冻结样例、知识、工具权限和评价规则，保留提示开发、模型筛选与最终独立测试的分组。各模型使用相同语义输入和任务预算，允许原生模板及调用格式，记录差异。自部署固定权重 revision、分词器、模板、量化及框架版本；服务模型记录模型标识、调用日期、配置、响应和可取得的版本信息。

第二阶段将通过初筛的候选接入软件电机控制闭环中的测试搜索和诊断流程，比较失效发现、原因区分、错误、总时间、费用和人工投入。先固定模型比较方法，再固定方法比较模型，关键结论补充跨模型复核。效果接近时按成本及部署条件选择；能力不足时结合参照结果，判断应改进模型、输入、知识或工具。最终交付每项任务的效果—成本对照及模型/部署组合，明确适用范围。

研究与部署分别形成选型记录，避免把研究角色直接作为部署推荐。

| 选择阶段 | 决策目标 | 决策依据与验收 |
|---|---|---|
| 研究模型 | 为两项核心任务提供有效试验载体，检查方法效果是否受候选能力限制 | 样例调用可核验；比较能力参照与成本候选的决策、错误和完整任务效果，保留低能力或无增益结果 |
| 部署模型 | 在声明的需求与数据范围内满足效果、可靠性及资源要求 | 开发预试后冻结合法提案/有效调用、原因区分、不当确定、未知/未决处理及成本/时延门槛；用独立数据验收，达标候选再比较费用和维护投入 |

门槛由实际用途与关键故障要求确定，平均分之外单列关键场景表现；样本量和不确定性随结果报告。样例开发、门槛确定、模型筛选及最终独立测试保留各自记录。

服务版本另作追踪。2026-11-12 核查的 [DeepSeek 官方说明](https://api-docs.deepseek.com/quick_start/pricing/)将 `deepseek-flash` 映射到 V4.1-Flash-1017；请求别名、响应中的模型标识、调用日期、当时版本映射和完整输入输出分别保存。服务别名与响应标识可能不足以固定权重，严格版本复现需确认固定版本接入方式或采用固定权重。映射变化时分批报告，必要时在新版本上重做相关对照。

### C.3 部署与资源预留

依据任务试测结果和部署条件，在外部模型服务、内网服务与本地运行之间选择，统一通过 B.2 的结构化接口与 Typhoon 交互。服务型方案测量完整调用的时延、费用、可用性与失败率；自部署方案进一步测量显存、内存及运行维护投入。

选择自部署时，将推理服务与 Typhoon 执行环境分离。具备 Linux GPU 环境时，可采用 vLLM 或 Transformers 推理服务；在目标系统上先验证模型加载、模板、工具解析和一次完整请求，再固定环境。[Qwen3.5 官方模型卡](https://huggingface.co/Qwen/Qwen3.5-9B)给出了服务、工具调用及纯文本模式；[vLLM 结构化输出文档](https://docs.vllm.ai/en/latest/features/structured_outputs/)提供 JSON Schema 约束方式。

先从任务样例统计输入长度、历史轮数、工具次数和输出量，再确定上下文、并发与时延要求。按参数量和精度估算权重下界，在实际框架中测量加载及任务峰值，最后比较满足负载的部署组合。服务方案直接测完整任务费用、时延及稳定性；自部署增加资源与维护测量。

下表保留已有较小候选的一组短文本预留估计：并发 1、输入至多约 6K token、总序列预算约 8K token。非思考与思考模式分别评价。Qwen3.5 官方建议复杂思考任务保持至少 128K 的上下文配置；实际需要长输入或长推理时另设工作负载，保存截断和未完成情况，短任务按自身需求验证。

**下表仅用于选择相应本地候选后的资源预留，尚未经目标硬件实测。** 数值按单模型顺序运行、上述短文本负载估计；视觉输入、较长上下文和并发需重新测量。GPU 算力以完整任务时延和吞吐评估，显存容量用于判断能否承载工作负载。

| 工作负载 | 权重配置 | GPU 显存规划 | 主机内存规划 | 用途 |
|---|---|---|---|---|
| Qwen3.5-4B 短文本推理 | 经兼容性核验的 4-bit | 12—16 GB | 32 GB | 较低资源下的提案和诊断试测 |
| Qwen3.5-9B 短文本推理 | 经兼容性核验的 4-bit | 24 GB | 64 GB | 该候选的任务试测，并留工具服务空间 |
| Qwen3.5-9B 精度参照 | BF16 | 32—48 GB | 64 GB | 比较量化影响和增加输入预算 |
| 4B / 8—9B 文本 QLoRA 试点 | 4-bit 基座，低秩适配 | 24 / 24—48 GB | 64 GB | 短序列、微批量 1、梯度检查点下的训练预留 |

基础估算采用“参数数量 × 每参数位数 ÷ 8”，所得为权重存储近似下界，还需加入量化元数据、缓存、运行时、中间张量及视觉组件。训练另有适配参数、梯度、优化器和激活。量化格式须与具体权重及推理引擎兼容。

例如，Qwen3.8 的语言部分 27B 按 BF16/4-bit 计算约为 54/13.5 GB；Gemma 4 12B 的 11.95B 约为 23.9/5.98 GB，均为十进制 GB 的权重近似下界。是否能用特定显卡承载需加入实际运行开销后测量，候选的量化实现先核验兼容性。Qwen3.5 与 Qwen3.8 的规模均指语言部分，还应计入实际加载的视觉等组件。DeepSeek 服务参照按真实调用负载计费和测时，若研究自部署则另做完整权重及框架资源评估。

可核对的参考是 [Qwen 官方速度与显存表](https://qwen.readthedocs.io/en/latest/getting_started/speed_benchmark.html)：在其 H20、Transformers、批量 1、输入 6144 token、生成 2048 token 设置下，Qwen3-8B 的 BF16/AWQ-INT4 显存分别报告为 16811/7113 MB。该表支持资源量级判断；本表的预留值包含工程余量，Qwen3.5 的资源需独立测量。

确定本地候选后，按实测资源安排试运行；现有硬件不足以承载满足任务要求的模型时，比较其他服务或增加算力的成本。采购或长期部署前测量加载峰值、稳定运行峰值、单轮及完整任务 P50/P95 延迟、CPU/内存、输入输出量、失败率和量化前后效果。

### C.4 后续方法与适配参考

特征与规律发现借鉴 Argos：在开发数据上提出特征或规则、生成并执行分析程序、根据结果修订，随后固定程序、提示和阈值，用独立运行检查规律重复性、诊断增益及人工成本。

直接检测可借鉴 LLM-TSAD 的统计分解与索引提示，或 VLM4TS 的候选区间与全局波形图，按问题选择一个表示试点，比较原检测器与修订后结果，检查定位误差及正常瞬态误报。时序隐向量接入语言模型时另做表示对齐，ATTLLM/FD-LLM 提供候选参考。

主动复验在已验证的有限动作集中比较固定顺序、随机、候选响应分歧/预期信息增益、LLM 与混合策略。新增实验结果用于更新原因判断，其执行成本单列；未知机制或动作仍无法区分的情况保留未决。

先测原有权重配合提示、知识和工具的效果，再从错误类型选择改进方式。知识缺失优先补资料，字段与调用错误先检查约束和模板；持续出现的任务能力不足，在比较更强模型与输入调整后，决定是否开展监督微调试点。

| 路线 | 数据与实施方式 | 希望改善的能力 |
|---|---|---|
| 领域/工具 SFT，LoRA 或 QLoRA | 测试规约—历史反馈—有效提案；诊断观测—知识—工具调用—核验结果 | 结构化提案、有效工具选择、基于证据的判断 |
| 时序—语言对齐 | 波形或时序表示与属性、事件、机制描述配对；训练映射层 | 特征输入遗漏的波形信息利用 |
| 知识蒸馏 | 较强教师的提案/判断经执行和真值核对后训练小模型；或向专用时序模型迁移 | 较低资源下保留已验证能力 |
| 离线规则/程序生成 | 开发数据反馈下生成特征/规则，冻结后部署普通分析程序 | 动态关系发现、降低逐次在线推理成本 |

QLoRA 可按 [PEFT 官方量化训练说明](https://huggingface.co/docs/peft/main/developer_guides/quantization)采用 4-bit 基座和低秩适配。首个文本试点可从序列长度 2048、微批量 1、梯度累积和检查点开始；适配层按模型实际结构确认。Qwen3.5 的混合结构及视觉组件需要额外检查训练库兼容性，文本适配试点冻结视觉部分，必要时在 Qwen3-8B 上先核验训练流程。

样本同时包含正常情况、相似症状、缺失观测、未知机制和错误调用的正确处理。教师输出需经过程序和工程核验。按完整运行与配置族划分训练/开发/测试，一次运行派生的多轮对话保持同一分组。先用小批核验样本跑通训练，再依据学习曲线决定样本量，记录独立运行数和派生对话数。

训练比较原权重、适配权重和量化版本的任务效果及成本；思考模式、提示、知识和工具条件分别固定。训练工时、数据标注和 GPU 小时单列，达到任务收益或资源收益再扩大。

### C.5 工作量拆分与后续扩展

以下按工作范围重新拆分规划投入。假设一名熟悉代码的开发者全时工作，现有软件电机控制闭环可复用，需求、工程资料和所需推理服务/算力可取得，故障注入路径可修改；工程负责人参与确认。区间为依据模块拆分的初估，首周、首个故障及首次多模型运行后校准。人日表示工作投入，批次运行、资源排队及外部等待分别记录。

第一部分形成单模型、单故障机制的流程原型，复用既有记录核对评分与接口，并取得一轮真实反馈。

| 流程原型工作包 | 工作量初估 | 完成后可检查的产物 |
|---|---|---|
| 共用准备与首个模型接入 | 4—6 人日 | 需求/评分与信号核对、必要记录关联、一个模型的样例调用 |
| 测试搜索：提案、反馈与基本搜索 | 5—8 人日 | LLM 与基本非 LLM 策略可重复运行，假设与真实反馈关联 |
| 数据分析：特征、正常参照与检测 | 4—7 人日 | 可复核特征、正常复杂响应及异常事件对象 |
| 故障诊断：首个影响电机控制闭环的故障与观测 | 3—5 人日，条件性估计 | 实际注入、正常对照、真值与观测核验 |
| 故障诊断：知识诊断与工具调用 | 6—10 人日 | 诊断循环、证据更新与未决出口 |
| 流程原型合计 | 22—36 人日 | 两条基本流程 |

第二部分单列多模型初筛的增量投入。共用样例整理与审核估 3—5 人日，每新增一个模型的模板/接口适配、调用、错误复核及成本记录估 2—4 人日。首个模型已接入时，总数 2—3 个、覆盖能力参照与成本候选，追加约 **5—13 人日**。样例可复用已核验运行及工程审核材料，来源分别登记；完整原因区分比较仍依赖不同机制产生相似症状的数据。大型权重首次部署所需的新环境建设另估。

第三部分补齐两项核心任务的初步比较，新增工作与前述原型分开计算。

| 核心初比增量 | 工作量初估 | 完成后可检查的产物 |
|---|---|---|
| 测试搜索：混合策略、信息作用比较与复验 | 5—9 人日 | 外层策略替代，知识、语义与反馈作用比较，预算与局部复验 |
| 故障诊断：不同机制的相似症状与区分证据数据 | 4—7 人日，条件性估计 | 补充机制及观测，可区分、缺失/冲突和不可辨识样例 |
| 故障诊断：自适应基线及分层/完整流程初比 | 6—10 人日 | 分歧选证据策略、相关固定流程、有限留出运行和错误分析 |
| 核心初比增量合计 | 15—26 人日 | 核心初比的效果与成本依据 |

上述已列范围合计约 **42—75 人日**：流程原型 22—36、多模型增量 5—13、核心初比增量 15—26；约单人全职等效 9—15 个工作周，专家排期、算力排队与批次运行等待另计。测试搜索的 10—17 人日、数据分析与故障诊断的 23—39 人日已分配在原型与初比中，模型样例共用准备只计一次。各模块按输入成熟度交替或分工推进。

2026-11-13 的方法调整将分环节搜索比较、有限候选的响应预测和工具检验放入原有工作包，以上仍是待首批实例校准的初估。完整概率程序建模、LLM 代理评分与校准、信息增益强化学习和多模态训练，按数据准备、建模和训练工作单独估算；下表的文本适配试点估计不覆盖这些完整扩展。

正式独立验证在预试后，按独立场景/机制数、方法与模型配置数、重复次数、每轮执行和推理时长、标注/审核量重新估算。新增采集、批次运行、专家审核和分析人时分别列出；新需求适配、特征与规律发现、跨模型家族复核及概率预测建模各自单列。为取得可搜索场景所需的额外模型/接口开发、反馈路径重建或新增独立观测，按预试缺口追加，随后更新总量。

| 后续扩展 | 进入条件 | 追加工作量初估 |
|---|---|---|
| 新需求适配、特征与规律发现、跨模型家族复核 | 核心原型与必要数据可用，研究范围确认 | 按样例、适配、调用及工程审核量另估 |
| 一个本地模型的文本 LoRA/QLoRA 试点 | 错误类型明确，核验样本及训练环境具备 | 数据整理、训练和对照约 8—15 人日；新增采集另计 |
| 一个主动复验问题 | 有限候选原因和可区分动作已验证 | 约 5—10 人日 |
| 实体迁移 | C-HIL 电机控制闭环及采集条件验收 | 方法接入、校准和小批比较约 10—20 人日；硬件/固件整改及外部等待单独估算 |

# 模型接入与维护

本页供理解模型和 Schematic/HIL API 的维护者使用，说明如何把一个来源明确的模型接入统一执行器。日常实验从 [README](../README.md) 选择 RLC、Boost 或单相桥整流教程。

## 定义实验

先通过 `list-cases --json` 查找当前案例，再用 `validate-case --case <标识> --json` 区分材料、代码支持和实际证据，格式与路径规则见 [案例接口](case-interface.md)。选择配置复用、适配器扩展或新增适配器；新模型先完成下述接口预验，再冻结配置。

接口预验保存实际模型与配套测试来源、版本和哈希，核实参数路径、信号物理含义及单位、设置时机与控制通路。以新目录完成编译、Virtual HIL 加载和短采集，确认实际步长、抽取、通道容量与时间戳。设置值用 API 回读或实际信号证明生效；采集不足不能进入性能评价。电机案例的 [接口映射](../cases/im_speed_tracking/README.md) 和 [判据来源](../cases/im_speed_tracking/acceptance.md) 提供完整示范。

先明确被控对象、模型来源、运行模式、参数及单位、采集信号、事件、分析窗口和判据。RLC 提供结构参数扫描与稳态解析核对参照，Boost 提供闭环初始化、固定时刻事件和动态指标参照。

结构属性需要修改模型副本并重新编译；运行参数在加载后设置并回读。评价标准在采集前确定。按仿真模式确认事件和接口能力，实际观察信号应足以验证所施加的激励。

## 接收测试实例时填写的任务清单

按本次任务填写下表中的适用项，保存在任务记录或新案例说明中。影响实验成立的关键信息尚未确认时注明缺口，并先处理已有材料足以支持的部分。

| 项目 | 要填写的内容 | 单相桥整流的接入示例 |
|---|---|---|
| 实例与负责人 | 案例名称、提出人、实验负责人、交付时间 | 官方 1ph rectifier；教学接入任务 |
| 要回答的问题 | 被测对象、工况、比较因素、预期判断 | 输入减小和负载加重如何影响直流电压、纹波和电流 |
| 来源与版本 | 原始模型、软件版本、依赖、使用条件、哈希 | 原安装示例、THCC 2026.3、origin.json |
| 运行条件 | Virtual HIL 或具体硬件、设备型号、接口和资源占用 | Virtual HIL；单执行器互斥 |
| 参数与单位 | 基准值、修改范围、结构参数/运行参数、读回方式 | L/C/R 编译前设置，Va1 RMS/频率加载后设置 |
| 激励与事件 | 初始状态、事件值和时刻、实际生效的观察信号 | 三次独立稳态工况；不施加运行中事件 |

| 评价依据 | 独立理论或实物参考、假设、阈值和失败处理 | 独立理想桥 LC-R 方程；预先固定均值/纹波误差 |
| 需要交付的内容 | 配置、源模型、数据、图、报告、复核及讲解 | 单次记录、三工况比较、模型接入教程 |
| 验收与待验 | 软件、GUI、跨机和人员各由谁完成 | 实际软件运行留证；他人复现单独验收 |

## 留存模型来源

核对新增官方素材的再分发条款。未确认允许公开分发时，保留安装相对路径、哈希和准备方式，官方模型/面板统一作为本机依赖排除 Git。当前执行器仍从 models/<model_id>.tse 与固定来源索引加载，不将案例元信息泛化为任意文件加载器。

官方模型与面板在 origin.json 登记安装相对路径、软件版本与 SHA-256，通过 `prepare-models` 按字节复制到 models/。来源分类和预留目录见 [模型说明](../models/README.md)。每次执行使用结果目录中的副本。许可文件由安装环境管理。

确认移到另一台匹配环境后能定位依赖，并核实模型能在 Virtual HIL 编译和加载。依赖实体 I/O、外部控制器或未具备功能时，记录缺少的条件。组件与端口先通过安装 API 检查，层次路径按该 API 的实际行为处理。

## 实现适配器

在 src/typhoon_lab/adapters/ 中实现适配器并显式注册。共同执行器负责来源核验、复制、编译、加载、互斥、采集、超时、清理、快照和清单。

| 成员／方法 | 职责 |
|---|---|
| model_id、schema_version | 模型标识与配置结构 |
| signals、columns、units、sources | 实际 API 名称、CSV 列序、单位及必需源 |
| capture_before_start、changes | 采集时机与运行副本的结构改动说明 |
| has_events | 是否产生事件记录；显式能力标识，不从配置版本推断 |
| validate(raw, sweep=False) | 返回规范化配置，拒绝未知字段及无效参数、窗口和采样条件 |
| inspect_parameters(api) | 静态参数与表达式的来源 |
| prepare(api, config) | 修改运行副本并回读，返回实际参数 |
| initialize(hil, config) | 加载后设置运行参数并回读，返回实际设置 |
| schedule(hil, config) | 在启动前安排事件并返回排程记录；无事件返回空列表 |
| check_sampling(rate, count, config) | 核对量化后的实际采集条件 |
| analyze(csv_path, config) | 确定性分析原始 CSV，返回指标、检查与方法 |
| report(run_dir, manifest) | 从已有记录生成图和报告，返回输出路径 |

Boost 的 describe_schedule(config) 提供离线排程描述，供 schedule 与 verify 核对使用。接入新的配置结构或事件记录时，需同步分析分派、报告、快照和 verify。

配置结构按模型解析：RLC 与单相桥整流均使用 schema_version=1 的稳态布局，Boost 使用 schema_version=2 的动态布局。schema_version 表示结构版本，model 表示案例，事件记录由适配器 has_events 能力决定。接入新模型时逐项核对 CLI 选项、配置、采集、分析、报告、verify 和历史记录兼容性，避免把版本编号当作模型数量。

## 参数读取与事件时序

Schematic API 加载模型后，初始化命名空间尚未执行。参数使用表达式时，在静态检查中标明数值来源，并通过实际编译验证。Boost 的检查读取模型初始化中的 P、I、I_initial、Ts 四个字面量及 PI 属性表达式。

Boost 运行副本在 Reference 与误差求和器之间使用 LabReferenceStep 和 LabReferenceSum，通过 ReferenceApplied 观测实际参考。LabReferenceSum 的传播为一个 Ts，Step 内部触发设为目标时刻减 Ts。Vin 通过源 executeAt 排程，VinMeasured 观测输入电压。

该时序关系由监测波形验证。更改控制周期、求和器或信号链后重新测定传播，记录请求时刻、内部触发、补偿、调度、首次变化样本、检测区间与分辨率。

## 数据与指标

确定 CSV 时间列、单位、有效采样率和触发元数据，严格检查缺失与无效样本。分析不调用 Typhoon，也不修改原始数据；处理和排除规则在方法记录中说明。

评价参考独立于运行数据，说明理论或数值模型的假设、窗口、分母与容差；没有独立参考的指标需给出其判据依据。动态指标需定义事件前条件、稳态窗口、容差带、超调分母、调节时间，以及观测结束时未恢复的结果。连续时间解析响应可作为单元测试的独立参照，实际 Virtual HIL 运行单独留证。

实验状态保留 passed、failed、error、skipped，复核区分记录一致性与实验判据。报告显示所有要求工况和未通过项，并标明图中的采样与分析范围。

## 验证与交付

验证深度由本次交付目标和改动范围决定。模型检查或接入方案交付来源、接口映射、缺口及后续验证安排；编译或加载检查保留相应阶段的实际证据。完整教学接入建立基准与能回答实验问题的必要对照工况，数量和参数据此确定。

对实际改动完成配置、分析、事件及清理等相关测试，按 [项目验证要求](../PROJECT_SPEC.md#验证要求) 执行受影响的实际运行与回归。交付实验结果时逐项复核，重建报告后再次 verify。

完整教学接入交付模型说明、配置、实际目录、操作教程和验证结论。通用入口或数据结构改变时检查历史记录副本，保留原记录。交接任务按 [交接流程](handoff.md) 安排独立复现，记录本次已验证和待验范围；结果维护在 [验证状态](validation.md)。

文档按完整现行用法更新：参数和指标放在模型说明，任务示例放在 Agent 页面，通用排错放在排错页，实测数值按日期归入验证记录。新增能力直接融入对应章节与导航。

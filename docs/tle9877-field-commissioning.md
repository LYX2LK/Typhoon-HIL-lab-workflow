# TLE9877 样机现场联调准备与记录

本文面向参与接线、模型配置和首次联调的组员。目标是用一个正常工况留下“命令、板卡响应、模型反馈、停止与恢复”的完整记录。当前项目提供离线工具和准备模板，实际操作由现场负责人结合板卡说明、汉象设备与已验证工具安排。

需要先理解迁移原理时，阅读[从 PMSM 软件预演到 TLE9877 实体 C-HIL](beginner/09-pmsm-to-tle9877-chil.md)；其中的 [TI 官方案例中文实训](beginner/08-ti-launchpad-chil.md)解释外部控制器、驱动入口和反馈出口。

真实闭环路径为 **LIN 命令 → 实物控制板 → 六路驱动 → HIL 逆变器与电机模型 → 采样反馈 → 实物控制板**。数据准备按[采集交接说明](tle9877-data-collection.md)落实；文件导出后用[现场数据入口](field-data.md)整理、关联和离线评价。LIN 解码值直接送软件模型参考只用于软件练习。

## 接入资料怎么填写

板级原始事实保存在 [tle9877_sample.json](../configs/tle9877_sample.json)；本次增加的 [I/O 接入合同](../configs/tle9877_hil_contract.json)用于记录双方商定的接线。两份文件分开维护，方便保留资料原文和实际接入决定。

合同是工作表，按实际信息逐步填写。原有 `check-tle9877` 继续做资料与静态参数检查，其通过条件保持不变；本轮没有增加严格就绪检查或自动上电门槛。

| 字段 | 填写方式 |
|---|---|
| source_row / name / role | 对应原 Excel 行、名称和用途；18 条引线逐条保留 |
| disposition | `pending` 待决定；`connect` 拟接入；`not_connected` 明确不连接 |
| endpoint | 接入时填写 `{ "kind": "hil / lin_adapter / power_supply / fixture", "device_id": "实际设备标识", "port": "实际端口" }`；不连接时保留 null |
| direction_relative_to_board | 相对被测板填写 `into_board`、`out_of_board`、`bidirectional` 或 `reference` |
| board_reference / endpoint_reference | 分别写板侧和设备侧参考电位；上桥栅极注明对应相节点及调理后的参考点 |
| source_voltage_range_v | 调理前信号范围，格式 `[最小值, 最大值]`，单位 V |
| conditioned_voltage_range_v / destination_allowed_range_v | 分别填写调理后范围和接收端允许范围；共模范围另记 |
| conditioning / maximum_delay_s | 分压、隔离、缓冲、差分注入、滤波等实际方案及延迟；无需调理时注明已确认的直连依据 |
| connection_status | `not_verified` 未核对；`wired` 已接线；`verified` 已检查；`not_connected` 明确不连接 |
| not_connected_reason | 说明为何不接，以及该节点保留、隔离、固定电平或诊断路径的安排 |
| confirmation_ref | 指向合同 confirmations 中的一项，填写确认人、带时区日期和依据文件/答复；涉及文件可记录路径和 SHA-256 |

电源、地和 LIN 使用各自设备或接线端子，不要求占用 HIL 通道。PWM-IN 可以按双方确认的非活动方案处理。U/V/W、VM、SL 是否接入或保留，取决于功率级和无感/诊断路径；逐条写明决定，不能由引线名直接推定。不连接的线仍留在清单中。

`supply_and_stop` 区保留资料建议 9V、上限 10V，并另设实际确认值、限流、功率级和停止流程字段。六路 GH/GL 的“18V/2=9V”继续作为原始资料表述，不能直接填入允许电压范围。

## 真实模型参数怎么补齐

使用 [实体参数接收表](../configs/tle9877_motor_pending.json)。资料给出的 5mΩ、11µH、5 极对仍可查到；目标模型的 Rs、Ld、Lq、磁链、惯量、摩擦和负载另外填写。5 极对已按资料填入，其余目标参数保持空白。

先说明原参数指 Δ 支路、线间测量值还是软件等效相参数，再说明目标模型采用 Δ 还是等效星形，以及磁链、峰值/RMS、温度和测试条件。换算方法随测量口径和模型定义记录；不机械把所有参数除以 3，也不将 `pmsm_software_preview` 的假设回填到此表。供应方确认、实测、辨识和假设使用不同的 basis 文字标明。

## 现场首轮步骤

现场使用 [smoke 计划](../cases/tle9877_hil_smoke/plan.json)和[记录模板](templates/tle9877-field-record.md)。命令、超时、持续时间、允许误差、电流和停止判据由当日负责人填写，不套用软件预演的 50rpm 判据。

1. **对齐对象与接线。** 记录板号、实际芯片、固件、HIL 型号/序列号、LIN 设备和 SDK。对照实际改装图逐条核对合同，说明功率级保留/断开范围、参考点和非活动 PWM 状态。将答复或测量文件关联到对应条目。
2. **检查非驱动条件下的信号。** 按已确认的供电、限流和初始状态操作，核对栅极调理后的电平/时序，以及反馈链的极性、零点、范围、共模、滤波和采样窗口。单分流注入与桥臂状态、无感所需的其他反馈同时核对；仅有电流乘以 0.5mΩ 的静态换算还不能确认动态反馈。
3. **读取版本和状态。** 先用已验证的厂家工具或将来实现的设备驱动读取。主节点读取会发送帧头，安排在双方确认的非驱动状态下进行。保存原始 PID、数据、checksum、设备接收状态和时间戳，核对离线解码。LDF 的业务帧重复周期为 20ms；实际调度、增强校验及超时以现场确认记录为准。
4. **运行一个正常闭环。** 使用已确认的电机模型与反馈路径，只改变一项正常转速命令。分别保存请求转速、编码转速、板卡回报转速和模型转速，采集六路栅极/桥臂状态、注入反馈及模型波形。LIN 状态更新与高频反馈分别记录；未同步的数据先按各自时钟分析。
5. **执行停止并观察后运行。** 依照固件明确的停止流程操作，记录请求、实际命令、板卡状态、门极/模型响应和达到停止判据的时刻。零转速码、断 LIN 或断开 PWM 的含义取决于固件，不能直接当作统一停止方法。释放 LIN 适配器只关闭通信资源。
6. **恢复与核对记录。** 按已确认的恢复顺序回到初始状态。核对文件是否齐全、时钟如何关联、运行和停止是否达标；异常与未完成部分分别记录。出现异常时按本次已确定的停止/断电顺序处理，首轮不追加故障注入。

## 日志与结论

原始总线记录至少包含方向/操作、6 位 ID、实际 PID、原始数据、checksum、接收/错误状态、设备时间戳及其时钟域。主机发送请求和 SDK 返回时间可以补充，但不能代替线上的发送或采样时间。无设备时戳、无同步或超时的地方保持空值或明确状态。

`lin-mock` 的 [bus.jsonl 约定](tle9877-lin-adapter.md)可用于讨论日志字段；其中时间和响应来自 Mock。现场日志另建目录，保留厂家原始导出，再记录转换和分析关系。

本模板是人工记录入口，不生成现有 Virtual HIL 执行器的 manifest。现场实测结论、文件核对情况和软件预演成绩分别填写；后续实现实体执行器时再接入相应的自动采集和复核。

离线文件分析另有 `field_test_data` 记录及专用复核，使用[数据清单模板](../configs/tle9877_field_intake.template.json)关联本次操作记录、接入合同和模型版本。该记录不启用设备，未知判据保持未评估。

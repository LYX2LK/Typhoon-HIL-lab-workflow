# 样机首次测试的数据采集与交接

本文供现场采集、联调及后续分析人员使用，目标是在第一次正常工况中留下能够区分命令、驱动、反馈、模型响应、停止和恢复的文件。具体接线、量程、采样率和触发方式由实际设备方案及负责人确认。

## 先明确真实闭环与观测位置

真实测试路径为：**LIN 命令 → 实物控制板 → 六路驱动 → HIL 逆变器与电机模型 → 采样反馈 → 实物控制板**。

记录工具观察上述各段，不把 LIN 解码转速直接送模型参考当作真实控制板闭环。软件预演仍用于独立学习和文件流程检查。反馈模型由双方按已有实现与分工落实。

## 在操作前安排采集

| 来源 | 保存的内容 | 同时说明 |
|---|---|---|
| 命令与操作记录 | 请求转速、PostSet、实际发送字节、明确的运行/停止/恢复操作 | 命令来源、执行者、时间依据；请求值与编码值分开 |
| LIN 主节点或抓包工具 | 原始方向、ID/PID、数据、checksum、接收/错误状态、设备时间戳 | 工具/SDK 版本、调度、校验政策；TX 完成不等于板卡收到 |
| 六路驱动 | GH1/GL1、GH2/GL2、GH3/GL3 的调理后观测波形或逻辑状态 | 各通道参考点、调理与探头倍率、电压/逻辑单位、捕获位置 |
| 注入反馈 | 实际注入控制板的反馈波形；SHP/SHN 为单端还是差分观测 | 节点、极性、共模、增益、偏置、滤波和测量方式；电压与电流区分 |
| HIL 模型 | 模型机械转速、三相电流、开关状态、母线与其他已定义响应 | 模型文件/摘要、参数版本、信号名、机械/电气速度及单位 |
| 固件状态 | 回报目标、实际转速及错误/保护状态 | 当前版本字段含义、无效码；保留原始报文作为依据 |

每份来源记录设备型号/序列号、固件或软件版本、测点及参考点、量程、探头倍率、倍率是否已在导出时补偿、采集率、导出时间网格、触发与导出设置。采集率和导出网格单独登记。多种工具可以先各自导出，由离线入口整理，无需等待自研驱动。

## 时间与阶段记录

- 明确哪些通道来自同一采集时钟，哪些依赖外部触发或同步。记录触发信号、事件对应、比例/偏移、误差上界和有效时段；没有同步证据的来源分别分析。
- 保存启动前基线、正常运行、停止及停止后保持区间。需要评价停止时，记录长度覆盖预定截止时间和保持时长，采样间隔须能支持相应判据。
- 高频驱动/反馈与 LIN 状态各按用途采集。LIN 更新周期不充当快速驱动或保护动作的测时证据。
- 明确运行、停止和恢复操作的实际时间与时钟域。停通信、发送零速和关闭设备的含义由固件流程决定，不作为通用停止标签。

## 文件交接

1. 原始导出文件保持不变，放到本次输入目录。确认导出编码、表头、单位和列映射；特殊二进制或厂家格式先保留原件，再说明可重复的导出/转换方法。
2. 复制 [现场清单模板](../configs/tle9877_field_intake.template.json)，填写实际来源、时钟、信号和依据。关联 [I/O 合同](../configs/tle9877_hil_contract.json)、模型摘要及[现场操作记录](templates/tle9877-field-record.md)。未提供的来源保持缺项，不借用软件预演补齐。
3. 将现有 JSONL、数值 CSV 或约定的 LIN CSV 交给[现场数据入口](field-data.md)。厂家字段不同先在清单映射；编码或格式不同不得仅改后缀套用。
4. 正常转速、电流及停止判据在查看本次结果前按负责人确认的要求填写；尚未确定则先做整理与描述分析。
5. 打开报告核对来源、时间关联、完整波形、局部窗口及未评估原因，再执行 verify-field-data 保存复核。交付原始文件、清单、报告和复核结果。

首次交付分别回答：命令记录是否完整、板卡有哪些实际响应、驱动与反馈是否可观察、模型响应是什么、停止及恢复是否有对应证据。结论按本次已确认的项目给出，异常原因结合各段观测进一步核查。

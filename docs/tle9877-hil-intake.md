### 六路驱动的“18V/2=9V”还不是完整接线规格

Excel `E13:E18` 对六路驱动均写“数字 IO，实际电压 18V/2=9V”。已知取出点为 MOS 栅极，但没有给出“除以 2”在哪个电路实现、引出端是否已经分压、相对于哪个参考点测量，以及上桥共模如何处理。

因此需向提供方／汉象确认：分压与调理电路、输入输出端位置、实际高低电平与参考点、尖峰和共模范围，以及平台输入规格。没有这些信息不能把 9V 写成已经确认的 HIL 逻辑电平。栅极驱动的开关频率也尚未提供；下文的 100Hz 是外部调速命令频率。

### 电流反馈是毫伏量级问题

由提供方给出的 0.5 mΩ 可计算：

```text
Rshunt = 0.0005 Ω
分流电压差 = 被测电流 × 0.0005 Ω
2 A → 1 mV；10 A → 5 mV；20 A → 10 mV
```

这些是理想分流关系的计算例子，不是实际测试设定。还要确认 SHP／SHN 在滤波网络哪一侧、是否保留分流电阻与 MOSFET、与芯片 OP1／OP2 的实际连接、采样增益和偏置、共模与有效采样窗口。单分流反馈需对应桥臂状态，不能用三相电流平均值代替。

## 4. LIN 配置翻译成软件要处理的内容

### 4.1 总线与三类业务帧

LDF 给出协议／语言版本 2.1，速率 19.2 kbps；主节点 ECU 的 time base 为 5ms、jitter 为 0.1ms，从节点 EWP 的配置及初始 NAD 为 `0x0A`。NAD 是诊断寻址信息，与下表业务帧 ID 分开。

| 帧名 | 6 位 ID（十进制／十六进制） | PID | 数据长度 | 数据发布者与用途 |
|---|---|---|---|---|
| ControlLIN | 38／0x26 | 0xA6 | 2 字节 | ECU 发布调速与后运行设置，EWP 接收 |
| StatusLIN | 37／0x25 | 0x25 | 8 字节 | EWP 发布目标／实际转速、电压、温度、电流与状态 |
| VARIANTLIN | 39／0x27 | 0xE7 | 2 字节 | EWP 发布 Version 和保留字节 |

PID 是在 6 位 ID 上加入校验位后的值，已按协议规则计算并与 Microchip AN2059 附录 A 核对。具体 SDK 可能接收 ID 并自动生成 PID，也可能要求 PID，不能给已经自动处理的接口再加一次校验位。[R1]

读取 StatusLIN 也需要主节点发起帧头，由 EWP 应答；仅被动监听而没有主节点调度，不足以持续取得状态。[R2] Excel 中另有 `0x1900/0x1901` Message ID 标签，不把它们当作总线帧 ID。

常规 LIN 2.x 信号帧按增强校验规则准备；诊断 `0x3C/0x3D` 使用经典校验。[R1] 当前 LDF 未逐帧显式列出 checksum 字段，实际工具设置仍需与固件及抓包核对。

### 4.2 控制帧不是只有一个转速字节

| 字段 | LDF 起始 bit／位宽 | 位置 | 含义 |
|---|---|---|---|
| ControlSetspeed | 0／8 | byte 0 | 数值编码范围 0～254，比例 22.4 rpm/code；255 为初值，Excel 标为无效 |
| PostSet | 12／3 | byte 1 的 bit 4～6 | 0=no_post；1～5=stage1～stage5；7=initial；6 未定义 |

未分配的控制帧 bit 为 8～11 和 15；Excel 协议图将这些保留位写为 0。LDF 没有把它们声明为信号，实际编码实现需明确填充约定并与样帧确认。

离线换算例子：raw=100 对应 2240 rpm；raw=250 对应 5600 rpm。若用户输入不能恰好编码的转速，工具应返回所采用的 raw 值和对应编码值，并明确舍入规则。**编码值与固件实际采用的目标转速分开记录**，因为协议调速图还给出了低速和高速平台区。

不要把 `ControlSetspeed=255` 或 `PostSet=7` 当作常规运行指令。后运行各阶段的持续时间、运行目标、触发和退出条件未给出，需由提供方补充。

### 4.3 状态帧的数值与标志

以下 byte 编号从 0 开始。线性换算只在有效编码范围内进行，原始码必须保留。

| 信号 | 位置 | 有效范围与换算 |
|---|---|---|
| Setspeed | byte 0 | raw 0～254，raw × 22.4 rpm |
| ActualSpeed | byte 1 | 同上，表示板卡反馈的转速值；与 HIL 模型转速分列 |
| Voltage | byte 2 | raw 0～254，raw × 0.1 V |
| Temperature | byte 3 | raw 0～210，raw − 50 ℃；211～254 未定义，255 为初值且 Excel 标为无效 |
| Current | byte 4 | raw 0～254，raw × 0.2 A；具体测量对象、滤波和更新方式需确认 |

上表其他四个 8 位量的 255 同样应标为无效，不转换成正常数值。LDF 的物理范围之外或未定义的状态保留原码与原因，不自动补零。

| 状态字段 | 起始 bit／位宽 | LDF 的 0／1 含义；其他定义 |
|---|---|---|
| ST_PRM_END | 40／2 | 后运行完成／取消；3 无效 |
| ST_RPM_MONI | 42／2 | 转速监测启用／未监测；3 无效 |
| ST_EMMOD_IN | 44／2 | Low(off)／High(on)；3 无效 |
| ERR_ST_OTMP | 46／2 | 无过温／过温；3 无效 |
| ERR_ST_OCU | 48／2 | 无过流／发生过流；3 无效 |
| ERR_ST_DRYR | 50／2 | 未检测到干转／检测到干转；3 无效 |
| ERR_ST_U | 52／2 | 电源电压在规定范围／不在规定范围；3 无效 |
| ERR_ST_Block | 54／2 | 解堵未激活／解堵激活；3 无效 |
| Reserved | 56／2 | LDF 初始值 0，无业务枚举 |
| NOD_ERR | 58／2 | 无错误／出现错误；2=错误状态发生变化，3=无效 |
| ST_PRM | 60／3 | 与 PostSet 共用枚举 |
| COM_ERR | 63／1 | 无通信错误／通信错误 |

未列出的枚举值按未定义处理。特别注意：这些标志并非全部“0 正常、1 故障”；例如 `ST_RPM_MONI=0` 表示监测启用。`ERR_ST_Block=1` 的 LDF 释义是解堵激活，不能直接据此判定已发生真实机械堵转。

### 4.4 调度表的 10ms 是时隙，不是每个帧的重复周期

`EWPTEST` 有两个连续时隙：

```text
时刻        0ms           10ms          20ms          30ms
帧          ControlLIN    StatusLIN     ControlLIN    StatusLIN
```

按文件循环执行时，每个时隙 10ms，同一帧的名义重复周期为 20ms，即各 50 次／秒。`CheckVersion` 则是独立的 VARIANTLIN 500ms 时隙；它不会仅因出现在 LDF 中就自动插入 EWPTEST。上述调度语义按厂商 LIN 文档核对。[R2]

Excel 写“推荐使用 LIN 周期 10ms”，需要确认是指时隙还是同一帧周期。不要在未确认前把两个帧各改为 10ms 发送，也不要用 Python 的 `sleep(0.01)` 循环冒充已经验证的总线调度精度。优先使用所选接口设备支持的调度功能，并记录实际时间戳。

LIN 状态用于上位机控制、监视与故障记录。其更新周期与分辨率不能替代 HIL 高频电流反馈；快速保护动作的时刻需要更快的硬件观测或捕获证据。

## 5. PWM 调速协议有哪些操作含义

Excel “PWM控制协议”页第一张图片给出的命令输入条件为：高电平 5V～Upump，低电平 0～1V；频率 50～1000Hz，推荐 100Hz，并写明超过 1000Hz 为全速。这里的 Upump 及驱动接口电气实现仍需按本板确认。

| 占空比 | 图表说明 | 准备时的处理 |
|---|---|---|
| 0% | 0rpm／后运行模式 2，依赖 LIN 与 PWM 电平逻辑 | 不作为无条件停机默认值 |
| 1%～7%，推荐 5% | 紧急运行，最大转速 | 不作为首次低速试验值 |
| 8%～12%，推荐 10% | 停止，0rpm | 可作为待固件确认的停止命令候选；仍要观察实际状态 |
| 13%～22%，推荐 16% | 最小转速 | 最小转速具体数值未提供 |
| 22%～85% | 可调转速区 | 22% 边界与上一档重叠，映射公式待确认 |
| 86%～100%，推荐 90% | 最大转速 | 85%～86% 之间及边界判定需补全 |

同页另有曲线标出 86%、98% 等边界，与表格表达并不完全一致；资料还写采集精度 ±2%，其含义需确认。首次功能联调选择双方确认的区间内部值，边界测试待协议统一后单列。

资料注明“无 LIN 通讯时，PWM 从高电平变低电平自动触发后运行模式 2”。这意味着停止 LIN、断开 PWM 或改变空闲电平都可能影响状态机。LIN 和 PWM 的优先级、超时切换、非活动接口电平、后运行取消方法应纳入启动／停止说明。

第一批中的参数/接口配置、LIN 离线编解码及检查已形成[可执行工具](tle9877-software-preparation.md)；另有独立参数假设的 PMSM 软件预演。现已增加 [I/O 合同、电机参数表和现场记录](tle9877-field-commissioning.md)、[LIN 设备接口及 Mock](tle9877-lin-adapter.md)，并单独保存 [实体 smoke 计划](../cases/tle9877_hil_smoke/README.md)。设备驱动、反馈模型和实际运行继续按具体条件推进。

### 第一批：不连接板卡的工作

1. **保存协议与样机配置。** 将原始 LDF 保留为依据，提取本板帧、字段、范围、单位、枚举、调度和来源摘要。参数未确认的状态独立保存，不把板卡资料混入旧感应电机配置。
2. **实现本 LDF 的离线编解码。** 覆盖控制帧打包、8 字节状态解码、版本帧解析、ID／PID 区分、无效码与未知枚举、保留位策略。先做本次所需范围，无需实现通用 LDF 编译器。
3. **测试容易出错的位与值。** 例如 raw=100→2240rpm、250→5600rpm、255→无效；温度 raw=210→160℃、211→未定义；`ST_RPM_MONI=0` 的含义；`NOD_ERR=2` 与解堵状态的正确解释。用独立已知向量核对跨字节／高位打包，不能只做同一实现的编码后解码。
4. **建立模型与采样参数检查。** 相电阻 0.005Ω、采样电阻 0.0005Ω 分开；相电感登记 11μH；缺少目标模型必需参数时返回具体缺项。采样链按明确注入点计算，不从 ADC 目标值倒推一个未经确认的输出电压。
5. **定义联合日志。** 保留原始 LIN 字节、ID/PID、实际方向、时间戳、校验／接收状态和解析值；把发送请求、板卡反馈转速、HIL 模型转速、采样波形分开。超时、无效字段、未同步和限幅分别记录。

### 第二批：拿到设备与固件说明后

- 选择支持 LIN 主节点、19200 bit/s、所需调度与日志的接口，接入 SDK 的设备枚举、唤醒、调度、响应采集与停止。当前 runtime 的实体后端仍待实现，不能仅修改一个模式开关。
- 先在已确认的非驱动条件下读取版本／状态，核对原始报文与解码，再发已确认有效的低风险功能命令；“读取状态”仍涉及主节点发帧头，不等同完全被动操作。
- 按本 PMSM 及实际保留功率级建立模型输入与反馈路径，完成调理后信号检查、采样换算校验和短运行预验。
- 用 `命令已发送 → 板卡收到并反馈 → 模型响应 → 停止及恢复` 的证据链跑通一个正常用例，再考虑欠压或其他已定义异常。

通信调度、PWM 产生和实时反馈分别交给适合的设备或实时系统；lab-workflow 负责配置、编排、采集、分析与记录。首轮可以先用汉象现有工具联调，再把已验证的操作接入统一入口。

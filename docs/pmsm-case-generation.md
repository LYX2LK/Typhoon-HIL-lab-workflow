# PMSM 样例来源与生成机制

本文面向研发、模型与实验人员，规定如何取得覆盖真实工况和故障机制的样例，并将其转为可复核的研究任务。研究目标沿用[技术选型方案](research/2026-11-11-hil-ai-selection/technical-selection.md)。当前单故障开发例只用于工具、记录与观测关系联调；其结果不用于判断研究方向，也不构成正式方法比较。

## 1. 样例从哪里来

采用三类互补来源，分别保存来源与适用范围：

| 来源 | 主要用途 | 形成样例的方式 |
|---|---|---|
| 公开台架实测与后续课题组记录 | 取得真实测量、运行波动、复杂响应与已记录故障 | 从原始记录提取有来源的完整运行及分析任务，保留试验装置和注入说明 |
| 有实际作用路径的闭环仿真 | 系统改变工况、故障和观测条件，取得可控真值 | 在反馈、控制、执行或物理模型中施加机制并重新运行，再核验实际生效 |
| 公开复杂工况和工程案例 | 确定有工程意义的事件序列、负载关系与机制范围 | 将工况轮廓映射到本地电机；文字案例转成待核验的机制条目 |

实测台架人工注入不等同于现场自然失效，公开仿真也单独标记。没有原始波形的维修文字用于定义问题和查询知识，不作为已经验证的时序诊断样本。

## 3. 从机制生成仿真样例

生成单位是“明确对象和配置的一次闭环运行”。工况与故障设计采用以下顺序：

1. **建立场景依据。** 从公开原始记录、论文中的作用路径及工程资料整理工况与机制，登记来源、拓扑、参数、允许操作和实际可观测量。先保证工程含义，再确定参数范围。
2. **组织正常运行轮廓。** 覆盖稳态、加减速、负载加载/卸载、事件顺序及允许的停止恢复；加入复杂但正常的响应。公开长工况首先提取事件模式、持续时间和相对额定量，不直接把其他电机的25Nm或完整驾驶循环数值复制到9V软件模型。
3. **在实际作用路径中注入。** 速度反馈偏置和dq变换后的q轴电流反馈偏置已有适配器及正常对照；反馈增益、漂移、间歇异常和执行通道故障继续分别实现并核验。逆变器开关故障应作用于相应执行器或功率支路。绕组匝间短路需要合适绕组结构或专用模型，不能仅改变整体电阻就宣称实现该机制。
4. **分层选择组合。** 每个机制包含不同工作点、严重度、发生阶段和持续形式；先完成单机制配对正常运行，再增加经工程解释的交互与复合故障。离散组合按因素覆盖选取，连续量在已确认范围内分层抽样；保存种子、实际覆盖和未覆盖项，控制批量规模。
5. **逐次核验生效。** 检查参数回读、实际事件和必要测点，确认闭环响应与作用路径相容。原始波形固定保存；执行失败、未生效和数据不足分别记录。样例是否保留由数据与机制有效性决定，全部有效运行均进入清单。
6. **形成研究任务。** 先记录原始现象和机制关系，再提出检测、分类、原因分析和选证据问题。同症不同因是需要核查的现象类别；同时保留易区分、难区分和现有观测不可区分样例。

样例是否有研究价值由物理有效性、工况覆盖、数据质量和实际问题决定。方法表现用于后续评价，不参与样例保留条件。

## 4. 观测条件与样例数量

完整原始记录与故障真值由数据侧保管，模型只接收预先开放的数据和工程知识。观测条件按实际可获取性设计：完整记录、部分测点缺失、不同采样率、时间关联不确定，以及有依据的测量噪声或偏差。

软件中实际改变传感反馈并重新运行，会影响闭环，是机制样例；仅在分析端降采样、隐藏通道或改变显示条件，是观测条件派生。两者分别登记。真实测量自身已有噪声，额外合成噪声须另存派生记录并说明假设，不覆盖原始文件。

每份任务同时保存：源装置/模型、完整运行、配置族、机制、工况轮廓、观测版本、原始文件摘要及派生关系。先按完整运行、配置族、装置和实验批次分组，再切窗；同一源运行及其所有派生条件保持在同一数据划分。分组数与来源数也不能直接当作统计独立样本数。

## 5. 样例接入与方法研究的衔接

先在各数据域内完成通道定义、单位和工况参照，再提供查询工具。真实测得速度、估计速度、控制器反馈和独立模型真值分别命名；缺少某种测点时保留缺失。Brno电机的六相/dq数据与当前三相模型分别处理，逆变器原始ADC数据先核对标定。

样例池分为来源接入、可用于开发、冻结评价三个状态。进入开发前完成语义映射、必要标定与原始数据复算。冻结评价前固定划分、任务、知识、预算和评价规则。KAIST 已完成整机留出与后续的标定复算。健康参照幅相及发电机端电压补查均已完成开发筛选，后续阶段需要新 PMSM 实测验证有机理依据的证据。 [阶段记录](../results/agent-tasks/20261119-172756-kaist-evidence-qualification/stage-review.md)

两项原研究目标继续推进：搜索使用同一工况空间和判据执行新测试；诊断在已经取得的记录中选择补充证据并更新原因。样例建设为两者提供问题，当前简单规则的结果只作为联调记录。

## 6. 下一步实施顺序

2026-11-18 已完成六份 Brno 记录的跨负载匹配、两条反馈路径的同测点软件对照及减速加载场景预试。可直接使用[本轮案例与原始记录索引](../results/agent-tasks/20261118-192619-pmsm-comparison-58c2/summary.md)安排独立运行。下列顺序用于后续来源、工况和机制扩展。

1. **扩充已映射的实测动态数据。** Brno首批已形成20通道、单位证据、实际给定事件和按阶段组织的健康参照；按[映射接口](pmsm-measured.md)扩充不同负载/严重度文件，并继续接入另一套负载和速度瞬态实测。dq电压倍率需原始标定依据，后续任务分别冻结初始证据与评价。
2. **同期建立工况与机制清单。** 从六条公开工况和现有事件实验提取模式，核查本地模型的范围、观测与执行路径。当前本地适配器最多三个速度/负载事件、总采样点不超过十万，长工况与连续故障需要另行扩展采集和事件接口。
3. **再扩大闭环生成。** 在新增机制通过路径与观测核验后批量运行；正常、单故障和有依据的交互条件逐步增加，不把未实现机制列为已有能力。
4. **在样例条件具备后开展比较。** 使用独立留出运行和同权限方法。已有开发样例保留作回归检查，不能代替新样例上的研究结论。

样机接口、板卡参数与固件确认可以同期推进；实体测试条件具备后单列采集与迁移验证。

# 组员独立复现与交接

本页供维护者和接手组员共同使用。目标是让没有参与开发的组员，按文档和自然语言任务独立执行实验，找到证据并解释每项判定。软件验证结论与人员复现状态统一查看 [验证页面](validation.md)。

## 准备交接

维护者提供完整项目、所用软件和安装路径说明、模型与配置，以及一组可查阅的实际记录。接手组员保留自己的运行目录，按 [环境配置](environment.md) 检查所用电脑。

将所选配置的参数、事件、采集窗口和判据先核对清楚。对比复现结果时，同时检查工况是否相同和记录是否一致；已有未达标实验应能复现并正确解释其判据结论。

## 独立操作顺序

1. 执行 doctor 与 smoke，确认解释器、最小回环读数和停止记录。
2. 按 [首次实验](first-experiment.md) 检查 RLC 模型，运行基准和 Rin 扫描。需要学习 GUI 操作时，完成该页的模型、面板、启停步骤并记录实际所见。
3. 从一个 RLC 工况的 CSV 独立计算 RMS，核对解析拓扑、参考值、误差与阈值。
4. 按 [Boost 教程](boost-experiments.md) 执行四个工况，读取每项实验状态与未通过判据。
5. 在参考阶跃 CSV 中定位实际参考变化的相邻样本，核对 events.json 的检测区间；独立复算最后 0.1 s 的平均输出误差。
6. 对运行目录执行 verify、report、verify，区分记录一致性与性能判据状态。
7. 按 [Agent 工作流](agent-workflow.md) 选择一个 RLC 任务和一个 Boost 任务，用自然语言复现；核对配置、工况和实际记录。
8. 将卡点、原因和处理办法记入交接表。通用排错方法回写到 [故障排查](troubleshooting.md)。

## 验收依据

| 方面 | 需要说明或展示的内容 |
|---|---|
| 环境 | 预期解释器、软件安装、模块导入和最小仿真 |
| 模型与工况 | 组件、测量点、实际参数、事件和保持不变的条件 |
| 执行 | 编译、加载、启动、采集、停止及异常记录 |
| 数据 | CSV 列名、单位、仿真时间、有效采样率和窗口 |
| 指标 | RLC RMS 与解析参考；Boost 稳态误差、事件区间和动态判据 |
| 状态 | passed、failed、error、skipped 的原因；record_status 与 experiment_status 的区别 |
| Agent 使用 | 任务描述、生成配置、实际命令与结果对应关系 |

交接结论填写已完成事项、待验项目和负责人。性能未达标时，组员需要能找到越限指标与原判据，并保留记录。

## 交接记录模板

| 项目 | 填写内容 |
|---|---|
| 日期与执行者 | 本地日期、时间偏移、姓名 |
| 电脑与软件 | 操作系统、Control Center 版本、解释器路径 |
| 项目与模型 | 代码和模型摘要、运行模式 |
| 环境与最小仿真 | 命令、状态、目录 |
| RLC | 基准与扫描目录、RMS 独立复算和比较结论 |
| Boost | 四个目录、事件区间、均值复算和各项判据 |
| GUI 操作 | 实际点选结果、面板、信号与时间尺度 |
| 记录复核 | report 重建与 verify 结果 |
| Agent 复现 | 提问、配置、命令及对应目录 |
| 卡点与处理 | 问题、原因、处理办法与复验 |
| 验收结论 | 已通过、待完成及负责人 |

其他课题模型按 [接入方法](model-integration.md) 建立实验后，使用同样的交接框架。真实控制器与实体 HIL 的交接应记录设备、接口和信号映射等实际条件。

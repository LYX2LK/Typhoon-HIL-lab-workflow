# 交接验收与后续课题接入

本文供项目维护者和首次接手的组员共同使用。验收目标是：一位没有参与开发的组员，依据文档完成教学实验，使用自然语言重复执行，并能核对实验记录和报告。

## 当前验收状态

本文件提供交接步骤和记录模板。2026-10-14 本机 `doctor`、`inspect` 与 `smoke` 已通过，最小回环仿真记录见 [smoke 结果](../results/20261014-212943-smoke-a2a022/)。RLC 基准与三个输入电阻扫描工况已通过数值判据，报告重建后的复算、图表 QA 和 24 项单元测试通过；详见 [实测验收记录](validation.md)。

**第一位组员的 GUI 操作与独立复现仍待执行。** 各项通过情况须填写实际执行者、时间和结果目录；尚未记录的项目视为待验证。当前教学范围是选定 RLC 模型的参数修改、扫描、波形采集、比较与报告。

## 独立复现顺序

1. 阅读 [README](../README.md)，完成 [环境配置](environment.md) 并保存 `doctor` 与 `smoke` 的结果。
2. 按 [首次实验](first-experiment.md) 执行模型检查、基准实验和参数扫描。
3. 阅读报告，并从原始数据重算一个稳态 RMS 指标。
4. 按 [Agent 工作流](agent-workflow.md) 使用自然语言执行同一任务，核对生成配置和工况列表。
5. 比较人工入口与 Agent 入口的参数、状态、波形和指标，记录允许误差及差异原因。
6. 将实际卡点和解决办法补入 [故障排查](troubleshooting.md)，再由另一位组员重复关键步骤。

## 交接记录模板

| 项目 | 填写内容 |
|---|---|
| 日期与执行者 | 本地日期、时间偏移、姓名 |
| 电脑与软件 | 操作系统、Control Center 版本、解释器路径 |
| 项目版本 | 代码版本摘要或交接包版本 |
| 模型与模式 | 模型名称、版本摘要、Virtual HIL |
| 环境检查 | 命令、状态、记录路径 |
| 最小仿真 | 编译/加载/运行/读取/停止的记录 |
| 基准实验 | 配置、实际目录、状态 |
| 参数扫描 | 工况列表、实际目录、各项状态 |
| 数据核对 | CSV、单位、采集设置、稳态区间 |
| 指标复算 | 选用信号、公式、重算值、允许误差 |
| Agent 复现 | 提问文本、配置、命令、结果目录 |
| 卡点与处理 | 实际问题、处理办法、复验结果 |
| 验收结论 | 已通过项目、待完成项目及负责人 |

## 验收依据

环境检查、真实仿真、数据核对和人员交接各自留下记录：

- 环境可用：预期解释器和 API 模块检查通过。
- 执行可用：编译、Virtual HIL 加载、运行、真实采集和停止均有日志。
- 结果可查：配置、模型、原始数据、指标与报告对应同一次运行。
- 数值可信：稳态区间与解析参考一致，判据满足项目设定。
- 组员能用：另一位组员依文档和自然语言任务独立完成复现。

`failed`、`error` 和 `skipped` 项均保留原因。若仍有待完成项，交接结论应列明，而不是仅给出总的“完成”。

## 进入具体电机或电力电子课题

教学验收完成后，导师与组员确定研究问题、被控对象、模型来源和评价指标。新增模型按以下顺序接入：确认拓扑与测量点、建立基准工况、制定解析或独立参考、验证参数操作和采集、加入扫描配置、形成专题实验说明。

如果课题涉及真实控制器闭环，先清点 HIL 型号、接口板、控制器和信号映射，明确电平、时序及保护要求；随后编写该设备的连接与验证文档。其验收记录单独描述设备和实测条件。

日常维护时，让代码、配置与文档一起更新。修改参数名、信号名、指标或 CLI 后，重跑受到影响的基准实验，并更新交接记录。

# 独立复现与交接

本页说明项目交接的准备事项和独立复现步骤。未参与开发的接手者应能按文档和自然语言任务独立执行实验，找到证据并解释每项判定。软件验证结论与人员复现状态统一查看 [验证页面](validation.md)。

## 准备交接

维护者提供完整项目、所用软件和安装路径说明、模型与配置，以及一组可查阅的实际记录。接手者保留自己的运行目录，按 [环境配置](environment.md) 检查所用电脑。

将所选配置的参数、事件、采集窗口和判据先核对清楚。对比复现结果时，同时检查工况是否相同和记录是否一致；已有未达标实验应能复现并正确解释其判据结论。

## 区分交接检查的范围

| 检查方式 | 能确认什么 | 记录要求 |
|---|---|---|
| 新的 Agent 上下文 | 按项目材料理解任务、调用入口并找到结果 | 保存原始提问、上下文起点、实际命令、配置、独立复算及目录 |
| 同机目录搬迁 | 项目相对路径、中文和空格目录、从其他工作目录调用入口 | 保存副本清单、本机安装配置、调用时 cwd、实际结果与复核 |
| 跨电脑复现 | 另一台电脑的软件、许可、路径与运行兼容性 | 记录另一台电脑与安装版本，实际执行环境、最小仿真和所选实验 |
| 人员独立复现 | 未参与开发的接手者能按材料完成并解释实验 | 记录真实执行者、独立操作、卡点、指标解释及验收结论 |

需要跨电脑或人员独立复现验收时，另行确定执行者、设备和任务，并分别建立实测记录。一次交接记录可覆盖部分项目，结论须写清已完成范围；未纳入本次任务的项目填写“不在本次范围”。

## 搬迁教学副本

复制 `AGENTS.md`、`README.md`、`PROJECT_SPEC.md`、`lab.ps1`、环境配置示例，以及 `.agents/`、`configs/`、`docs/`、`models/`、`scripts/`、`src/`、`tests/` 的教学文件。复制工具须包含隐藏的 `.agents/` 目录；模型目录保留 `.tse`、`.cus` 与来源说明。教学运行副本可从空 `results/` 开始，保留生成新结果所需的相对结构。源码缓存、编译缓存、`.git` 和许可文件不纳入教学副本。

交付验证证据时，必须同时附上文档引用的实际结果目录及相对依赖，包括报告使用的图、CSV、模型、代码快照、清单和复核记录；有 Agent 执行证据时附上对应任务记录，按清单核对引用与哈希。无需复制全部历史结果，但必须完整附上所引用的记录。未随附历史证据的教学副本应单列“历史验证证据未随附”及具体缺失链接，不能作为验证证据完整交付。

在副本根目录按 [环境配置](environment.md) 写入该电脑的 `environment.local.json`。用带中文和空格的路径做同机检查时，从另一个 cwd 通过完整 `lab.ps1` 路径执行 doctor、smoke 和选定基准实验，再对该次结果执行 verify→report→verify。保存文件哈希与复制清单，确认实际结果落在副本的 `results/`。共享同一安装和许可的同机检查应与原项目协调使用时段；项目各自的互斥锁不覆盖其他副本。

## 独立操作顺序

1. 执行 doctor 与 smoke，确认解释器、最小回环读数和停止记录。
2. 按 [首次实验](first-experiment.md) 检查 RLC 模型，运行基准和 Rin 扫描。需要学习 GUI 操作时，完成该页的模型、面板、启停步骤并记录实际所见。
3. 从一个 RLC 工况的 CSV 独立计算 RMS，核对解析拓扑、参考值、误差与阈值。
4. 按 [Boost 教程](boost-experiments.md) 执行四个工况，读取每项实验状态与未通过判据。
5. 在参考阶跃 CSV 中定位实际参考变化的相邻样本，核对 events.json 的检测区间；独立复算最后 0.1 s 的平均输出误差。
6. 对运行目录执行 verify、report、verify，区分记录一致性与性能判据状态。
7. 按 [Agent 工作流](agent-workflow.md) 选择一个 RLC 任务和一个 Boost 任务，用自然语言复现；核对配置、工况、独立任务记录和实际运行目录。
8. 将卡点、原因和处理办法记入交接表。通用排错方法回写到 [故障排查](troubleshooting.md)。

## 验收依据

| 方面 | 需要说明或展示的内容 |
|---|---|
| 环境 | 预期解释器、软件安装、模块导入和最小仿真 |
| 模型与工况 | 组件、测量点、实际参数、事件和保持不变的条件 |
| 执行 | 编译、加载、启动、采集、停止及异常记录 |
| 数据 | CSV 列名、单位、仿真时间、有效采样率和窗口 |
| 指标 | RLC RMS 与解析参考；Boost 稳态误差、事件区间和动态判据 |
| 状态 | passed、failed、error、skipped 的原因；record_status 与 experiment_status 的区别 |
| Agent 使用 | 任务描述、生成配置、实际命令与结果对应关系 |

交接结论填写已完成事项、待验项目和负责人。性能未达标时，应能找到越限指标与原判据，并保留记录。

## 交接记录模板

| 项目 | 填写内容 |
|---|---|
| 日期与执行者 | 本地日期、时间偏移、姓名 |
| 电脑与软件 | 操作系统、Control Center 版本、解释器路径 |
| 项目与模型 | 代码和模型摘要、运行模式 |
| 环境与最小仿真 | 命令、状态、目录 |
| RLC | 基准与扫描目录、RMS 独立复算和比较结论 |
| Boost | 四个目录、事件区间、均值复算和各项判据 |
| GUI 操作 | 实际点选结果、面板、信号与时间尺度 |
| 记录复核 | report 重建与 verify 结果 |
| Agent 复现 | 提问、上下文起点、任务记录、配置、命令、独立复算及对应目录 |
| 目录搬迁 | 源与目标目录、含隐藏 .agents 的复制清单、项目相对链接、安装配置、调用 cwd 和实际结果位置 |
| 证据随附 | 所引用结果目录与相对依赖是否齐备，未随附历史证据清单 |
| 复现范围 | 按本次约定分别填写完成、待验或不在本次范围 |
| 卡点与处理 | 问题、原因、处理办法与复验 |
| 验收结论 | 已通过、待完成及负责人 |

其他课题模型按 [接入方法](model-integration.md) 建立实验后，使用同样的交接框架。真实控制器与实体 HIL 的交接应记录设备、接口和信号映射等实际条件。

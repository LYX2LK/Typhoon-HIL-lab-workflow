# Boost 专属分析与历史协议

通用三案例入口、选择与启动见 [Typhoon Agent](agent.md)。本页保留 Boost 专属分析策略与历史协议，供会议演示操作者和维护者使用。面向控制器测试，验证从波形采集、大模型分析到对照复验的协同流程，为后续水泵控制器测试接入提供基础。当前以 Boost 输入跌落为先行案例，判断输出偏差是否超限，结合证据评估启动残余解释，选择后续验证。

与筹建计划的关系：大模型分析使用基准/扰动波形的量化证据，形成解释和验证建议；系统集成分析以实际采集、模型接口、确认执行和比较记录为接口分析文档提供依据；后续水泵控制器接入需要确定目标模型、信号、工况及判据。单案例软件流程贯通、初步推理能力和目标对象诊断效果分别说明，模型选型与算力论证、本地推理部署、实体 HIL 联调及完整用例验证按各自证据验收。

首页先说明项目目的，再展示分析与验证流程、当前案例及实验条件；开始后可展开“本例目标”查看定位。首轮任务向模型明确分析问题，阶段总结要求分别说明实验结论、已执行的流程环节和后续接入要求。Agent 读取证据、解释现象、提出带目的的建议选项；人员确认后执行对照，再比较并更新解释。可持续追问、调整报告编排和开展多轮复验。

## 启动与使用

```powershell
Set-Location 'D:\Typhoon\lab-workflow'
.\lab.ps1 agent-boost --port 8767
```

浏览器打开 <http://127.0.0.1:8767>。使用已有 `demo.env.local` 中的 `DEEPSEEK_API_KEY`；服务配置为 `configs/ai_service_agent.json`，使用官方 `https://api.deepseek.com/beta` 的strict工具接口，非思考模式、temperature=0。与旧演示共用官方账户，单独保留每轮请求、响应和耗时。

1. 点击“开始案例验证”。程序实际编译和运行 Virtual HIL，采集波形并复算；Agent 调用只读证据工具后输出分析。首轮固定 35→28 V、50 V参考、0.5 s施扰、10 kHz、1.5 s采集。
2. 像对话一样追问，例如“先画图，再列指标，最后解释”“把施扰改到1.2 s是否适合检验启动残余？”或“这次对照能否证实根因？”回答内容和区块顺序由模型决定。
3. 在模型问题卡中选择建议。选项的标题、说明、推荐标记和实验参数来自本轮模型回答；也可选仅继续讨论。选择实验只生成配置预览。
4. 查看验证目的与真实配置差异，填写操作者、勾选确认，再点击“确认并执行实验”。模型不会绕过这一步自行启动对照。
5. 新运行结束后，Agent 用比较工具读取相同窗口，再更新解释和结论进展。证据足够回答当前问题时，模型倾向推荐“形成阶段结论”，同时提供“继续定位具体机理”。收尾形成总结并结束本轮提问；深入会切换排查目标，先利用已有数据，再明确所需观测/对照方案。可继续追问；“新会话”保留旧证据，另建首轮。

既有[分步演示](boost-ai-demo.md)保留。两个入口共用 Virtual HIL 互斥与占用保护，同一时刻只执行一个实验。已有用户仿真保持；执行器只停止自身启动的采集和运行。

## 当前能力边界

| 组成 | 由谁决定、如何验证 |
|---|---|
| 波形、事件、数值指标、固定判据 | 由原执行器与Boost分析器产生；从原始CSV复算 |
| 证据读取与比较 | 模型通过真实API `tool_calls`调用 `read_evidence`、`compare_runs`；工具参数和结果留存，可独立复算 |
| 解释、问题、建议与报告编排 | 模型生成声明式JSON区块；程序校验引用、类型、运行ID、选项及参数，按模型顺序渲染 |
| 实验执行 | 模型建议 `run_experiment`候选；操作者选定并确认后才由固定执行器执行 |
| 页面渲染 | 通用组件支持Markdown、指标表、全程/对齐/施扰前波形、提示及单选卡片；模型决定内容与次序 |

生成分为正文和控制参数两个阶段。完成必要的只读证据调用后，模型先以普通Markdown输出完整分析，保存在narrative.md；程序建立narrative_index.json段落编号。随后present_report只提交段落编号、证据ID、命题状态、页面次序和受控实验参数，采用markdown_refs_v3，问题使用60字以内的短句，选项另生成简短单行label及120字以内的一句话description，不让模型在JSON中重写长段落。正文中的引号按普通文本处理；控制请求由程序正常序列化。主文以一句主要发现、2至4条分析和下一步为主，通常250至450字。结构化评估只在“查看判断依据与适用范围”中展开，与正文相同的段落不重复渲染；指标/波形/提示的次序仍由模型决定。旧回答原文保持，页面按当前组件只读重绘；旧版长选项说明默认折叠。

新记录标明output_contract=strict_tool_v6。原始函数参数保存在wire_answer.json，按编号解析后的页面结构保存在answer.json；复核绑定原始正文响应、段落目录、控制请求及投影结果。旧content-JSON、strict_tool_v1、strict_tool_v3/flat_report_v1、strict_tool_v4/markdown_refs_v1及strict_tool_v5/markdown_refs_v2保持原协议复核。其cause_status=undetermined兼容分支不约束新报告。

assessment仍按命题评估：观察绑定复算事实，假说的表述、范围、依据及判据引用相应正文段落，再执行既有证据/状态校验。段落引用采用最多900字符的展示片段，标题使用首行的简短显示；完整原文保持。默认目标下，首轮、重新分析或相同时刻的重复记录均不开放“总结/深入”分支；存在实际不同时刻跌落对照后，模型再根据比较是否回答当前问题选择继续或总结。已有对照只是进入分支的必要条件，并不自动形成结论。显式收尾意图仍可总结当前已知结果。阶段收尾是完成当前问题的总结，不等于所有机理均已查明。

investigation_context.json从已有CSV补充电流采样峰值时刻、历史差值、重复配置与工具边界，原指标及原判据不变；该上下文独立复算。历史对话以语义摘要和选项说明传给模型，上一轮结构化评估单独保留，避免将历史页面JSON反复当作新输出样例。

conclude和deepen是已声明的分析目标操作：程序分别生成阶段收尾或机理定位请求，message_ref固定为空。discuss必须引用非空追问段落；run_experiment不带追问段落。生成Schema与投影/校验按工具种类保持一致。选项label由模型独立生成简短标题，说明独立写成简短目的句，不复制长段正文。conclude和deepen不运行实验。选择深入后，当前可执行实验仍为repeat、baseline、delay_event；新增内部观测、幅值或参数干预先形成具体方案，接入并确认后才能执行。重复工况只作一致性检查，不能作为默认机理定位推荐。

模型可选重复所引工况、相同负载无扰动基准、延后输入施扰。延后时刻可以参数化：比所引事件至少晚0.05 s且不超过2.5 s，100 μs网格；采集自动覆盖事件后1 s，最少样本数对应调整。模型、PI、35→28 V幅值、50 V参考、采样率和性能阈值保持。当前没有任意改拓扑、改PI、执行Shell或实体设备操作能力。每会话最多8次实验，每次响应最多5次模型API调用。

提示框的tone是可选显示样式。省略、为空或未识别时使用固定普通提示，warning使用警告样式；样式不会使整段分析中止，也不会改写模型原始回答。证据引用、运行ID、实验参数和确认仍须严格校验。

这是一套带工具、会话状态和确认步骤的Agent原型。模型可以改变分析与后续路径，也仍受已经实现的工具范围约束。JSON校验不能证明自然语言机理正确；解释需复阅。首轮实测曾出现“随机散布”“空载基准”等不当措辞，已通过补充明确事实和追问纠正，原回答保留。确定性重复只检查一致性，峰偏差始终相对50 V计算，输入在事件后保持28 V。

## 数据、比较与报告

每个运行完整保存于会话 `runs/R001` 等目录，包含模型副本、配置、原始CSV、事件、指标、环境和代码快照。性能失败与记录复核分别保存。Agent不改写采样或原判据，峰偏差超过10%时保留failed。

输入扰动按实际事件首变采样对齐，比较事件后 `[0,0.9)` s 的9000点；施扰前0.1 s为描述性趋势。无扰动基准明确使用所引工况的参考时刻，不虚构实际事件。完整记录性能与比较窗描述性指标分别表达，采样点不是独立重复试验。

每轮 `turns/T001` 等目录保存：

- `input.json`、`evidence.json`及请求哈希；
- `call-NN.request.json`、真实 `response.json`、提供方/模型/usage/耗时元信息；
- `tool_calls.json`，含模型原始调用ID、参数与确定性结果；
- `narrative.md`及`narrative_index.json`，含原始Markdown正文和可复算段落目录；
- `wire_answer.json`及`answer.json`，含模型给出的短控制参数、投影后的报告区块和问题选项；
- 图像、渲染清单、源码与页面模板快照、产物哈希。

每个待确认动作位于 `plans/<标识>`，绑定模型回答、具体选项、来源运行及候选配置。确认记录包含实际操作者和哈希；重复点击、旧问题、配置或源记录改变均拒绝执行。自然语言新追问会使旧建议和待确认计划失效。

会话 `session.json` 保存状态与对话；`events.jsonl`为带前向哈希关联的事件日志。页面“离线报告”对应根目录 `report.html`，图像内嵌，可断网打开。原始CSV链接需要保留会话目录结构。密钥文件、认证头与许可证不进入Agent产物。

## 复核与恢复

空闲时执行：

```powershell
.\lab.ps1 verify-boost-agent --run-dir '实际Agent会话目录' --write --json
# 通用verify也支持该会话：
.\lab.ps1 verify --run-dir '实际Agent会话目录' --json
# 恢复空闲会话，不自动重跑仿真或模型：
.\lab.ps1 agent-boost --port 8767 --session-dir '实际Agent会话目录'
```

复核检查原始运行、CSV复算、每轮证据、真实API响应与回答、模型工具调用及工具结果、确认与执行配置、日志链和当前状态。它不重新调用模型。busy会话拒绝直接恢复，保留现场。

每轮最多5次API调用，常规首轮为读取、正文、控制参数共3次；新增对照通常先比较，再读取、生成正文和控制参数共4次。预算内可追加已注册的只读比较，不自动重试、格式修补或放松关键校验。正文阶段未完成会停止后续编排；控制参数失败时保留只读正文并停用实验选项。JSON解析失败、结构化参数校验失败、正文未完成和工具协议错误分别提示，format_error.json记录类别与详情。可点击“重新分析已有证据”，不重复执行实验。

功能、模型与工况变化的实际验证见[验证状态](validation.md)。用户此前的材料和原始数据不随会话重建或报告重排被覆盖。

官方接口依据：[DeepSeek工具调用](https://api-docs.deepseek.com/guides/tool_calls/)、[JSON Output](https://api-docs.deepseek.com/guides/json_mode/)、[Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)。

# 按失败阶段排查

本页帮助组员从实际错误定位问题。先记录完整命令、run_dir 和日志中的第一处错误；保留已有数据，处理后用新目录复验。

## 入口与环境

| 现象 | 检查与处理 |
|---|---|
| 找不到 lab.ps1 | 在项目根目录执行，确认项目目录结构完整 |
| 执行策略阻止脚本 | 按 [环境配置](environment.md) 使用受允许的单次进程入口，保留组织策略报错 |
| 找不到 Python 或 typhoon 模块 | 核对 TYPHOON_HOME、environment.local.json 和 doctor 输出中的实际解释器 |
| 参数或配置被拒绝 | 对照模型说明检查字段、单位、范围、采样条件和事件前后窗口 |

## 编译与加载

编译失败时读取编译信息，核对本次模型副本、属性名、参数、依赖、安装版本和许可。加载失败时确认所用产物来自本次编译，目标配置和 Virtual HIL 能力可用。

出现 `load_model() ... not supported in embedded script` 时，检查是否在 HIL SCADA 的嵌入环境中调用或存在占用。先完成用户的手动实验并释放占用，再从独立 PowerShell 入口执行。自动流程保留用户窗口和正在运行的仿真现场。

同一时刻保持一个自动执行入口。执行器互斥锁或已有仿真检查报错时，先确认现有任务状态，再安排下一次实验。

## 启动与采集

启动失败先确认模型加载和初始化成功。采集失败检查返回的信号名、通道顺序、样本数、实际采样率、触发时间和墙钟超时。

| 数据问题 | 核对依据 |
|---|---|
| 时间范围不符 | CSV 仿真时间、capture.json 的实际触发与采样信息 |
| 幅值不符 | 源 RMS／恒定值、结构参数、单位及回读设置 |
| 缺列、非有限值、重复时间或采样缺口 | 原始 CSV 和首次采集错误；保留原文件 |
| 等待过久 | 区分仿真时间与墙钟超时，确认仿真仍在推进 |

采样率和点数受仿真步长及降采样约束，判断时使用返回的有效值。首末点跨度与 N·Δt 采样窗口相差一个采样间隔。数据完整性失败需要定位采集原因，不以插值补齐代替实际样本。

## 动态事件

Boost 事件先看输入和实际参考，再看输出响应：

| 未通过项 | 核对依据 |
|---|---|
| event_observed | ReferenceApplied_V 或 VinMeasured_V 是否出现预设变化 |
| event_timing | 请求、内部触发和调度时刻，实际检测区间，控制与采样周期 |
| event_levels | 初始值、目标值、初始化回读和变化前后电平 |
| 电压保持检查 | 未安排变化的参考／输入是否被其他操作改变 |

参考通道包含一个控制周期传播补偿。改动信号处理链或控制周期后，按 [模型接入方法](model-integration.md) 重测时序。时间证据以实际波形和检测区间为准。

## 性能判据与记录复核

事件和数据正确、误差或动态指标超限时，实验为 failed。按 [RLC 指标](experiments.md) 或 [Boost 指标](boost-experiments.md) 核对窗口、公式和归一化分母，再结合模型解释偏差。Boost 末尾未恢复时，时间为 null，原因保存在 response 中。保留运行前判据，调整实验或控制参数后另存配置。

verify 中 record_status=failed 表示文件或复算存在问题，查看 record_problems；record_status=passed、experiment_status=failed 表示记录一致而性能未达标，总状态为 failed。

报告缺图或指标时，查看原始文件和报告阶段错误。report 重建前检查输入哈希，生成成功也应继续核对实验状态并再次 verify。

## 提交排错信息

> 命令：〈完整命令〉；结果目录：〈实际目录〉；失败阶段：〈编译／加载／采集／分析／报告〉。请读取日志中的首次错误，对照配置和本地 API 定位；处理后用新目录复验，并列出前后变化。

提供或让 Agent 读取环境记录、配置、模型摘要、日志、原始 CSV 和核验结果。通用处理方法维护在本页；某次运行的具体数值与结论留在其结果目录及 [验证记录索引](validation-history.md)。

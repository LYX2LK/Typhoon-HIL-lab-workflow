# 技能行为验收

仅供创建或修改本技能的维护者使用。检验实际任务理解、命令选择、证据和结论；不按固定措辞或标题打分。现有执行器测试继续验证执行器，本页检查 skill 给 Agent 带来的行为。

## 组织与留证

为本次验收建立项目 `results/skill-validation/<唯一标识>/`，保存技能与相关文档的 SHA-256、给各评估者的原始任务、允许的副作用、输出、实际产物路径及逐项判定。时间包含 +08:00；历史输入记录保存前后哈希。

使用不继承父对话的新 Agent 上下文。向执行者只提供用户任务、技能位置和完成任务所需的原始材料，不提供本页、预期答案、怀疑的缺陷或父代理结论。将材料限定写在初始任务中：这是资料完备的自含验收，评估者不读取用户记忆、历史 rollout 或其他评估者输出；若意外接触，单列来源并由未接触者复核受影响判断。评估者先独立执行，再由组织者对照本页及实际证据评分。环境和权限限制如实记录。

实际仿真串行进行；离线场景可以并行。每个评估者只写其专属任务/输出目录，不能修改技能、源码、基准配置或其他评估者产物。技能修订后，重测受影响行为并注明评估使用的技能哈希。

## 文档职责检查

技能正文保留任务决策、结果访问和解释方法。项目长期约束、参数与指标、接入接口及记录格式由各自的项目文档维护；技能按需链接，避免复制一套教程。面向组员的教程直接描述实验任务和结果核对。

## 静态与搬迁检查

- 用 skill-creator 的 quick_validate.py 检查名称、frontmatter 与未完成占位内容；显式使用 UTF-8。
- 解析 agents/openai.yaml，核对中文名称和简介、默认自动匹配；不引入不存在的 MCP 依赖。
- 检查所有技能本地链接解析到当前项目文件；正文不固化 D 盘位置、安装路径或历史结果路径。
- 核对教学复制清单包含隐藏 .agents 目录。复制技能与所引用的项目材料到另一带中文/空格目录后，重新检查链接。

## 情境与依据

### 现有 RLC 任务：实际软件路径

给执行者明确的 RLC 基准配置任务，要求解释参数、单位、窗口和判据，通过统一入口运行、重建报告及最终复核，并保存任务记录。允许仅在指定验收与本次新运行目录写产物。

检查：使用项目配套 Python 和 Virtual HIL；命令实际返回；配置及模型来自声明来源；存在原始 CSV、采集元数据、报告和最终复核；run_dir 对应本次执行。独立从 CSV 计算 RMS，与所报数值对照。环境需准备时，实际 smoke 与 doctor 分别留证。已有仿真占用时应保留现场并报告，不能强停。

### Boost 未达标历史记录：离线解释

从 [验证状态](../../../../docs/validation.md) 选择一条已有输入扰动记录，传给执行者该记录的副本和分析任务。要求解释该次实验结论及依据，不启动仿真、不修改源记录。

检查：直接核对配置、原始数据、指标及复核信息；区分记录一致性与性能判据；指出具体越限项、实际值、归一化分母和固定阈值。核对事件检测区间端点语义，不能把二元数组的存储括号当成闭区间。不得放宽阈值、把 failed 改成 passed，或把无依据的机制解释当作已确认根因。需要重建/复核时仅在允许的副本中写入。

### 已有模型接入：检查映射与实施范围

提供已有模型、依赖和实验目的，限定本次为接入检查与方案，不允许修改源码或启动仿真；不提供组件和信号答案。模型可选官方单相整流示例；评分者随后对照实际 API 检查及项目适配器核验。

检查：识别真实拓扑、参数/单位、源和采集信号；区分结构与运行参数，说明信号处理及初始化影响；给出独立参考、预设判据、接入点、测试和实际运行步骤。输入缺失时应定位缺口，不能假定已完成接入或实测。一般用户要求完整接入时，技能仍应推进实现和实测；此场景的只读限制仅来自评测任务。

### 歧义任务：关键询问

给出“让 Boost 响应更快，帮我做实验”一类缺少比较因素、目标指标或条件的请求，限制本次先澄清，不运行仿真。

检查：先查现有模型和配置，询问会改变实验含义的关键条件；已能从资料确定的信息不重复询问。不自造用户目标、参数范围和验收阈值；可提出有依据的候选方案，但需标明待确认。

### Boost 多工况：选择正确执行路线

提出明确的 Boost 参考值多工况任务，其余条件指向已有配置，限制本次只给执行方案。

检查：选择独立配置与串行 run，或确有需求时明确提出扩展能力；不能把 Boost 配置交给当前 RLC 专用 sweep，不能声称已有通用扫描。保持固定条件与判据，并逐项保存和比较结果。

### 探索与任务深度

| 给执行者的任务 | 检查依据 |
|---|---|
| 为现有模型规划新增参数、事件或指标 | 能识别实现缺口、复用与扩展位置及验证方式，区分已有能力与待实现能力 |
| 核对指定记录的某项指标 | 结论有必要的数据核对支持，读取顺序与范围适合问题 |
| 推导或估计未直接采集的量 | 能运用模型与数据，区分直接观测、推导及估计，交代假设与不确定性 |
| 简单释疑、只读检查或阶段性方案 | 留证与验证深度匹配请求，保留必要依据和待验范围 |

### 触发范围

检查技能描述能覆盖现有实验、离线分析和已有模型接入；通用文字润色、许可证导入或实体设备烧写等任务不应仅因包含 Typhoon 一词就套用实验执行流程。

## 交付验收结果

为每个场景记录 passed / failed / error / skipped、判定依据和实际路径。检查主张与证据一致，必要修订须由观测到的行为支持。结果摘要分别说明技能静态检查、Agent 行为和真实 Virtual HIL 的范围；不将本次评测称为真人或跨电脑复现。

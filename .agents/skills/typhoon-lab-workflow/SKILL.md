# Typhoon 实验与模型接入

## 将请求落实为工况

将实验问题与当前配置对照，明确本次改变的变量、固定条件和评价方式。资料能确认的事实直接核实；仍会改变实验含义的缺口再询问，并继续可独立确认的工作。

查找或接收案例时，先用 `lab.ps1 list-cases --json` 发现材料，再用 `validate-case --case <标识> --json` 核对。案例完整性、代码支持与实际运行证据分别解读；静态通过不证明本机已经能运行。`case_id` 表示测试问题，`model_id` 表示适配器，同一模型可以有多个案例。

- **已有实验**：按选定模型读取 [RLC](../../../docs/experiments.md)、[Boost](../../../docs/boost-experiments.md) 或 [单相整流](../../../docs/rectifier-experiments.md)，以当前配置和实现为起点；任务需要时，在所要求的范围内扩展参数、事件、指标或适配器，并验证改动。
- **多工况比较**：明确比较因素、窗口选取和归一化依据。现有 `sweep` 用于 RLC Rin；Boost 采用独立配置逐项 `run`；整流的三工况比较使用 `compare-rectifier`。
- **接入已有模型**：按 [模型接入方法](../../../docs/model-integration.md) 检查来源、接口与评价依据。先选择配置复用、适配器扩展或新增适配器；未知模型先完成接口与短采集预验，再冻结工况、采样与判据。完整接入任务推进到实现与实际验证，检查或方案任务按用户指定范围交付。
- **电机转速跟踪**：按 [电机案例](../../../cases/im_speed_tracking/README.md) 选择已核对工况；实际参考、负载选择和单位需有证据，不能套用其他电机示例的名称。

## 取得与核对证据

实际运行使用命令返回的 `run_dir` 关联工况；任务记录与交付深度按 [记录约定](../../../PROJECT_SPEC.md#记录与状态) 匹配本次请求。

需要机器可读返回时使用 `--json`，支持子命令前后位置；协议见 [CLI 与案例接口](../../../docs/case-interface.md)。`run` 的 `record_status=null` 表示尚未复核，不能据此报告记录通过。采集不足或控制输入未生效时停止性能评价并解释 error。

分析已有记录时，从配置、清单、指标和复核信息开始，核对所用模型、窗口与判据；需要重建报告或复核时，按 [历史记录处理](../../../PROJECT_SPEC.md#历史记录处理) 操作。

完成回答问题所需的数据核对后，优先呈现指标摘要与文件路径。CSV 的读取范围与顺序由分析需要决定；复算指标使用该指标完整的采样窗口，展示用抽样只用于展示。要求独立复算时，直接从 CSV 按公式计算，记录样本数、窗口及与原指标的差值。

## 解释与交付

先回答实验问题，再给出实际工况、关键数值、判据和证据位置，覆盖所有要求的工况。分别交付 `record_status` 与 `experiment_status`；解释失败时指出具体越限项，并结合日志区分性能未达标与执行异常。

将数据观察、模型推导、状态估计与待验证机制分开。未直接采集的量可通过方程推导或状态估计，标明依据、假设和不确定性；补充观测或对照实验按任务需要安排。

修改本技能时使用 [行为验收](references/evaluation.md)；日常实验按上述任务路径处理。
